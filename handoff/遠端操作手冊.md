# 遠端操作手冊

> 在學校的遠端 GPU 機器上照這份做。每一步都有「怎麼確認成功」。

## 步驟 0:取得程式碼

```bash
git clone https://github.com/yiznmin/smaet_kitchen.git
cd smaet_kitchen
```

之後每次開工先 `git pull`,收工前 `git push`(至少要 push `handoff/紀錄/`)。

### 步驟 0.5:把模型權重拉下來(2026-09-04 新增)

**我們自己訓練的 RF-DETR 權重放在 Git LFS 裡**,普通 `git clone` 只會拿到指標檔。

```bash
git lfs install          # 每台機器只要跑一次
git lfs pull             # 把指標換成真正的權重檔
```

驗收 —— 檔案大小要對:

```bash
ls -la model_result/nano/ model_result/medium/
```

| 檔案 | 應有大小 |
|---|---|
| `model_result/nano/checkpoint_best_regular.pth` | **117 MB** |
| `model_result/medium/checkpoint_best_regular (1).pth` | **129 MB** |

⚠ **若看到的是幾百 bytes 的文字檔,不是權重壞掉 —— 是還沒跑 `git lfs pull`。**
那個檔案裡面長這樣:

```
version https://git-lfs.github.com/spec/v1
oid sha256:...
size 123060123
```

⚠ **`medium` 那個檔名有空格和括號**(`checkpoint_best_regular (1).pth`),
在命令列要加引號。目前沒有任何程式引用它,實際在用的是 `nano`。

### ⚠ 有兩個權重**故意不在 git 裡**,要用就自己複製

| 檔案 | 為什麼不入庫 |
|---|---|
| `model_result/reid/osnet_reid.pth` | OSNet Re-ID,原始碼自己標「研究限定,僅驗證」 |
| `model_result/reid/external/market_bot_R50.pth` | FastReID,**Market-1501 訓練**,研究限定 |

**本 repo 是公開的** —— 推上去等於**公開散布研究限定權利物**,而本案是要出貨的
產學合作,授權會傳染。要在這台用它們,**直接複製檔案,不要走 git**。

(9/1 那輪 arm R 已經在遠端下載過 `market_bot_R50.pth`,應該還在。)

### ⚠ LFS 的額度會用完

GitHub 免費額度是 **1 GB 儲存 / 1 GB 每月頻寬**,現在已用掉 **258 MB**。

**LFS 不做差分 —— 每次 push 新的 checkpoint 都會再佔一份完整空間。**
所以:

- **不要**每訓練一輪就 push 一次權重
- 要交換新權重時,優先考慮 GitHub Release 附件或直接檔案傳輸
- `model_result/reid/` 底下的 Re-ID 訓練產物**仍然全部排除**(見 `.gitignore`)

## 步驟 1:建環境

⚠ **Python 用 3.10~3.12,不要 3.13+。** 本專案在 3.14 上已經有三個模型直接匯不出來
(2021 年的程式碼與新版 numpy/torch 不相容),Re-ID 框架同一風險。

```bash
conda create -n reid python=3.11 -y && conda activate reid
# 或:python3.11 -m venv .venv && source .venv/bin/activate
```

### torch 要「先看 CUDA 版本再裝」

⚠ **不要直接 `pip install torch`。** 多數環境會給你 CPU 版,而 CPU 版的症狀是
**「跑得動,但慢 50 倍」,而且完全不報錯** —— 訓練跑到一半才發現就浪費一天。

```bash
nvidia-smi          # 看右上角的 CUDA Version
# 再到 https://pytorch.org/get-started/locally/ 挑對應指令,例如 CUDA 12.4:
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
```

```bash
pip install -r requirements.txt -r requirements-reid.txt
```

### 檢查點

```bash
python scripts/check_reid_env.py --data-dir <打算放 CHIRLA 的路徑>
```

**必須 0 個 ❌ 才能往下。** 它會檢查五項,其中第 3 項會**實跑一次 ResNet50 的
forward+backward** —— 因為「`nvidia-smi` 列得出 GPU」不等於「torch 算得動」,
驅動不合或 VRAM 被佔用都會在那一步才炸。它同時會量 VRAM 峰值,告訴你 batch 要開多大。

不需要資料就能跑的驗證(順便確認環境正常):

```bash
python scripts/verify_reid_metrics.py     # 指標實作可信度,6 組
python scripts/verify_m4.py               # M4 追蹤
python scripts/verify_m5_st.py            # M5 時空邏輯
```

## 步驟 2:資料驗收(曾薪下載完之後)

```bash
python scripts/chirla_prep.py --root <CHIRLA 路徑> --verify
```

**exit code 0 才能往下,不通過就不要開始訓練。** 它會:

- 對帳論文規格:22 身份 / 7 相機 / 10 序列
- 檢查四種切分 CSV(`_train` / `_val` / `_gallery` / `_query`)都在
- 檢查 identity leakage(train 與 gallery/query 的身份不可重疊)
- **全掃 Git LFS pointer** —— 這是「看起來下載完了但檔案是空殼」最常見的形式。
  刻意做成全掃而非抽樣:90 萬張抽 30 張等於沒抽。

常見失敗與修法:

| 症狀 | 修法 |
|---|---|
| 大量影像小於 1KB | `git lfs pull`,或重跑 `huggingface-cli download` |
| 身份數 ≠ 22 | 可能只下載了部分 scenario |
| 找不到 CSV | 確認下載的是 `benchmark/` 而不是只有 `videos/` |

### 建索引

```bash
python scripts/chirla_prep.py --root <CHIRLA 路徑> --index --out chirla_index.json
```

## 步驟 3:訓練

先用 `--smoke` 確認能跑(每 epoch 只跑 2 個 batch):

```bash
python scripts/train_reid_chirla.py --index chirla_index.json \
    --scenario <從上一步的輸出挑一個> --arm S --epochs 2 --smoke --out /tmp/smoke
```

正式跑:

```bash
# S 臂(可出貨,交付主線)
python scripts/train_reid_chirla.py --index chirla_index.json \
    --scenario <scenario> --arm S --epochs 60 --out model_result/reid/armS

# R 臂(研究上限對照,不可出貨)—— 除了 --arm 與 --weights,其他參數必須完全一樣
python scripts/train_reid_chirla.py --index chirla_index.json \
    --scenario <scenario> --arm R --weights <外部 Re-ID 權重> \
    --epochs 60 --out model_result/reid/armR
```

### VRAM 不夠時

| VRAM | 參數 |
|---|---|
| ≥ 10 GB | 預設 `--P 8 --K 4` |
| 6~10 GB | `--P 6 --K 4` |
| < 6 GB | `--P 4 --K 4 --freeze-until 6` |

### 過擬合(預期會發生,不要藏)

只有 22 個身份,Market-1501 有 1501 個。train_acc 衝很高但 val 沒跟上是**預期中的事**。
對策:`--freeze-until 5`(凍結骨幹前段)、降 `--lr`、早停(預設 `--patience 15`)。
**train/val 曲線分離要如實記錄進報告**,那是資料規模的限制不是做壞了。

## 步驟 5:接回 M5

訓練好的模型可以直接插進 M5 主線:

```bash
python scripts/m5_track_video.py --embedder chirla:model_result/reid/armS/best.pth ...
```

⚠ **但要先重新校準 `src/m5_reid/evidence.py` 的 `AppearanceLR.MEASURED`** ——
那裡只有 dinov2/osnet 兩組實測分布。沒有新模型的 (mu_same, mu_diff),
`AppearanceLR.measured()` 會直接 raise。數字由 `reid_eval_epfl.cross_view_consistency()` 產生。
**這是最容易漏掉的一步。**
