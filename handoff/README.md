# 交接與紀錄 — 先讀這個

> 本機與遠端 GPU 機器之間的交接。**任何人(包含新開的 Claude session)接手前先讀完這一頁。**

## 這是什麼專案

產學合作的**智慧廚房食安追責系統**。攝影機拍廚房,系統要能回答「是誰在幾點碰了生肉、有沒有洗手」。
技術上分成 M2~M9 九個模組,目前 M3(偵測)、M4(追蹤)、M5(跨鏡頭身份)已完成並驗證過。

**現在在做的是工研院第一階段任務:用 CHIRLA 資料集訓練一個人物 Re-ID 模型,交期 2026-09-11。**

## 為什麼要做這件事(一句話)

M5 判斷「這個人是不是剛才那位」時會綜合多種證據,其中「長得像不像」那條一直是空的 ——
**不是技術做不到,是授權**:認得出人的 OSNet(Rank-1 92.7%)權重研究限定不可出貨,
可出貨的 DINOv2 只有 11%(比隨機還差)。

**CHIRLA 是 CC-BY-4.0 可商用**,用它訓練就能得到第一個「認得出人、而且能出貨」的模型。

## 工作流程

```
本機(寫程式、規劃)  ──git push──►  GitHub  ──git clone/pull──►  遠端(訓練、評估)
        ▲                                                            │
        └──────────── 紀錄/*.md 回寫,git push ◄─────────────────────┘
```

**兩邊都用同一個 repo,靠 `handoff/紀錄/` 交換狀態。** 每次在遠端做完一輪:
寫一份紀錄 → commit → push,本機這邊 pull 就知道發生什麼事。

## 三個絕對不要踩的坑

1. **Python 不要用 3.13+**。本專案在 3.14 上已經有 YOLOX / DAMO-YOLO / LW-DETR 三個模型
   直接匯不出來。Re-ID 框架多為 2019~2022 年的碼,同一風險。用 **3.11**。
2. **torch 不要直接 `pip install torch`**。多數環境會裝到 CPU 版,症狀是
   **「跑得動但慢 50 倍」而且不報錯** —— 訓練跑一半才發現就浪費一天。
   先 `nvidia-smi` 看 CUDA 版本再挑 wheel,裝完用 `check_reid_env.py` 確認。
3. **資料到位後先跑 `chirla_prep.py --verify`,不過就不要開始訓練**。
   資料是別人下載的,不完整或是 Git LFS pointer 會讓你白跑三天。
