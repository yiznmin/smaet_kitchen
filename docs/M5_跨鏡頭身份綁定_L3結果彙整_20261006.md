## 3. 兩項改動的分工

| 改動 | L3S 一致 | 增量 |
|---|---|---|
| 基準(A) | 5/16(31.3%) | — |
| **+ 修正拓撲**(B) | 12/16(75.0%) | **+43.7 點** |
| **+ M5 外觀**(C) | 14/16(87.5%) | **+12.5 點** |

**修正拓撲的貢獻是外觀的 3.5 倍,而且成本是零**(改一個設定檔,不需要模型、不需要 GPU)。

### 3.1 為什麼外觀原本沒用

M5 的綁定是「在候選集裡挑一個」。拓撲決定**誰進得了候選集**。

`camera_1` 在原始 `base.yaml` 裡**不在任何 `overlapping`、也不在任何 `links`** ——
只出現在時鐘偏移清單。→ M5 **結構上不可能**把它綁到別台,
**外觀再準也排序不到不存在的候選**。

**兩項改動是互補的**:先把候選放進候選集(拓撲),外觀才有機會發揮。

## 5. 設定

| 項目 | 值 | 說明 |
|---|---|---|
| M4 追蹤器 | `rf_mcbyte_nomask_app`,`DINOv2 w = 0.7` | 三格相同 |

| M5 embedder | `none`(A/B)/ `dinov2`(C) | |
| 拓撲 | `base.yaml`(A)/ `base_overlapfix.yaml`(B/C) | |
| `--ttl` | 600 次迴圈 = 100 秒 | 以迴圈計,不是秒 |

### 5.1 ⚠ 兩項改動的選定方式(照實說明)

| 改動 | 怎麼決定的 |
|---|---|
| **修正拓撲** | 重算 10 個序列標註的共現次數後,補上漏列的四對。**依據是實測,但套用與否是看過 L3 結果後決定的。** |
| **`w = 0.7`** | **看過 L2 結果後選的**。紀律上的合法選擇是 w=0.6;w=0.7 的推導集 IDSW 280 > 基準 264,被選參數規則排除。 |

**兩者都不是預先登記的驗證結果。** 要正式採用必須另立預先登記,把判準先寫死再跑。

### 5.2 修正拓撲改了什麼

依實測共現次數(10 個序列的標註,「同一人同一幀出現在兩台」),
`overlapping` 清單**只新增四對、不移除任何現有的**:

| 新增的對 | 實測共現 | 原本為何漏掉 |
|---|---|---|
| `camera_1 + camera_3` | **116,224** | 全資料集**第二高**,完全漏列 |
| `camera_1 + camera_2` | **58,333** | 漏列 |
| `camera_6 + camera_7` | **6,870** | 漏列(它同時也是一條 `link`) |
| `camera_1 + camera_5` | **5,109** | 漏列 |

對照:原清單裡最小的 `camera_2 + camera_4` 只有 **1,336** 次,
而清單裡的 `camera_5 + camera_6` 只有 **738** 次(**誤列**,本次未移除)。

## 6. 指標怎麼算

實作在 `src/common/clip_metrics.py` 的 `l3_handoff()`。L1/L2 共用的指標定義見
`docs/M4_外觀模型_L2單鏡頭再取得_結果彙整_20260929.md` §7,本節只列 L3 專屬的。

### 6.1 跨鏡頭一致率(`l3_p_handoff`)

1. 每台鏡頭各取目標在該台的**多數編號**(該台所有「被配對且有編號」的格)。
2. 列出所有鏡頭兩兩配對(3 台 → 3 對)。
3. **分母**:兩台都有編號的鏡頭對數。任一台沒有編號 → **該對排除**,計入 `n_pairs_dropped`。
4. **分子**:兩台的多數編號相同的對數。

### 6.2 同時幀一致率(`l3_p_simul_agree`)

1. 找出**同一個取樣幀**上有 ≥ 2 台鏡頭都綁定到目標的幀。
2. **分母**:這種幀的數量。
3. **分子**:那一幀上各台的編號**完全相同**的幀數。

⚠ 這個指標**比跨鏡頭一致率嚴格** —— 它要求每一幀都對,不是多數對。
⚠ **L3T 的分母是 0**(轉場從不同時出現)→ 回「不可量測」,不可印 0% 或 100%。

### 6.3 為什麼要兩個指標

跨鏡頭一致率用**多數決**,會掩蓋「大部分時間對、關鍵時刻錯」。
同時幀一致率逐幀看,抓得到那種情形。
本輪兩者走勢一致(16.2% → 93.4% vs 31.3% → 87.5%),**沒有互相矛盾**。

## 7. ⚠ 這份結果不能推論到哪裡

| 邊界 | 依據 |
|---|---|
| **多人場景:已實測會變糟** | 同一組修正在 **7 個完整序列 × 7 台鏡頭的多人資料**上:誤併率 **59.5% → 83.0%**,加權成本(誤併×5 + 碎裂)**+26.8%**。機制是決策從轉場路徑(誤併 44%)被搬到重疊路徑(誤併 80%),等於把「不敢綁」換成「亂綁」。本文件 17 段皆為獨佔片段,**沒有別人可以綁錯**,所以只量得到好處。 |
| **轉場仍未解決** | L3T 的 40% 來自 5 段中的 2 段,而**那 5 段全部牽涉 camera_5/6(玻璃倒影)**,外觀**分不出人與其倒影**。轉場路徑的天花板 **1.484 < 門檻 1.609** 這個結構問題**沒有被碰到**。 |
| **樣本極小** | L3S 分母 16 個鏡頭對、L3T 只有 **5 個**。L3T 的 2/5 區間是 **[0.118, 0.769]** —— 幾乎什麼都不排除。 |
| **倒影鏡頭佔多數** | 17 段裡 **14 段**牽涉 camera_5/6。排除後只剩 3 段(全部 100%,但樣本太小)。 |
| **現場會更差** | CHIRLA 每個人衣著不同;廚房為**同款制服加口罩**。**本文件數字是上界。** |
| **選定方式不合紀律** | 見 §5.1。 |
| **拓撲修正尚未套用** | `configs/fix_grid/base.yaml` **未改**。依 §7 第一列,**不應套用**。 |

## 8. 結論

**在單人、同一人同時被兩台鏡頭看到(L3S)的情境下,跨鏡頭身份綁定可以做到 87.5%。**

- 跨鏡頭一致 **31.3% → 87.5%**,同時幀一致 **16.2% → 93.4%**。
- 偵測與定位三格**逐位相同**(召回 0.9607、IoU 0.9370)→ 改善純粹來自身份綁定。
- **修正拓撲貢獻 +43.7 點、M5 外觀再貢獻 +12.5 點** —— 前者成本為零。

**兩件沒解決的事**:

1. **轉場(L3T)**:12 段 L3S 有 136 個同時出現幀,5 段 L3T **全部是 0**。
   沒有同時幀就用不上重疊路徑,而轉場路徑數學上通不過門檻。
   **這是證據模型本身的問題,改拓撲與加外觀都碰不到。**
2. **多人場景**:同一組設定讓誤併率從 59.5% 升到 83.0%。
   **這份結果只在單人前提下成立。**
