## 1. 為什麼要做

`docs/M4_層0_關聯方法_預先登記_20260915.md` §8 的勝出者 `cbiou`,是 `cbiou` / `ocsort` 兩個候選
在**評估集 7 個序列**上比較後選出來的。**在同一批資料上挑最好的,成績會偏樂觀。**

推導集 seq_000 / 001 / 002 **從未參與任何 M4 的決策**(門檻、stride、backend、方法參數都不是在它上面選的),
可以回答一個問題:

> **`cbiou` 在沒看過的資料上,是否仍然通過全部主判準與硬性約束?**

⚠ 推導集並非「完全沒碰過」:它曾用來估 M5 的轉場拓撲(`chirla_build_topology.py`)與 F4 的逐對單應性
(`chirla_build_crossview.py`)。**M4 追蹤評估不讀這兩者**,所以對本輪不構成洩漏,但要記錄。

依規矩第 1 條:打的是**層 0 的 B 類**;本輪不是修法,是確認 9/15 的修法是否穩健。

## 5. 事先寫下的預測(可被否證)

| # | 預測 | 依據 |
|---|---|---|
| **1** | `d_cbiou` 的 B 佔比**低於** `d_t010` | 9/15 評估集:20.14% vs 29.85% |
| **2** | `d_cbiou` 較 `d_rf_botsort` 的 B 佔比**相對下降 ≥ 10%** | 9/15 評估集:−21.6% |
| **3** | `d_rf_botsort` 的 B 佔比**低於** `d_t010` | 9/15 橋樑格效應:−4.17pp |
| **4** | `d_cbiou` 相對 `d_t010` 的 B 佔比降幅**小於** 9/15 評估集的 **9.71pp** | 在評估集上挑出的勝出者,換到新資料通常會回落(贏家詛咒) |

### 5.1 失敗條件與處置(先寫死)

- **若 M1 不成立**(`d_cbiou` 的 B 佔比沒有同時低於兩者)→ 判定 **9/15 的勝出不穩健**。
  處置:**不以 `cbiou` 進入步驟 3**,**不在推導集或評估集上調參**,結果回報使用者決定下一步。
- **若 M1 成立但 M2 或任一硬性約束不過** → 判定「方向成立但代價未確認」。
  處置同上:不自動進步驟 3,回報使用者決定。
- **若全部通過** → `cbiou` 確認為層 0 的新設定,進步驟 3(完整 M5 + 四層分解,另寫預先登記)。
