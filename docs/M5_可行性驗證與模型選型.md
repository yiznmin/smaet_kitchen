## 1. 可商用模型結論:DINOv2(Apache-2.0)

| 模型 | 程式碼 | 權重 | 可出貨? | 角色 |
|---|---|---|---|---|
| **DINOv2** | Apache-2.0 | **Apache-2.0** | ✅ **可** | **出貨候選**(通用外觀特徵) |
| OSNet / torchreid | MIT | 研究限定(Market-1501…) | ❌ | **僅驗證上限對照** |
| InsightFace(人臉) | MIT | 多非商用 + 生物辨識 | ❌ | 本專案不做 |

- **DINOv2 主模型 code + weights 皆 Apache-2.0**(已查官方 repo;CC-BY-NC 只適用其 Cell-DINO 生物延伸)。影像相似度優於 CLIP;RF-DETR 本就用 DINOv2 backbone → 生態相容。
- DINOv2 是**通用視覺特徵、非 Re-ID 專用**;實際 Re-ID 準確度**要驗**(見下)。
- 來源:https://github.com/facebookresearch/dinov2 (LICENSE: Apache-2.0)

> ⚠ **驗證用的 OSNet 權重與 Market-1501 皆研究限定,不可出貨、不可散布、不可拿來訓練出貨模型。** 它們只用來「證明技術可行 + 當 DINOv2 的對照上限」。

## 2. 主驗證:EPFL 同步多視角(廚房域,推薦)

**為什麼改用 EPFL**(取代 Market-1501 為主):
- Market-1501 是**街上行人、衣著多樣(好認)**;廚房廚師**衣服基本相同**,街上高分不代表廚房。
- EPFL 是**同步多視角**:同一時刻 9 台鏡頭拍**同一個人** → **天生的 same-person ground truth**,而且**就是廚房域**。不同場次(不同參與者)= 不同身份。

**工具**:`scripts/prep_m5_epfl.py`(下載 K 個不同參與者場次、抽同步幀)+ `scripts/reid_eval_epfl.py`(RF-DETR 微調權重偵測 person→裁切→DINOv2 抽特徵→三指標)。
```bash
python scripts/prep_m5_epfl.py --k 6                 # 準備 6 個廚房身份的同步幀
python scripts/reid_eval_epfl.py --embedder dinov2   # 跨視角一致性 + Rank-1 + chef_id 綁定
```
量三件事:①**跨視角一致性**(同人不同視角特徵多像)②**身份判別 Rank-1/mAP**(over 場次)③**chef_id 綁定**掃門檻。

**現況**:管線已在本機(CPU)跑通;用 M3 微調權重偵測 person(COCO 預訓在俯視視角幾乎抓不到人)。
**早期煙霧測試(僅 2 身份)**:DINOv2 跨視角同人相似度 ~0.52、不同人 ~0.45(**差距很小**);2 身份 Rank-1=1.0(身份太少、判別很鬆)。→ **需 6–8 身份才有判別力訊號**。

> ⚠ 觀察到:EPFL 參與者穿**自己的衣服(有色差)**,所以它仍**無法完全代表「制服完全相同」**的極難情形;但域對、且驗到跨視角一致性,遠比 Market-1501 貼近。

## 補充驗證:Market-1501(多身份,但域不同)

```bash
# 需 torch(dinov2)或 torchreid(osnet)+ Market-1501(研究用途)
python scripts/reid_eval_market1501.py --data data/market1501 --embedder dinov2   # 可商用候選
python scripts/reid_eval_market1501.py --data data/market1501 --embedder osnet    # 研究上限對照
```

量三件事:
1. **標準 Re-ID 指標 Rank-1 / mAP**(query 對 gallery 餘弦排名,標準協定排除同 pid+同 cam)。
2. **chef_id 綁定正確率**:模擬 `IdentityManager` 決策(比對最相似的已知廚師、cosine≥門檻才綁),量綁對 / 綁錯(身份污染)/ 漏綁。
3. **掃 `similarity_threshold`** → 定 DINOv2 版操作點,寫回 `configs/reid.yaml`(預估 0.6~0.75)。

- 可插拔 embedder:`src/m5_reid/dino_embedder.py`(DINOv2)、`osnet_embedder.py`(OSNet);皆 `BaseEmbedder` 子類,`IdentityManager` 不動。
- metric/binding 為純函式,已用**合成特徵單測通過**(完美可分離 → rank1=mAP=1.0;門檻行為正確)。

## 4. 誠實限制(必讀)

1. **街上 ≠ 廚房**:Market-1501 是路上行人、**衣著多樣(較好認)**;廚房廚師**相似白制服(難認)**。這裡拿高分只證明「技術可行」,**不保證廚房**。
2. **驗證資料/OSNet 權重不可出貨**;可出貨路徑只有 **DINOv2** 或**自訓**。
3. **最終仍需自錄多人廚房資料**(2–3 位、實際制服、跨鏡頭、含離開再現、標 chef_id+鏡頭+時間;spec §C.5)才算真正驗證廚房可行性。

---

## 5. 若 DINOv2 不夠用 → 自訓路徑

1. 用**自錄廚房多人資料**(或可商用授權資料)**微調**一個外觀模型(OSNet/DINOv2 架構皆可,重點是**訓練資料可商用**)。
2. 微調後同樣用本工具在自錄 test 集上量 Rank-1/綁定正確率。
3. 換入 `BaseEmbedder` 子類,`IdentityManager` 與門檻流程完全沿用。
