## 2. 精確的失效機制(不是「沒有正確率項」)

2026-09-12 的交接紀錄寫「`cost` 沒有獎勵正確」。**那個描述不夠精確**,
而精確的版本更有用。

三個結果互斥且窮盡,所以 `FM + BR + C = 1`(七格實測全部 = 1.0000):

```
cost = 5·FM + 1·BR
     = 5·FM + (1 − FM − C)
     = 1 + 4·FM − C
```

**它有正確率項,權重 1;誤併項權重 4。相差四倍。**

所以「用 1pp 的正確率換 0.25pp 的誤併下降」在這個判準下就算划算。
`f1f2` 讓出 9.38pp 正確率、換到 55.83pp 誤併下降 → 依判準是**大賺**。

### 為什麼「權重比」這個框架本身在這裡不適用

5:1 是為**大致能運作、偶爾出錯**的系統推導的 —— 那時邊際取捨的邏輯成立。

但 `base` 的誤併是 **58.84%**:系統不是偶爾出錯,是**根本沒在運作**。
這種狀態下,「少綁一點就少錯一點」永遠划算,一路滑到**完全不綁**。

```
完全不綁的系統:FM → 0、C → 0、BR → 1   ⇒   cost = 1.0(下界)
f1f2 的 1.116 距這個地板只有 +0.116
```

> **純損失函數沒有辦法表達「系統必須有用」。** 它只能表達「錯得少」,
> 而「什麼都不做」永遠錯得最少。

## 3. 修正後的判準(往後每一輪適用)

### 3.1 主判準:**IDF1 必須上升**

用標準 MOT 的 IDF1,不自創指標。理由:

- 它直接量「身份有沒有被正確地維持」,同時含 precision 與 recall
- **拒絕作答會同時壓低兩者** → 結構上不可能靠不綁來刷分
- `metrics.py` 已經在算,不需要新實作,而且與文獻可對照

```
IDF1 > 基線 IDF1        → 可以進一步考慮
IDF1 ≤ 基線 IDF1        → **修法無效**,不論 cost 多低
```

### 3.2 硬性約束:**正確率不得低於基線**

```
p_correct ≥ 基線 p_correct
```

一個讓系統**更少綁對**的修法不是修法。這條與 §3.1 高度相關但不重複 ——
IDF1 會被碎裂稀釋,正確率是更直接的「有沒有做對事」。

### 3.3 次判準:`cost` 保留,但**降級為排序工具**

在**通過 §3.1 與 §3.2** 的候選之間,用 `cost` 排序 ——
那是 5:1 的成本不對稱該發揮作用的地方(兩個都有用的修法,選誤併較低的那個)。

**`cost` 不再是通過/不通過的門檻。**

### 3.4 ⚠ 判準失效的自我檢查(先寫死)

往後每一輪,若出現以下任一情況,**先懷疑判準而不是慶祝**:

| 徵兆 | 含意 |
|---|---|
| `cost` 大幅改善但 IDF1 下降 | 判準被「拒絕作答」鑽了空子 |
| 碎裂率 > 80% | 系統實質上停止綁定,任何指標都不再有意義 |
| `cost` 距其下界 1.0 小於 0.3 | 逼近「什麼都不綁」 |

這是 repo 工作文化第 6 條(主判準大幅改善時先懷疑判準)的具體化。

## 5. ⚠ 這份修正**不能**解決的事

1. **IDF1 也不是萬能的。** 它對碎裂相對寬容(切成兩段仍保有大部分 IDTP),
   所以 §3.2 的正確率硬約束不可省略。
2. **5:1 這個成本比仍然沒有實測來源。** 它現在只影響排序不影響通過,
   風險降低了但沒消失。與「每 2~5 分鐘跨一次鏡頭」同屬待校準的假設。
3. **基線本身很低(IDF1 0.1214、正確率 9.83%)。** 「超過基線」是很低的門檻,
   達到它不等於可用。真正的驗收門檻仍是誤併 ≤1% / 碎裂 ≤5%,
   那個目標目前**沒有任何修法接近**。
4. **這份修正沒有讓任何修法變得有用。** 它只讓我們**看得出**它們沒用。
