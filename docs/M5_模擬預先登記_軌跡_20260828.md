## 1. 要修什麼(已量化的根因)

拆解剩下的誤併:

```
真的那位永遠在候選集裡          100%
真的那位勝出                     91%
真的那位輸掉                      9%  ← 其中 76% 是兩人相距 < 0.5 m
                                       (中位數 0.11 m,等於站在同一點)
```

**位置這個證據軸到此為止。** 兩個人站在同一個地方時,位置分不出誰是誰,
而我們已經測到 σ=0.05 m(近乎完美校正)仍是如此 —— 這是物理極限,不是精度問題。

## 2. 修法:速度/軌跡

兩個站在同一點的人,**是從不同方向走過來的**。位置相同,速度不同。

這是一個**還沒動用的證據軸**,而且與位置正交:

```
LLR_vel = log p(Δv | 同一人) − log p(Δv | 不同人)
        = log V − log(2πσ_v²) − |Δv|² / (2σ_v²)

Δv  = 新 track 的速度向量 − 候選者的速度向量(世界座標,m/s)
σ_v = 速度估計噪聲
V   = 「不同人」時速度差的散布範圍(速度空間的面積,m²/s²)
```

與 `GroundPlaneLR` 是同一套數學,只是換到速度空間。

⚠ 這**不是** CLM 四線索(拓撲/時間/方向/外觀)裡的任何一個。
  它是**運動連續性**,而且全景鏡頭本來就在連續追蹤,軌跡資料是現成的。

## 3. 實作前先算清楚(第二輪的教訓)

速度估計噪聲:`σ_v ≈ σ_pos · √2 / Δt`(兩個位置點差分)。
取 σ_pos = 0.1 m(地面校正殘差)、觀測窗 Δt:

| 觀測窗 Δt | σ_v | 證據上限 log(V/2πσ_v²) | 判定 |
|---|---|---|---|
| 0.25 s | 0.57 m/s | **0.76 nats** | 太吵,幾乎無用 |
| 0.50 s | 0.28 m/s | **2.15 nats** | 可用 |
| 1.00 s | 0.14 m/s | **3.53 nats** | 好,但要等 1 秒 |
| 2.00 s | 0.07 m/s | **4.92 nats** | 更好,但延遲明顯 |

(取 V = π·1.5² ≈ 7 m²/s²,即人的步行速度上限約 1.5 m/s、方向任意)

**登記時先講清楚:這是「延遲換精度」的取捨。** 觀測窗越長證據越強,
但綁定決策要等越久。門檻 1.61 nats → **Δt 至少要 0.4 秒**。

## 4. 模擬設計:世界模型必須先改

⚠ **現在的世界模型 `step_world()` 是隨機遊走,速度沒有持續性** ——
  每一步的方向都獨立重抽。那會讓軌跡證據**因為錯的理由失效**:
  不是「速度分不出人」,而是「這個世界裡速度根本不預測下一步」。

真實的人走路是有慣性的:朝一個方向走幾秒,偶爾轉向。
所以世界模型要改成**帶速度持續性的隨機過程**(Ornstein–Uhlenbeck):

```
v ← v·exp(−Δt/τ_v) + 噪聲        τ_v = 速度自相關時間
x ← x + v·Δt
```

τ_v 是新增的世界參數,**必須掃描** —— 因為它直接決定軌跡證據有沒有用:
τ_v 很小 = 隨機遊走 = 軌跡無資訊;τ_v 很大 = 直線行走 = 軌跡極有資訊。

## 5. 掃描網格(事先固定)

| 參數 | 掃描值 |

| 地面校正 σ | 0.1(固定,已知可用) |
| 廚師人數 | 4(主網格)、8 |

**其他世界參數固定**:全景鏡頭開啟、`master_fragment_rate=0.05`、
`p_loiter=0.15`、`p_detour=0.05`、`m4_fragment_rate=0.05`。
**執行**:`--reps 12 --hours 1.5`。

## 6. 判準

沿用第一輪 §4:A(碎裂≤5% 且誤併≤1%)/ B(≤10% 且 ≤3%)/ C(其餘)。
加權成本 = 碎裂 + 5 × 誤併。次判準:正常轉場碎裂不得惡化超過 1 個百分點。

**本輪特有的成功條件**:誤併率從 14.5% 至少降到 **10% 以下**,
且碎裂率不惡化。低於 3% 才算真正突破(B 級)。

**本輪特有的失敗條件**:若在**任何**觀測窗與 τ_v 組合下誤併都降不到 12% 以下,
判定「軌跡證據不足以解決近距離模糊」。屆時的結論是:
**剩下的誤併是多人近距離共處的本質模糊,演算法層面已無解**,
只能靠流程手段(徽章/腕帶)或接受這個誤差並在 M6 設計上補償。

## 7. 事先寫下的預測(可被否證)

1. **軌跡證據的效益集中在「兩人相距 < 0.5 m」那一類**,對其他情境幾乎無影響。
   若整體改善但近距離那類沒改善,表示我把證據接錯地方了。
2. **效益隨 τ_v 單調上升**。τ_v=1.0(接近隨機遊走)時幾乎無效,
   τ_v=8.0(接近直線行走)時明顯有效。
3. **觀測窗 0.5 s 已足夠**(§3 算出 2.15 nats > 門檻 1.61),
   1.0 s 與 2.0 s 的邊際效益遞減。
4. **改善幅度小於地面校正的 5 倍**,因為它只救得了 9% 裡的 76%。
   樂觀估計誤併 14.5% → 約 8~10%。
5. **碎裂率不會惡化** —— 軌跡只影響「綁給誰」,不影響「綁不綁」。
   若碎裂惡化,又是接錯地方(第六輪同樣的教訓)。

## 8. 已知限制

- **新出現的 track 沒有速度**。它剛進畫面,還沒有軌跡。所以軌跡證據只能用在
  「候選者(全景鏡頭裡連續追蹤中的人)」那一側,或**延遲決策**等新 track 累積
  幾幀。本輪採**延遲**,並把延遲時間當成掃描參數(即 `vel_window_s`)。
  ⚠ 這代表 chef_id 的指派會延後 0.5~2 秒。spec 的資料流是事後查詢
  (M6→M7 非同步→M8→M9),所以可接受;若 M6 有即時告警需求則不適用。
- τ_v 是新的世界參數,**沒有實測依據**。所以本輪量的是「軌跡證據在不同
  行走慣性下有多少效益」,不是絕對準確率。真實廚房的 τ_v 需量測。
- 速度是從**地面校正後的世界座標**差分而來,所以它繼承校正誤差。
  σ=0.1 m 是樂觀值(實測隨便標也有 0.078 m,但腳點被遮擋時會大得多)。
