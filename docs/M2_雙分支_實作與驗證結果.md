## 1. 兩條分支的分工(對「人」態度相反)

| | 分支 A | 分支 B |
|---|---|---|
| 抓什麼 | 大動作 / 有人活動 | 孤立的小目標(老鼠) |
| 框的樣子 | 一個大框框住移動區 | 把人清掉,只留孤立小框 |
| 對「人」 | **就是要抓人**(送 M3 認他) | **要把人排除掉**(雜訊) |
| 輸出 | has_motion=True → 整張送 M3 | 確認是目標的小裁圖才存 |
| 模型 | M3 = RF-DETR | 自己的輕量分類器(MobileNet) |
| 對小目標 | 全域門檻會漏(motion_ratio 太低) | 專門補這個洞 |

```
影格 ──┬─ 分支 A:有大動作? → 整張送 M3(RF-DETR)認人/食材/器具
       └─ 分支 B:把人清掉 → 找孤立小目標 → 分類器認老鼠
```

## 2. 分支 B 的判別機制(四層幾何過濾)

依序套用,**全部「寧可多留、別誤砍老鼠」**;精準判斷留給最後的分類器。

| 順序 | 機制 | 砍掉什麼 | 留下什麼 | 對應程式 |
|---|---|---|---|---|
| 1 | **MOG2 背景相減** | — | 靜止背景上「移動的小前景」(定位) | `cv2.createBackgroundSubtractorMOG2` |
| 2 | **連通元件 + 面積分流** | 太小(雜訊)、太大(人/大事件→分支A) | 中間尺寸的小斑塊候選 | `connectedComponentsWithStats` |
| 3 | **空間排除** | 緊鄰大斑塊(人=單一大塊時)的碎塊 | 遠離大斑塊的孤立小斑塊 | `_near_any()` |
| 4 | **密度排除** ⭐ | 密集疊一起的群聚(人大動作散成多塊) | 孤立的小斑塊(像老鼠) | `_isolate()` |
| 5 | **時序持續性** | 閃一兩幀就換位置的雜訊(反光/影子) | 連續出現且連貫移動的目標 | `_update_tracks()` |
| — | **裁切放大** | — | 在 blob 座標裁 256×256 原生解析度圖 | `_extract_crop()` |
| — | **不丟棄策略** | — | 全部保留交分類器(max_crops 只警示) | — |

### 2.1 關鍵修正:密度排除(本輪重要洞察)

**原本的反向判斷**:把「小框/密集」當老鼠候選 → 人大動作散成一堆小框時,反而把人全留下。

**修正後**:
```
密集疊一起 = 人(砍掉)   ← 人大動作 = 一堆互相重疊的小框
孤立、遠離人群 = 老鼠候選(保留)
```
做法:數每個小框半徑 `density_radius` 內的鄰居數,≥ `density_max_neighbors` 視為群聚(人)→ 排除;孤立的留。**總數很少時全留**(孤立的老鼠永遠保得住)。

### 2.2 為什麼需要「空間排除 + 密度排除」兩種

- 人**靜止**時 = 一個大連通塊 → 空間排除(機制 3)處理。
- 人**大動作**時 = 散成一堆中型碎塊,沒有單一大塊 → 密度排除(機制 4)處理。
- 兩者互補,覆蓋「人=一大塊」與「人=一堆小塊」兩種情況。

## 3. 參數表(configs/benchmark.yaml → m2_branch_b)

| 參數 | 值 | 作用 | 調整方向 |
|---|---|---|---|
| `min_blob_area` | 8 | 小斑塊面積下限(濾雜訊) | 怕漏老鼠 → 設小 |
| `large_blob_area` | 2000 | ≥ 此面積=大事件,交分支 A | 太低會把大老鼠誤判成大事件 |
| `exclusion_margin` | 24 | 與大斑塊距離 < 此值即排除 | 設小=只砍貼著的,避免誤砍貼腳邊老鼠 |
| `density_radius` | 120 | 多少 px 內算鄰居 | — |
| `density_max_neighbors` | 3 | 鄰居 ≥ 此值=群聚(人)→ 排除 | 設大=更保守(更不易誤砍) |
| `crop_size` | 256 | 裁切窗邊長(放大小目標) | 依老鼠在畫面典型大小 |
| `max_crops_per_frame` | 32 | **負載警示門檻(非上限)**,只記錄不丟 | — |
| `mog2_history` | 500 | 背景模型記憶幀數 | — |
| `mog2_var_threshold` | 16 | 前景敏感度 | 小=敏感、易誤報 |
| `warmup_frames` | 30 | 暖機幀數(期間不輸出) | — |
| `persistence_frames` | 3 | 連續幾幀才確認 | 1=關閉時序 |
| `match_max_dist` | 60 | 兩幀視為同目標的最大位移 | 老鼠不瞬移 |
| `track_max_miss` | 2 | 軌跡容忍幾幀沒對到 | 短暫遮擋容忍度 |

## 4. 測試與驗證結果

驗證腳本:[scripts/verify_branch_b.py](../scripts/verify_branch_b.py);報告:[results/m2/branch_b/branch_b_verify.md](../results/m2/branch_b/branch_b_verify.md)。

### 4.1 合成單元測試(答案已知,自動判對錯)— 全 PASS

| 測試 | 方法 | 結果 |
|---|---|---|
| **A vs B 對照** | 14×9px 小目標(佔畫面 0.014%)移動 20 幀 | 分支 A 命中 **0/20**(漏);分支 B 命中 **18/20**(救回) |
| **時序持續性** | 連貫移動 vs 每幀瞬移 | 連貫:第 2 幀(persistence-1)起確認、8/10;閃爍亂跳:**0/20**(全擋) |
| **密度排除** | 6 密集(人)+ 1 孤立(老鼠) | 只保留 **1** 個(孤立的那個) |

### 4.2 真實影片驗證(EPFL,全程有人煮菜、**無老鼠** = 最壞情況)

密度排除前後,人身上的綠框(老鼠候選)數量:

| 影格 | 修正前(反向判斷) | 修正後(密度排除) | 砍掉的人碎塊 |
|---|---|---|---|
| f300 | 綠框 1 | **綠框 0** | dense ~80 |
| f320 | 綠框 45 | **綠框 0** | dense 73 |
| f340 | 綠框 81 | **綠框 0** | dense 152 |

**結論**:在「全程有人」的最壞情況下,分支 B 把人**完全清乾淨**(綠框=0)。因為此片無老鼠,**正確答案就是 0**,系統做到了不誤留。

視覺化圖檔(藍=人/大區域、綠=小目標候選、青=分支 A 全域框):
- 分支 B:`results/m2/branch_b/branch_b_f3*.png`
- 分支 A:`results/m2/branch_b/branch_a_f3*.png`(青框框住人,send-to-M3)
- 裁切內容:`results/m2/branch_b/crops/crop_f320_c*.png`(本片內容皆為人,待分類器拒絕)

### 4.3 誠實的限制

- 幾何 + 時序**無法分辨「賴在原地持續動的人手」與「逗留的老鼠」**——那是**外觀**問題,只有分類器能解。
- 幾何層的角色是**降量、殺雜訊**;**最終人 vs 老鼠的判斷必須靠分類器**。
- 真實抓老鼠情境(深夜、無人)畫面乾淨,分支 B 幾乎零框;有人煮菜是壓力測試。

## 4B. 靜態線(水漬偵測)實作與驗證

對應事件清單「環境設施／潑灑事件、殘渣掉落」。**水漬與老鼠動態特性相反**(老鼠持續移動;水漬潑灑瞬間動、落地後靜止),故需獨立一條偵測線。程式:[src/m2_motion/static_line.py](../src/m2_motion/static_line.py)`StaticTargetDetector`。

### 4B.1 判別機制(慢速基準比對 + 五層過濾)

| 機制 | 砍掉什麼 | 留下什麼 |
|---|---|---|
| **慢速基準比對**(accumulateWeighted) | — | 與「平常場景」不同的新增物(MOG2 會吸收靜止物,故改用慢速基準) |
| **靜態判定**(= 不同 AND 現在沒在動) | 正在動的(人) | 落地靜止的(水漬) |
| **樓地板 ROI** | 牆/檯面/上半部(水漬只在地面) | 地板範圍內的 |
| **動作排除**(把移動區外擴 margin) | 人(身體不動但旁邊手在動) | 周圍無動作的(水漬) |
| **長寬比過濾** | 瘦高的(站立的腿) | 扁平的(躺在地上的水漬) |
| **密度排除 + 持續存在** | 密集群聚、一閃即逝的 | 孤立且賴著不走的 |

> 與動態線的根本差異:背景用**慢速基準**(非 MOG2)、確認用**持續靜止**(非連貫移動)、大塊**保留**(大灘水漬,非丟給分支 A)。

### 4B.2 測試結果

驗證腳本:[scripts/verify_static_line.py](../scripts/verify_static_line.py)、示範:[scripts/demo_spill.py](../scripts/demo_spill.py)。

| 測試 | 方法 | 結果 |
|---|---|---|
| **靜止 vs 移動** | 靜止水漬 vs 每幀換位的移動物 | 靜止水漬確認 **12/20**;移動物 **0/20**(正確排除) |
| **長寬比測誤砍** | 扁平水漬 + 瘦高腿同時放 | 扁平水漬**保留(不誤砍)**;瘦高腿排除 ✅ |
| **合成污漬示範** | 把扁平污漬貼到 EPFL 地板 | 污漬被**框出 + 裁成 256×256 送分類器**(crop 內容清晰可辨) |

合成污漬示範圖:`results/m2/static_line/spill_demo/`(紅框=污漬、綠框=其他靜態、青=地板ROI;`crops/` 為送分類器的原始小圖)。

### 4B.3 誠實的限制

- EPFL 真片(全程有人站立)靜態線觸發 **2196/2340**——殘留主要是**站著工作的人下半身**:它「靜止、孤立、在地板、不瘦高」,**幾何上與一灘水漬完全相同**,無法再用幾何分。
- 這是**設計上的正常**:M2 只負責定位+推送,人腿與水漬都會被推給分類器,由分類器判「水漬/拒絕」。幾何層做到降量即可。
- 真實水漬偵測在區域淨空時最乾淨;有人時的殘留交分類器。

### 4B.4 樓地板 ROI = 人工設定一次

地板是**固定的**(攝影機不動)→ 屬「**裝機時人工框一次、存檔、開機載入**」的設定,不是 runtime 計算,符合專案 zone 設計。目前 demo 用手估的概略多邊形;**通用 zone 標註工具(手點多邊形→存檔)列為下一步**。語意分割自動產草稿(ADE20K floor 類別)為日後鏡頭多時的升級選項,但精度需求低、且權重多為非商用,優先序低。

## 5. 模型決策

| 模組 | 模型 | 授權 | 理由 |
|---|---|---|---|
| M3 主偵測 | **RF-DETR**(nano–large) | Apache-2.0 | 準確優先、小物件最強;取代速度冠軍 D-FINE-N |
| 分支 B 分類器 | **MobileNetV3 / EfficientNet-lite** | Apache/BSD | **多類別**(老鼠 / 水漬殘渣 / 拒絕);輕量,與 M3 共用 ONNX Runtime |

> 註:分支 B 已擴充為**多目標**——老鼠(動態)+ 水漬殘渣(靜態),兩者動態特性相反,需動態線/靜態線兩種偵測,匯入同一多類別分類器。詳見 [M2_雙分支重構設計.md](M2_雙分支重構設計.md) §3.2–§3.3。本輪完成的是**動態線**。

> 排除 Ultralytics YOLO(AGPL),延續出貨合規。RF-DETR XL/2XL 為 PML 不可商用,不採用。

## 7. 現況與下一步

```
分支 B 兩條線(定位+裁切+推送)        分類器(判身分)
  動態線(老鼠):MOG2 + 四層過濾   ✅完成  ┐
  靜態線(水漬):慢速基準 + 五層過濾 ✅完成  ├→ 多類別分類器  ⬜ 待權重
                                          ┘
```

**動態線 + 靜態線的幾何前處理全部完成且各有測試。** 唯一缺口 = 多類別分類器權重(需資料)。

下一階段:
1. **通用 zone 標註工具**(手點多邊形 → 命名 → 存 zones.json):供靜態線地板 ROI 與 M6 各 zone 共用。最準、一次性設定。
2. **合成貼圖 + 多類別分類器訓練**:老鼠 + 水漬正樣本 + 困難負樣本(人腿、櫃子、蒸氣)→ 訓練 MobileNet → 接上 `classifier.py`,整條線閉環。
3. **分支 A 省電驗證**:量測「無人安靜幀」分支 A 是否正確不送 M3(GPU 省電比例)。
