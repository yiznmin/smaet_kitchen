# M3 物件偵測 — 迭代式訓練 SOP(標註 → 資料 → 訓練 → 每類門檻)

> 這是**接下來正式的訓練做法**。核心是「**資料驅動迭代**」:訓練 → 看報表 → 針對弱點補資料 → 再訓練,直到達標,最後調每類門檻並部署。
> 版本 v1(2026-08-06)。

---

## 0. 一頁流程圖

```
① 訂驗收標準(每類 Recall/Precision 目標,食安類優先)
        ↓
② 準備標註資料(抽幀→分批標→合併→切分)
        ↓
③ fine-tune RF-DETR(一鍵筆記本;nano+medium)
        ↓
④ 看報表(AP / Precision / Recall / F1,逐類)
        ↓
   達標? ──否──▶ ⑤ error analysis:找最爛的類/情境
        │                 → 針對性多標那些 → 回到 ②
        是
        ↓
⑥ 調每類信心門檻(部署前,從 val 掃,不重訓)
        ↓
⑦ 鎖定變體 → 轉 ONNX → 部署(接 M4 追蹤 / M6 事件)
```

---

## 1. 前提觀念(先懂這幾點,不走冤枉路)

1. **RF-DETR 已預訓練**(COCO,Apache-2.0 可商用)。你做的「訓練」= **拿你的標註資料 fine-tune**,不是從零訓練。
2. **可出貨模型只能用真實資料**。EPFL 是 **CC-BY-NC(禁商用,丟棄驗證)**;Roboflow 廚房是 **CC BY 4.0(可商用,但只沾到刀/容器幾類)**。**真正的迭代跑在你們自己的真實廚房影片上。**
3. **補資料 ≠ 亂加**。要**針對報表上最弱的類/情境**補,才有效率。
4. **門檻能換不能生**:調門檻只在 precision↔recall 取捨,**無法把模型偵測不到的東西變出來**——那要補資料。

---

## 2. 步驟②:準備標註資料

流程:**抽幀 → 分批標註器 → (幫手)標 → 合併 → 切分**

```bash
# 抽幀(真實影片換成你們的檔)
python scripts/extract_multiview_frames.py --per 40      # 或自訂

# 產生分批標註器(每檔內嵌 200 張,自我包含)
python scripts/make_bbox_labeler_html.py \
   --img_dir data/m3_finetune/mv_images \
   --out results/m2/labeler.html --batch 200 \
   --classes 人,刀具,砧板,食材,鍋鏟,鍋子,手,容器,抹布,夾子,手套

# (幫手標完回傳 coco_1.json、coco_2.json…)後:合併多批
python scripts/merge_coco.py --out data/m3_finetune/_labeled.json coco_1.json coco_2.json

# 切 train/valid/test
python scripts/split_coco.py --labeled data/m3_finetune/_labeled.json \
   --img_dir data/m3_finetune/mv_images --out_base data/m3_finetune_mv
# → 壓成 dataset.zip
```

- **11 類固定**:`人 刀具 砧板 食材 鍋鏟 鍋子 手 容器 抹布 夾子 手套`(順序/名稱不可改)。
- 標註規範與交接:[M3_標註幫手上手說明書.md](M3_標註幫手上手說明書.md)。
- 可**合法混入 Roboflow**的 knife→刀具、bowl/cup/plate→容器(CC BY 可商用,需標來源)。

## 4. 步驟④:看報表 + 驗收標準

**食安是 Recall 優先(寧多抓不漏)。** 逐類看 Recall,別只看整體 mAP。

### 建議驗收門檻(可與指導教授調整)
| 類別群 | 指標 | 目標 |
|---|---|---|
| **食安關鍵**(刀具、食材、砧板、人、手) | **Recall** | **≥ 0.90** |
| 一般物件(容器、鍋子、鍋鏟、抹布、手套、夾子) | **F1** | **≥ 0.80** |
| 整體 | mAP@50 | ≥ 0.85 |

> 沒訂門檻就不知道何時該停。先訂,才有客觀依據決定「還要不要再補資料」。

---

## 5. 步驟⑤:error analysis + 針對性補資料

沒達標時,**不要亂加資料**,照這個順序:

1. **找最爛的類**(看報表 Recall/Precision 最低者)。例:bootstrap 中 **鍋子 Recall 0.4、砧板 Precision 0.57** 最弱。
2. **判斷原因**:
   - **樣本太少**(鍋子 28 框)→ **多標那一類**。
   - **常被誤判**(砧板 precision 低)→ 多標**容易混淆的負例情境**。
   - **特定情境漏**(如強光、遮擋、遠距)→ 補**那種情境**的畫面。
3. **針對性補**那些畫面 → 回到步驟② → 重訓 → 再看報表。

> 針對弱項補 100 張,勝過亂加 1000 張。

---

## 6. 步驟⑥:每類信心門檻(部署前調,不重訓)

達標後,用**每類不同門檻**把操作點調到最好。**這是推理參數,調它不用重訓。**

### 怎麼設(從 val 掃,不能猜)
- 在 **valid 集**對每一類掃描門檻:
  - **食安類**:在可接受 precision 下,**壓最低門檻拉高 recall**。
  - **一般類**:選**最大化 F1** 的門檻。
- ⚠ **樣本要夠**才調(每類至少數十個);bootstrap 每類只有 3–7 個會過擬合,**等真實資料再調**。

### 實作(低門檻拿全部 → 每類把關)
```python
PER_CLASS_THR = {'刀具':0.25,'食材':0.25,'砧板':0.3,'容器':0.5, ...}  # 從 val 掃出
det = model.predict(img, threshold=0.1)      # 先寬鬆拿全部候選
keep = [i for i,(c,s) in enumerate(zip(det.class_id, det.confidence))
        if s >= PER_CLASS_THR.get(NAMES[c], 0.3)]
```

> 提醒:門檻**微調操作點,不能取代補資料**。鍋子 recall 低是資料問題,門檻救不回。
