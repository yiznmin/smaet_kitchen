## 4. 執行網格(定死)

**67 段 × {stride 5, stride 1} = 134 次執行。** 每次一個獨立 process。

共用參數逐字同交付格 `m5_cbiou`:

```
--topology configs/fix_grid/base.yaml --tracker configs/tracker_rf_cbiou.yaml
--variant nano --thr 0.10 --person-cls 1 --embedder none --fps 30.0 --ttl 600
--max-frames -1 --det-cache results/det_cache/coco_nano/<seq>
```

只有 `--videos` / `--cameras` / `--stride` / `--start-fid` / `--end-fid` / `--out` 隨片段變。

- **不給 `--track-gt`**:片段執行的 track 編號與整段不同,`make_track_gt.py` 的對照表不適用;
  身份正確性一律由本輪的指標模組從 `tracks.csv` + 標註重算。
- 偵測**不重跑**:快取 `cache_stride=1`、`cache_thr=0.05`,`--thr 0.10` ≥ 0.05 → 任何幀可取。
- 輸出:`results/clips/runs/<clip_id>/s<stride>/`

### 4.1 次要對照(只對 L2,16 次)

`--ttl 600` 與 `lost_track_buffer: 30` 都以**迴圈**計數,所以 stride 1 時
TTL 由 100 秒縮成 20 秒、跟丟緩衝由 5 秒縮成 1 秒 —— 正好落在 L2 的間隔區間(1.1~4.9 秒)。

- **主網格:迴圈固定**(= 出貨設定,與 B 套同一組數字)。
- **次要對照:秒數對齊**(stride 1 用 `--ttl 3000` + `lost_track_buffer: 150`),只跑 L2 的 16 段。
- **兩組都要報**,不得只報其中一組。

## 5. 要量什麼(含分母,定死)

### 5.1 共同規則

- 取樣格:`fid ∈ {start_fid, start_fid + stride, …} ∩ [start_fid, end_fid]`。GT 幀 = `fid + 1`。
- 逐幀配對:同一(鏡頭, 取樣幀)上,系統框與標註框做**匈牙利配對**,保留 IoU ≥ **0.50** 的配對。
  配對前依 `gt_id` / `track_id` 升冪排序,使平手結果唯一。**空框(Kalman 預測、該幀沒配到偵測)
  不參與配對,另計 `n_coasting`**。
- 所有率一律由 `per_frame.csv` 算出,不另寫第二條計算路徑。
- **每個率都要附 N 與 Wilson 95% 區間**(L3 最短 3.0 秒 = stride 5 下只有 18 個取樣點)。
- 彙總一律**彙集逐幀列**再算一次(分母才對),另報逐片段中位數。

### 5.2 偵測 / 定位

| 指標 | 定義 | 分母 |
|---|---|---|
| `recall_target` | 目標被配對(IoU ≥ 0.5)的取樣格比例 | 目標**有標註框**的取樣格數 T |
| `visibility` | T / 全部取樣格 | 全部取樣格 |
| IoU 統計 | 平均 / 中位 / p10 / p90、≥0.5 比例、≥0.75 比例;未配對記 0 | T |
| `mean_iou_matched` | 只算有配對的格 | 有配對的格數 |

### 5.3 身份(三個率,分母皆為 B)

B = 目標**被配對且該 track 帶有 `chef_id`** 的取樣格數。另報 `bound_rate` = B / T。

| 指標 | 定義 |
|---|---|
| **連續率 `p_continuity`** | 以 B 的**第一格**的編號 `c0` 為準,之後每格是否仍是 `c0` |
| **多數率 `p_majority`** | 以 B 內佔比最高的編號 `c*` 為準(平手取較小編號並記錄) |
| **排他率 `p_exclusive`** | 同一取樣幀上,**沒有**另一個配到別的真人的框帶著同一個編號 |

⚠ **排他率是本輪唯一能否證「全部併成一個編號」的指標**:一段全部綁成同一個錯誤編號時,
連續率與多數率都會是 100%。
⚠ **獨佔片段(窗內只有目標一人)的排他率結構上不可量測** → 一律印
「**不可量測(窗內只有 1 個身份)**」,**不可印 100%**(與 B 套同一紀律)。

配套揭露(與三個率並列,不放在別的章節):`first_bound_fid`、
`n_chefs_created_before_target_bound`、`n_distinct_chef_ids_on_target`。

### 5.4 穩定度與誤偵

| 指標 | 定義 | 分母 |
|---|---|---|
| `chef_switches` | B 依 `(fid, camera)` 排序後,相鄰兩格編號改變的次數 | 次數(另報率:B − 1) |
| `track_switches` | 同上但看 `track_id`,**逐鏡頭**算(track 編號各鏡頭獨立) | 該鏡頭的 B − 1 |
| `ghost_box_rate` | 沒有配到任何真人的系統框比例 | **該片段畫出的系統框總數**(= 看影片時數得到的) |
| `ghost_track_rate` | 窗內配對率 < 0.5 的 track 比例 | 窗內 track 數 |
| `p_chef_stolen` | `c*` 同時被誤偵框帶著的格比例 | B |

⚠ `ghost_track_rate` 的判準只在**窗內**算,與 B 套的整段定義不同,不可直接比較。

### 5.5 Level 專屬

- **L2**:由 `appearances` 欄取出各段。相鄰兩段之間,
  `chef_before` = 前段最後 k 個有綁定格的多數編號,`chef_after` = 後段最前 k 個的多數編號,
  相同即算接回。**k = 5 為主、k = 1 併報**。
  `p_reacquire` 分母 = **兩側都至少有一個綁定格**的間隔對數(被排除的對數要報出來)。
  依間隔帶(≤5 秒 / >5 秒)分層。
- **L3**:依 `camera_order` 的鏡頭對,比較兩台上目標的多數編號是否相同。
  分母 = **兩台都有綁定**的鏡頭對數。
  **L3S(overlapping)與 L3T(sequential)永遠分開報,不得合併平均。**
  L3S 另報 `p_simul_agree`:目標同時在 ≥2 台上被綁定的取樣幀中,各台編號一致的比例。

### 5.6 對照用的既有指標

逐片段、逐鏡頭的單鏡頭 IDF1 / IDR / IDP / IDSW / MOTA,
用 `scripts/eval_m4_idf1.py` 的 `unit_inputs(..., fid_range=)` + `trackers.eval`。
它涵蓋窗內**全部**真人,是目標導向指標的互補面,也是 V7 的交叉核對對象。

## 7. 已知限制(報告照抄)

1. 數字**不可與 `results/levels/B*/` 並列**(§1)。
2. **L1 幾乎是常數**:連續率結構上接近 1.0、排他率不可量測 → L1 是 IoU / 召回 / 誤偵的健檢,
   不是身份鑑別力的證據。
3. **stride 1 的記憶只有 stride 5 的五分之一**(§4.1),差異表必須把這個混淆寫在表旁。
4. **片段的拓撲是子集**:2 台的片段看不到中間那台,原本 A→X→B 變成 A→B,落到「未建模路徑」
   (`logprior −2.0`)。manifest 記錄每段實際拿到多少連結與重疊對。
5. **樣本小**:L3 最短 18 個取樣點,一格 = 5.6%。
6. **片段之間會重疊**(同序列同鏡頭兩列、L3 窗包住 L1 窗)→ 彙總要報重複計入的格數。
7. **誤偵可能先搶走編號**:`thr 0.10` 偏低;誤偵若在目標出現前先拿到 `chef 1`,
   目標就會是 `chef 2` —— 指標行為正確,但必須與身份率並列揭露(§5.3)。
8. **影片是內部檢視版**:逐幀對錯與逐次綁定的誤併率分母不同,並列會被誤讀 →
   畫面強制標示「內部檢查用,不可交付」,且輸出到 `results/clips/videos/`,
   不進 `results/levels/videos/`。
