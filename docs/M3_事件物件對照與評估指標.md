# M3 — 事件↔物件對照 + 評估指標

> 兩個目的:
> (A) 從食安**事件**推出「要偵測什麼」,並分流到正確模組(M3 / zone / 分支 B)。
> (B) 定義**量化指標**,評估模型「有沒有有效偵測到」。
> 版本 v1(2026-07-07)。事件來源:多視角追蹤廚房監測事件清單。

---

## A. 事件 → 物件/區域 對照(三分法)

### A.1 三種東西走三條路(關鍵原則)

| 類型 | 例子 | 負責 | 做法 |
|---|---|---|---|
| **可動物件** | 刀、生肉、砧板、手套、人、容器 | **M3**(偵測) | 標註 + 微調訓練 |
| **固定位置** | 生食區、熟食區、洗手台、垃圾桶區、地板 | **Zone**(設定) | zone 工具框一次,不訓練 |
| **小/特殊目標** | 老鼠、水漬/殘渣 | **分支 B** | 背景相減 + 分類器 |

> 不要什麼都丟給 M3:固定的→zone、老鼠水漬→分支 B、只有**會動的物件**才進 M3。

### A.2 事件逐項對照

| 事件 | 可動物件(→M3) | 固定區域(→zone) | 其他 |
|---|---|---|---|
| 生肉進熟食區 | raw_meat、container | 生食區(A)、熟食區(B) | — |
| 器具未清潔跨用 | **knife、tongs**、raw_meat、cooked_food | (清潔區) | 需器具軌跡(M4) |
| 未換手套跨區操作 | person、**glove** | 生食區、熟食區 | 跨區身份(M5) |
| 取用食材前未洗手 | person、food | 洗手台、備料區 | 停留計時(M6) |
| 接觸垃圾桶後未洗手 | person | 垃圾桶區(C)、洗手台 | 接觸判斷(M6) |
| 生熟切換未洗手 | person、raw_meat、cooked_food | 洗手台 | 時序(M6) |
| 老鼠出沒 | — | (地板/全區) | **分支 B**(動態線) |
| 潑灑/殘渣掉落 | — | 地板 | **分支 B**(靜態線) |

### A.3 M3 類別清單(要標註 + 訓練)

```
person、knife(刀)、tongs(夾子)、cutting_board(砧板)、
raw_meat(生肉)、cooked_food(熟食)、container(容器/盆)、glove(手套)
```
共 ~8 類。**重點難點 = 小物件(knife、tongs)**,俯視遠距下需微調 + 高解析度。

### A.4 Zone 清單(zone 工具框一次)

```
生食區(zoneA)、熟食區(zoneB)、垃圾桶區(zoneC)、洗手台、備料區、地板
```

## B. 評估指標(模型「有沒有有效偵測」)

分**兩層**評估:**物件層(M3 本身)** 與 **事件層(端到端 M6)**。

### B.1 物件層(M3 偵測準不準)

在**標註好的測試集**上量:

| 指標 | 定義 | 為什麼看 |
|---|---|---|
| **mAP@50** | IoU≥0.5 的平均精度(所有類別平均) | 總體偵測水準 |
| **mAP@50:95** | COCO 式嚴格 mAP | 框準不準 |
| **各類別 AP** | 每類分開的 AP | **看小物件(刀/夾子)夠不夠** |
| **各類別 Precision** | 抓到的裡面對的比例 | 誤報多不多 |
| **各類別 Recall** ⭐ | 該抓到的裡面有抓到的比例 | **食安關鍵:有沒有漏** |

**量測方法**:用 `supervision` / COCO eval,拿微調模型在 test 集跑,對照 ground-truth 算上述值。

### B.2 事件層(端到端,系統真正有沒有用)

**最終指標**——把系統判出的事件,對照**人工檢視的正確答案**:

| 指標 | 定義 |
|---|---|
| **事件 Recall** ⭐ | 真實發生的事件中,系統抓到的比例(**漏報率的反面**) |
| **事件 Precision** | 系統報的事件中,真的是事件的比例(誤報率的反面) |
| **事件 F1** | Precision 與 Recall 的調和平均 |
| **各事件類型分別算** | 生熟污染 / 未洗手 / … 各自的 P/R | |

**量測方法**:準備一段有標註「事件真值」的影片,跑完整管線(M3→M4→M6),比對系統事件 vs 人工清單。

### B.3 食安系統的取捨:Recall 優先於 Precision

因為本案是**事後查詢**(不是即時警報),且**漏掉食安事件的代價 >> 誤報**:

```
寧可多報(人再去看) → 也不要漏(漏了就沒人知道)
→ 操作門檻調成「高 Recall」,容忍較低 Precision
```

- **報告 Precision-Recall 曲線**,選一個「Recall 夠高」的操作點。
- 關鍵物件(knife、raw_meat)**Recall 是主指標**。

### B.4 建議的目標值(暫定,微調後複核)

| 對象 | 指標 | 暫定門檻 |
|---|---|---|
| 大物件(person、冰箱) | AP@50 | ≥ 0.90 |
| **小物件(knife、tongs)** | **Recall@操作點** | **≥ 0.75**(不可漏) |
| 小物件 | AP@50 | ≥ 0.50(微調後) |
| 事件層(整體) | **事件 Recall** | **≥ 0.90** |
| 事件層 | 事件 Precision | ≥ 0.60(誤報可人工濾) |

> 目標值須在**目標主機 + 目標鏡頭 + 微調後**複核;現階段先訂方向。

### B.5 必做的對照:微調前 vs 後

每次微調都要出這張表,證明有效:

| 類別 | 微調前 AP@50 | 微調後 AP@50 | 提升 |
|---|---|---|---|
| knife | ~0.02(俯視遠距) | ? | ? |
| cutting_board | ? | ? | ? |
| raw_meat | ? | ? | ? |

**knife 從「幾乎 0」往上動 = 微調有效的最直接證據。**

## C. 落地順序

```
① 列事件 → 對照物件/zone(§A)
② 標 M3 可動物件 + 框 zone
③ 微調 RF-DETR → 出「各類別 AP + 微調前後對比」(§B.1, B.5)
④ 接 M4/M6 → 出「事件 P/R」(§B.2)
⑤ 依 Recall 優先選操作門檻(§B.3)→ 定案
```
