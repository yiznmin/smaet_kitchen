## 1. 為什麼做

### 1.1 起點

`docs/M5_綁定規則實測_20260915.md` 查明:**M5 決定「綁給誰」的分數不含任何「這是誰」的資訊。**
所有成功綁定都來自重疊路徑的常數 `3.806 − ln k`,它不能拒絕(k ≤ 8 必綁),也不能區分候選(只看鏡頭上掛了幾個身份)。

要讓 M5 依「是誰」做選擇,必須在重疊路徑上換成**能區分身份、而且能拒絕**的證據。現有的證據來源只有兩種:

| 證據 | 現況 | 能否作為本輪對象 |
|---|---|---|
| **外觀** | CHIRLA 跨鏡頭實測 d′:可出貨的 `chirla_armS` **0.118**、`chirla_armS0` 0.131、研究限定的 `chirla_armR` 0.421;DINOv2(EPFL)0.25。同人典型加分 = d′²/2 ≤ **+0.09 nats**,門檻 1.609(`docs/CHIRLA_預先登記_20260901.md` §9.5) | **否** —— 已量過,量級差了 18 倍以上 |
| **地面位置(單應性)** | 9/12 的 F4 失敗(重疊路徑正確率 16.49% → 6.07%),但失敗原因 **(a) 單應性不準**與 **(b) 位置本身分不開人** **沒有分開**(`docs/M5_修復F4_預先登記_20260905.md` §8.5)。為了分開而寫的 `scripts/chirla_position_discriminability.py` **從未執行**(`results/` 下沒有輸出) | **是** —— 唯一還沒被量清楚的候選 |

### 1.2 本輪要回答

> **在 M5 重疊路徑實際遇到的決策上,地面位置能不能選對人、並拒絕不是他的人?**

- 若**能** → 重疊路徑有可用證據,下一輪預先登記 F4 重做(只在通過的鏡頭對啟用)
- 若**不能,而且用真值框也不能** → (b) 成立,**現有兩種證據都不足以區分身份**,要回報使用者討論新的證據來源,而不是再調參數

### 1.3 查證時發現、與本輪有關的事實(程式碼查證)

9/12 擬合出 6 對單應性,但重疊路徑只查「與本鏡頭在 `overlapping` 清單上的鏡頭」(`src/m5_reid/identity_st.py` 第 179、191–192 行):

| 鏡頭對 | 有單應性 | 在 `overlapping` 清單 | 9/12 的 F4 實際有沒有用到 |
|---|---|---|---|
| camera_2 + camera_3 | 是(σ 16.9) | 是 | 有 |
| camera_2 + camera_5 | 是(σ 74.7) | 是 | 有 |
| camera_4 + camera_5 | 是(σ 37.1) | 是 | 有 |
| camera_1 + camera_3 | 是(σ 8.4) | **否** | **沒有** |
| camera_6 + camera_7 | 是(σ 8.7) | **否** | **沒有** |
| camera_1 + camera_2 | 是(σ 8.0) | **否** | **沒有** |
| camera_2 + 4、3 + 4、3 + 5、5 + 6 | 否 | 是 | 退回常數 |

**σ 最小的三對在 9/12 從未被使用**;有被使用的三對裡兩對 σ 大到同一個人都推不過門檻。
所以 9/12 的失敗**不能**當成「幾何這條路不行」的證據。本輪逐對量,包含這三對。

## 3. 量測(定死)

門檻一律 **`log 5 = 1.609`**(`cost_false_merge_over_break` 5.0,與 M5 相同)。

### 3.1 量測 G —— 真值框、真值身份(上限)

`chirla_position_discriminability.py` 原樣執行,推導集與評估集各一次。
對每一幀、每一對有單應性的鏡頭 A→B、A 上至少 2 人,對每個同時出現在 A 與 B 的真人 i:

- `決策餘裕 = LLR(i 自己的殘差) − max_j LLR(別人 j 的殘差)`
- **G 通過率** = 決策餘裕 ≥ 1.609 的比例(逐對、合計)

它回答 (b):**就算框完美、單應性照目前的品質,位置能不能把 i 和同鏡頭的別人分開。**
⚠ 只用「拍得清楚」的框(寬 ≥ 50、高 ≥ 120),與擬合時相同。

### 3.2 量測 R —— 實際 M4 框、實際 M5 決策時刻(現實)

資料:`results/m5_step3/m5_cbiou`(目前最好的 M4 設定)。

**決策集合**:`chef_events.jsonl` 中所有 `gt_id` 不為空的新 track 決策(真人決策),在 B 鏡頭、第 L 輪。

對每個決策:

1. 從同序列 `tracks.csv` 取**同一輪 L**、所有**與 B 有單應性**的鏡頭 A 上的 track(不論是否在 `overlapping` 清單)
2. 每條 track 經 `track_gt/<seq>.json` 對應到真人;對應不到的是誤偵,**當成獨立的競爭者**
3. 每條 track 算 `LLR_j = CrossViewLR(A→B).llr(框_j, 新 track 的框)`;同一真人有多條時取最大
4. 正確答案 = 新 track 的 `gt_id`

依「正確的人此刻有沒有出現在某台 A 上」分兩類:

| 類別 | 量什麼 |
|---|---|
| **可評估**:正確的人在某台 A 上 | **R1 選對率**:正確的人 LLR 嚴格最高<br>**R2 可正確綁定率**:選對 **且** LLR ≥ 1.609<br>**R3 餘裕通過率**:正確的人 LLR − 最高的別人 ≥ 1.609(與 G 同定義)<br>對照:隨機挑一個的期望選對率 = 平均 1/(競爭者數) |
| **應拒絕**:正確的人不在任何 A 上,但 A 上有別人 | **R4 誤接受率**:至少一個別人 LLR ≥ 1.609 |

逐對報告(以「提供最高 LLR 的那台 A」歸屬到鏡頭對),另報合計,以及 σ < 20 px 的鏡頭對合計。

**成本換算**(用來判定,不是另一個參數):M5 的成本比是誤併 5 : 碎裂 1。相對於「一律開新身份」:
一次正確綁定省下 1、一次誤接受多付 4 → **打平條件:正確綁定次數 ≥ 4 × 誤接受次數**。

## 6. 已知限制(報告要照抄,放在結論之前)

1. **量的是證據的鑑別力,不是系統表現。** R 以真人為單位、假設「此刻每台鏡頭上誰是誰」已知,**不經過 M5 的身份簿記**。
   即使「幾何可用」,M5 實跑還會受誤偵開出的身份、身份碎裂、track 對應錯誤影響,要下一輪才知道
2. **評估集只用於量測,不得從中挑任何參數**;H、σ、面積全部來自推導集
3. **`overlapping` 清單有資訊洩漏**(來自全部 10 個序列,9/3 已揭露);本輪 R 不依賴該清單
4. **同一輪 = 同一時刻**的前提:七支影片起始時間戳相同、幀數差 10 幀內(`clock.max_skew_s` 0.2 秒)
5. **反向單應性的 σ 與面積沿用正向**(`spatiotemporal.py` 第 300–303 行的既有做法)
6. **真值來自 IoU 配對 + 多數決**,一條在兩人之間跳的 track 只會拿到一個身份
7. G 只用拍得清楚的框;R 用 M4 所有框(M5 實際看到的就是這些),兩者樣本不同
8. 只量 `m5_cbiou` 一格;**CHIRLA 是辦公室不是廚房**
