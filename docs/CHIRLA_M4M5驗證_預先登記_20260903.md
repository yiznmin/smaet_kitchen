## 1. 為什麼做這件事

整套系統的驗收門檻是 **「誤併率 ≤ 1%」**
(`docs/M4_M5_階段驗證報告_20260828.md`)。但截至今天:

> **我們從來沒有在真實影片上量過一次誤併率。七輪的數字全部來自模擬。**

原因是結構性的 —— 手上唯一的真實多鏡頭影片 EPFL **全片只有一個人**,
「把兩個人併成一個」不可能發生,分母是零。

2026-09-03 的九鏡頭全長跑讓這件事變得更迫切。表面成績是
「chef_id 總數 1、碎裂 0 次、碎裂率 0.0%」,但拆開來:

| 執行 | 綁定次數 | 其中把**靜止物件**(牆上的袋子、鍋具反光、木鏟)綁進廚師身份 |
|---|---|---|
| 三台(9/1 已寫進報告) | 18 | 4 次 = **22%** |
| 九台(9/3) | 93 | 38 次 = **41%** |

**「碎裂 0 次」成立,但它的意思是「系統把畫面裡的東西全綁給同一個人」。**
在單人資料上,滿分答案與「把袋子當成廚師」的答案**分不開**。

CHIRLA 有 **963,554 個逐幀身份標註框**、21 個身份、7 台相機、**CC-BY-4.0 可商用**。
它讓上面每一項都變成可量測的。

### ⚠ 本輪與 9/1 那輪的關係

9/1 的預先登記結論是「在官方 `_train` 切分上**訓練**,產不出可出貨的外觀模型」。
**本輪不訓練任何東西**,用的是 `annotations/`(逐幀標註)與 `videos/`,
與那個結論不衝突,也**不違反該文件 §2**(§2 管的是訓練切分)。

## 4. 評估協定

### 4.1 預測 track 對 ground-truth 身份的配對

- 逐幀、逐相機,用 **IoU ≥ 0.5** 的匈牙利配對(標準 MOT 協定)
- 一條 track 的 GT 身份 = 其生命期內配對次數最多的 GT id;
  **若配對率 < 50%,該 track 標記為 `無 GT`(誤偵)**
- distractor 的負號 id 取絕對值(`-1` 與 `1` 是同一個人)

### 4.2 指標定義(先寫死,沿用 `src/m5_reid/metrics.py` 以便與七輪對照)

| 指標 | 定義 |
|---|---|
| **誤併率** | 綁定決策中,track 的 GT 身份 ≠ 該 chef 已建立之 GT 身份的比例。**分母不含初始化那一次** |
| **碎裂率** | 同一 GT 身份被拆到 ≥2 個 chef_id;分母同上 |
| **誤偵綁定率** | 綁定到 `無 GT` track 的比例 ← **9/3 在 EPFL 上量到 22~41%,本輪第一次有真值可判** |
| IDF1 | 標準定義,供與文獻對照 |
| M4 漏偵/幽靈 | 以 GT 框為準,不再用「全片單人」的代理判準 |

### 4.3 這輪要一併產出的一個數字

**實測跨鏡頭轉場間隔的分布。** 驗收門檻 ≤1% 是照「每 2~5 分鐘跨一次」推導的,
而那個假設 **沒有引用、沒有量測、沒有推導**
(`docs/M4_M5_階段驗證報告_20260828.md:378`),程式裡還有三個互相矛盾的數字。
本輪第一次能給它一個真實來源。⚠ 只從**推導集**估,評估集的實測值另外報告作為對照。

### 5.1 ⚠ 偵測器這一臂有領域混淆,先寫清楚

我們微調的 11 類模型是在**廚房**場景上訓練的,而 **CHIRLA 是辦公室/實驗室**。
所以 `FT` 在這裡是**領域外**。

> **若 `COCO` 贏 `FT`,不得解讀成「微調沒用」** —— 那只說明微調的模型
> 在領域外不佔優勢,與它在廚房部署時的表現無關。
> 這條先寫死,防的是事後拿這個結果去否定 M3 的成果。

### 5.2 算力與縮減規則(先寫死,防止事後挑序列)

先跑 **smoke test**(1 個序列 × 7 台 × 200 迴圈)量實際 ms/迴圈與 RSS,再決定。
若四格的總時數超過 **12 小時**,依**固定順序**從評估集尾端移除序列:

**不得依「哪個序列結果比較好看」挑選。** 實際跑了哪幾個序列必須寫進執行紀錄。

## 6. 判準(先寫死)

**參照點:規格書的驗收門檻 —— 誤併率 ≤ 1%、碎裂率 ≤ 5%。**

| 級別 | 條件 | 結論 |
|---|---|---|
| **A** | 誤併 ≤ 1% **且** 碎裂 ≤ 5% | 在真實多人影片上達標,可進入業主驗收 |
| **B** | 誤併 1~5% | 未達標但同量級,差距來源要逐項歸因 |
| **C** | 誤併 > 5% | **架構層問題**,不是調參可解 |

**次判準(誤偵)**:誤偵綁定率 **> 10%** 時,判定
「M5 的入口缺少『這個框是不是人』的把關」,處置是**做靜止/非人過濾**,
而不是調 LLR 門檻。

### ⚠ 本輪特有的失敗條件

若**任一格**的誤併率 **> 30%**,判定為 **`overlap_llr` 的結構性缺陷**:
重疊路徑對任何「同時出現」的 track 一律給 +5.0 nats(門檻 1.609),
**不看那個框像不像人、也不看它動不動**。

處置寫死:**改為對重疊證據加上幾何一致性條件**(同一時刻兩台看到的應是
可對應的位置),而**不是**把 `overlap_llr` 調小 —— 調小會同時傷害正確的綁定。

## 8. 已知限制(報告要照抄這段,放在結論之前)

1. **CHIRLA 是辦公室/實驗室,不是廚房。** 人數、走動模式、遮擋結構都不同。
   本輪量到的誤併率是**該場域**的,不能直接當廚房的預測值。
2. **沒有相機標定參數。** 所以 `GroundPlaneLR`(地面校正)在本輪**依然不生效** ——
   與 EPFL 同樣的限制。這表示重疊路徑上少了一條強證據,結果偏保守。
3. **重疊拓撲有資訊洩漏**(已在全部 10 序列上量過),參數沒有。見 §3。
4. **本輪不訓練任何模型。** 外觀用的是既有的 DINOv2,不是 CHIRLA 訓出來的。
5. **CHIRLA 的授權**(HF 卡片)禁止「未經明確同意、針對真實人物的監控/識別/追蹤部署」。
   **本輪是離線驗證,不是部署**,符合;但不得把 CHIRLA 影像放進出貨產品或對外簡報的示範畫面。
6. **GT 配對門檻 IoU 0.5 是慣例不是實驗結果。** 換門檻會改變誤偵的判定邊界,
   原始配對結果要存檔以便重算。
7. **`videos/` 是 8.95 GB、70 支影片,本輪可能只跑得完一部分**(見 §5.2 的縮減規則)。

### 10.2 附帶量到的三件事

**(a) M4 的多目標追蹤也可測**

| 同一相機同一幀的身份數 | 幀數 | 占比 |
|---|---|---|
| 1 | 116,403 | 32.3% |
| 2 | 87,495 | 24.3% |
| 3 | 67,523 | 18.7% |
| 4 | 29,999 | 8.3% |
| 5 | 33,556 | 9.3% |
| 6~9 | 25,465 | 7.1% |
| **≥2** | **244,038 / 360,441** | **67.7%** |

單台畫面最多同時 9 個身份。EPFL 全片單人時,M4 的漏偵/幽靈只能用
「每幀 active track 數應為 1」這個代理判準;本輪第一次有逐幀 GT 框可比。

**(b) 全場同時在場的身份數**

中位 6~7 人,最多 13 人。分布:1 人只有 1 個時刻(0.0%)、
5~8 人合計佔 66.8%、10 人以上佔 18.6%。

**(c) 每一次轉場都有可混淆的對象**

```
轉場當下同時在場的**其他**身份數:中位 7 / 最多 12
「全場只有這一個人」的轉場:0 / 606 = 0.0%
```

**沒有任何一次轉場是「沒有別人可以併錯」的。** 這是 EPFL 結構上做不到的條件。

### 10.3 §4.3 要的那個數字:實測跨鏡頭轉場間隔

⚠ **這裡先報全資料集的值,§4.3 要求的「只從推導集估」在 B1 建拓撲時另外算。**

```
跨相機轉場(間隔 ≤ 60s):606 次
  間隔中位 1.5s / p90 10.2s
```

對照驗收假設「每 2~5 分鐘跨一次」(120~300s)—— 那個假設**沒有引用、沒有量測、
沒有推導**(`docs/M4_M5_階段驗證報告_20260828.md:378`),而整套「誤併率 ≤1%」的
門檻建立在它上面。方向與 `docs/M5_模擬預先登記_幾何世界_20260901.md` §11.3
記的「轉場頻率比驗收假設高 26~65 倍」一致。

⚠ **但不要直接拿 1.5s 去取代那個假設。** 兩者量的東西不完全一樣
(這裡是「離開 A 到出現在 B 的間隔」,驗收假設講的是「多久跨一次」),
而且 CHIRLA 是辦公室不是廚房。要當正式數字用,需要照 §4.3 從推導集重算並定義清楚。

| 參數一致性自檢 | **[OK]** 所有執行的非網格參數與 `coco_none/seq_004` 逐字相同 |

⚠ **拓撲上的一個決定要先揭露**:`unknown_path` 設為 `enabled: true`,而 EPFL 那兩輪是 `false`。
理由是 camera_1 不在任何重疊對裡、推導集裡與它相關的轉場只有 4 次且全是單次(低於門檻),
沒有 unknown_path 的話它兩條路徑都走不到、進出必定開新 chef_id ——
量到的碎裂率會是「推導集只有 539 秒」的假象。這個決定**統一套用到所有沒有 link 的配對**,
而且是在看到任何評估集結果**之前**做成的。

### 11.3 兩條路徑用完全相反的方式壞掉 —— 本輪最重要的發現

| 格 | 路徑 | 決策數 | 碎裂率 | 誤併率 |
|---|---|---|---|---|
| `coco_none` | 重疊 | 922 | 2.71% | **80.80%** |
| | 轉場 | 814 | **54.42%** | 44.72% |
| `coco_dino` | 重疊 | 922 | 0.22% | **84.71%** |
| | 轉場 | 814 | **49.63%** | 49.75% |
| `ft_none` | 重疊 | 942 | 0.11% | **81.74%** |
| | 轉場 | 604 | **46.85%** | 51.32% |
| `ft_dino` | 重疊 | 942 | 0.11% | **84.29%** |
| | 轉場 | 604 | **46.85%** | 52.32% |

**重疊路徑幾乎不碎裂但誤併超過八成;轉場路徑幾乎不誤併但碎裂近半。**

機制與 §6 先寫死的失敗條件描述完全一致:

- **重疊路徑**:`overlap_llr` 對任何「同時出現」的 track 一律給 **+5.0 nats**(門檻 1.609),
  **不看那個框像不像人、也不看它在哪裡**。CHIRLA 同一時刻中位有 6~7 個人在場 →
  全部被併成一個。
- **轉場路徑**:CHIRLA 沒有相機標定參數 → `GroundPlaneLR` 與 `VelocityLR` **都不生效**
  (§8 第 2 條)。那條路徑上只剩轉場時間 + 外觀 → 拒絕掉近半的真配對。

⚠ 這正是 `docs/M5_模擬預先登記_幾何世界_20260901.md` §9.3 記的架構缺口
(地面校正與軌跡只在重疊路徑生效),**第一次在真實資料上顯形**。

### 11.5 §7 五條預測的逐條交代

| # | 預測 | 結果 |
|---|---|---|
| **1** | 誤併率 > 5%(C 級) | **成立**。四格 58.84~67.23%,全部 C 級 |
| **2** | 轉場碎裂率 ≥ 重疊的 2 倍 | **成立,而且極端得多**。比值 20.1 / 225.6 / 425.9 / 425.9 |
| **3** | 候選數 ≥2 的綁定佔比 > 20% | **成立**。95.4~97.3%(對照 EPFL 九台是 **0.0%**,分布 `{0:1, 1:92}`) |
| **4** | 外觀首次產生**超出雜訊帶**的可測差異 | **部分成立,但方向與期待相反**。COCO 臂 none→dino 誤併 **+5.32pp(變差)**、碎裂 −3.90pp;FT 臂只有 +1.35pp / 0.00pp。⚠ 「雜訊帶 2.4pp」來自蒙地卡羅換種子,套到真實資料是外推,**不是本輪量到的** |
| **5** | FT 不會明顯優於 COCO(差距 < 2pp) | **否證**。誤偵綁定率 32.55% → **11.66%**,差 **20.89pp**。但同時漏偵大幅惡化,是換來的不是白得的 |

**預測 3 是本輪唯一的好消息**:外觀終於有了舞台(97% 的決策有 ≥2 個候選,EPFL 是 0%)。
**但預測 4 顯示它上台之後把事情弄得更糟** —— DINOv2 的 d′ 只有 0.25,
在 6~7 個候選之間破平手時,它提供的是雜訊而不是證據。

⚠ 預測 5 被否證的方式值得記:§5.1 先寫死「若 COCO 贏 FT,不得解讀成微調沒用」。
實際是 **FT 在誤偵上大勝**,所以那條防呆這次沒用上;但反過來要小心的是
**不得把「FT 誤偵少」直接當成微調有效** —— 漏偵從 7~27% 跳到 31~71%,
這在廚房(領域內)會不會同樣發生,本輪答不出來。

### 11.6 §6 判準與處置

| 判準 | 結果 |
|---|---|
| A 級(誤併 ≤1% 且碎裂 ≤5%) | 否 |
| B 級(誤併 1~5%) | 否 |
| **C 級(誤併 > 5%)** | **是,四格皆是** → **架構層問題,不是調參可解** |
| **失敗條件(誤併 > 30%)** | **觸發,四格皆是**(58.84~67.23%) |
| 次判準(誤偵綁定率 > 10%) | **觸發,四格皆是**(11.66~32.55%) |

**§6 先寫死的兩個處置,照辦:**

1. **對重疊證據加上幾何一致性條件**(同一時刻兩台看到的應是可對應的位置),
   **不是**把 `overlap_llr` 調小 —— 調小會同時傷害正確的綁定。
2. **做靜止/非人過濾**,**不是**調 LLR 門檻。

### 11.7 一個過程中的錯誤,照實記錄

第一版的 `eval_m4m5_chirla.py` 印出「整體碎裂率 31.33%,但重疊與轉場兩條路徑都是 0.00%」。
**自相矛盾 → 先懷疑指標**(repo 工作文化第 5 條),查出來是路徑歸屬用錯了 key:
用「這個 chef_id 上次出現在哪台相機」判斷,但綁不上時會開一個**全新的** chef_id,
新 id 沒有上一台相機 → 整筆被跳過,於是碎裂事件系統性地從路徑統計裡消失。
改用「這個**真實身份**上次出現在哪台相機」後才自洽。

另一個:seq_006 的 camera_4 全程沒有人、標註是 `{}`,第一版誤判成「沒有 GT」而中止。
但那台相機上偵測到的東西**依定義就是幽靈**,正是要量的目標。
