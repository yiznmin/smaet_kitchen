## 1. 為什麼做這件事

整套系統的驗收門檻是 **「誤併率 ≤ 1%」**
(`docs/M4_M5_階段驗證報告_20260828.md`)。但截至今天:

> **我們從來沒有在真實影片上量過一次誤併率。七輪的數字全部來自模擬。**

原因是結構性的 —— 手上唯一的真實多鏡頭影片 EPFL **全片只有一個人**,
「把兩個人併成一個」不可能發生,分母是零。

2026-09-03 的九鏡頭全長跑讓這件事變得更迫切。表面成績是
「chef_id 總數 1、碎裂 0 次、碎裂率 0.0%」,但拆開來:

| 執行 | 綁定次數 | 其中把**靜止物件**(牆上的袋子、鍋具反光、木鏟)綁進廚師身份 |
|---|---|---|
| 三台(9/1 已寫進報告) | 18 | 4 次 = **22%** |
| 九台(9/3) | 93 | 38 次 = **41%** |

**「碎裂 0 次」成立,但它的意思是「系統把畫面裡的東西全綁給同一個人」。**
在單人資料上,滿分答案與「把袋子當成廚師」的答案**分不開**。

CHIRLA 有 **963,554 個逐幀身份標註框**、21 個身份、7 台相機、**CC-BY-4.0 可商用**。
它讓上面每一項都變成可量測的。

### ⚠ 本輪與 9/1 那輪的關係

9/1 的預先登記結論是「在官方 `_train` 切分上**訓練**,產不出可出貨的外觀模型」。
**本輪不訓練任何東西**,用的是 `annotations/`(逐幀標註)與 `videos/`,
與那個結論不衝突,也**不違反該文件 §2**(§2 管的是訓練切分)。

## 2. 前置條件(不成立就不跑,並照實報告)

⚠ **「資料集有 21 個身份」不等於「同一時刻有多個人在場」。**
若 CHIRLA 也是一次只拍一個人走動,誤併照樣量不到 —— 與 EPFL 同一個下場。

先跑 `scripts/chirla_concurrency_stats.py`,**三個門檻全部通過才進行本輪**:

| # | 門檻 | 不通過的處置 |
|---|---|---|
| P1 | 同一時刻跨相機 ≥2 個身份的幀 **≥ 10%** | **中止誤併部分**,只做 M4 偵測/追蹤驗證,報告明寫誤併仍不可量測 |
| P2 | 跨相機轉場 **≥ 100 次** | 中止轉場路徑部分 |
| P3 | 5 對真正非重疊相機上的轉場 **≥ 30 次** | 轉場路徑仍零覆蓋,報告照實寫 |

**這三個門檻先寫死,不得在看到數字後調整。**

## 3. 資料與切分(定死,不得更動)

CHIRLA benchmark 的 10 個序列,依序列編號排序後**固定**切成兩份:

| 用途 | 序列 |
|---|---|
| **拓撲推導集**(可以看,用來估參數) | `seq_000`, `seq_001`, `seq_002` |
| **評估集**(產生所有對外數字) | `seq_004`, `seq_006`, `seq_007`, `seq_020`, `seq_024`, `seq_025`, `seq_026` |

### ⚠ 為什麼要切這一刀 —— 這是本輪最重要的設計

`docs/M4_M5_實片全長評估_20260901.md` 的消融(A vs B)證明:

> 拿掉拓撲資訊,系統從「1 個 chef_id」變成「9 個」,完全綁不起來。
> **能力來自知道鏡頭怎麼擺,不是來自演算法。**

所以如果我們拿**評估集自己的統計**去建拓撲,等於把答案餵給系統,
量到的數字沒有意義。**拓撲的每一個參數只能從推導集估。**

### 已經發生的資訊洩漏,照實揭露

`scripts/chirla_overlap_stats.py` 已在 **全部 10 個序列**上跑過(2026-09-03),
所以「哪幾對相機重疊」這件事我們已經看過評估集了。處置:

- **重疊關係**視為**物理事實**(相機是固定的,10 個序列間機位沒動過),沿用全域結果並註明洩漏;
- **轉場時間分布、`background_arrival_hz`、`p_loiter`/`tau_loiter_s`** 這些**參數**
  一律**只從推導集估**,不得回頭用評估集校準。
- ⚠ 報告必須寫明:重疊拓撲有洩漏,參數沒有。

## 4. 評估協定

### 4.1 預測 track 對 ground-truth 身份的配對

- 逐幀、逐相機,用 **IoU ≥ 0.5** 的匈牙利配對(標準 MOT 協定)
- 一條 track 的 GT 身份 = 其生命期內配對次數最多的 GT id;
  **若配對率 < 50%,該 track 標記為 `無 GT`(誤偵)**
- distractor 的負號 id 取絕對值(`-1` 與 `1` 是同一個人)

### 4.2 指標定義(先寫死,沿用 `src/m5_reid/metrics.py` 以便與七輪對照)

| 指標 | 定義 |
|---|---|
| **誤併率** | 綁定決策中,track 的 GT 身份 ≠ 該 chef 已建立之 GT 身份的比例。**分母不含初始化那一次** |
| **碎裂率** | 同一 GT 身份被拆到 ≥2 個 chef_id;分母同上 |
| **誤偵綁定率** | 綁定到 `無 GT` track 的比例 ← **9/3 在 EPFL 上量到 22~41%,本輪第一次有真值可判** |
| IDF1 | 標準定義,供與文獻對照 |
| M4 漏偵/幽靈 | 以 GT 框為準,不再用「全片單人」的代理判準 |

### 4.3 這輪要一併產出的一個數字

**實測跨鏡頭轉場間隔的分布。** 驗收門檻 ≤1% 是照「每 2~5 分鐘跨一次」推導的,
而那個假設 **沒有引用、沒有量測、沒有推導**
(`docs/M4_M5_階段驗證報告_20260828.md:378`),程式裡還有三個互相矛盾的數字。
本輪第一次能給它一個真實來源。⚠ 只從**推導集**估,評估集的實測值另外報告作為對照。

## 5. 受控網格(除標示的因素外,所有設定逐字相同)

**2 × 2 = 4 格**,全部在評估集上跑:

| 因素 | 值 | 問的問題 |
|---|---|---|
| **偵測器** | `COCO`(RF-DETR nano 預訓,person_cls=1) / `FT`(我們微調的 11 類,person_cls=0) | 微調有沒有壓下 9/3 發現的靜止物件誤偵 |
| **外觀** | `none` / `dinov2` | **外觀第一次有機會發言**(EPFL 候選分布是 `{0:1, 1:92}`,從沒競爭過) |

⚠ **`chirla_armS` 不納入本輪。** 9/1 已測得它的跨相機 d′ = 0.118,
低於 dinov2 的 0.250,且系統層差距落在雜訊帶內。納入只會多燒四格算力。

### 5.1 ⚠ 偵測器這一臂有領域混淆,先寫清楚

我們微調的 11 類模型是在**廚房**場景上訓練的,而 **CHIRLA 是辦公室/實驗室**。
所以 `FT` 在這裡是**領域外**。

> **若 `COCO` 贏 `FT`,不得解讀成「微調沒用」** —— 那只說明微調的模型
> 在領域外不佔優勢,與它在廚房部署時的表現無關。
> 這條先寫死,防的是事後拿這個結果去否定 M3 的成果。

### 5.2 算力與縮減規則(先寫死,防止事後挑序列)

先跑 **smoke test**(1 個序列 × 7 台 × 200 迴圈)量實際 ms/迴圈與 RSS,再決定。
若四格的總時數超過 **12 小時**,依**固定順序**從評估集尾端移除序列:

```
移除順序:seq_026 → seq_025 → seq_024 → seq_020 → seq_007 → seq_006
```

**不得依「哪個序列結果比較好看」挑選。** 實際跑了哪幾個序列必須寫進執行紀錄。

## 6. 判準(先寫死)

**參照點:規格書的驗收門檻 —— 誤併率 ≤ 1%、碎裂率 ≤ 5%。**

| 級別 | 條件 | 結論 |
|---|---|---|
| **A** | 誤併 ≤ 1% **且** 碎裂 ≤ 5% | 在真實多人影片上達標,可進入業主驗收 |
| **B** | 誤併 1~5% | 未達標但同量級,差距來源要逐項歸因 |
| **C** | 誤併 > 5% | **架構層問題**,不是調參可解 |

**次判準(誤偵)**:誤偵綁定率 **> 10%** 時,判定
「M5 的入口缺少『這個框是不是人』的把關」,處置是**做靜止/非人過濾**,
而不是調 LLR 門檻。

### ⚠ 本輪特有的失敗條件

若**任一格**的誤併率 **> 30%**,判定為 **`overlap_llr` 的結構性缺陷**:
重疊路徑對任何「同時出現」的 track 一律給 +5.0 nats(門檻 1.609),
**不看那個框像不像人、也不看它動不動**。

處置寫死:**改為對重疊證據加上幾何一致性條件**(同一時刻兩台看到的應是
可對應的位置),而**不是**把 `overlap_llr` 調小 —— 調小會同時傷害正確的綁定。

## 7. 事先寫下的預測(可被否證)

| # | 預測 | 若被否證代表什麼 |
|---|---|---|
| **1** | **誤併率 > 5%(C 級)**。依據:9/3 在 EPFL 上,41% 的綁定綁到靜止物件,而那還是**沒有其他人可以併錯**的情況 | 系統比模擬預期的強,要回頭查模擬為何悲觀 |
| **2** | **轉場路徑的碎裂率 ≥ 重疊路徑的 2 倍**。依據:`docs/M5_外觀價值_20260903.md` 量到無全景鏡頭 16.6% vs 有 6.4% | 「地面校正與軌跡在轉場路徑上完全沒有」這個架構缺口的影響比預期小 |
| **3** | **候選數 ≥2 的綁定佔比 > 20%**(EPFL 是 0%) | CHIRLA 的人也很少同時競爭,外觀依然無舞台 |
| **4** | **外觀首次產生可測差異**:`dinov2` 與 `none` 的誤併率差距**超出雜訊帶**(依 9/3 的經驗,雜訊帶約 2.4pp) | 「外觀幾乎沒有影響」在多人真實資料上依然成立 |
| **5** | **`FT` 不會明顯優於 `COCO`**(差距 < 2pp),因為 CHIRLA 對它是領域外 | 若 `FT` 大勝,表示微調學到的是通用的人形先驗而不只是廚房 |

⚠ 預測 1 與預測 4 有張力:**若誤併率高到 C 級,外觀多半救不了**。
兩者同時成立的意思是「外觀有可測的效果,但不足以達標」—— 那正是
`docs/M5_外觀價值_20260903.md` 的既有結論(2~6pp 買不到 1% 門檻)。

## 8. 已知限制(報告要照抄這段,放在結論之前)

1. **CHIRLA 是辦公室/實驗室,不是廚房。** 人數、走動模式、遮擋結構都不同。
   本輪量到的誤併率是**該場域**的,不能直接當廚房的預測值。
2. **沒有相機標定參數。** 所以 `GroundPlaneLR`(地面校正)在本輪**依然不生效** ——
   與 EPFL 同樣的限制。這表示重疊路徑上少了一條強證據,結果偏保守。
3. **重疊拓撲有資訊洩漏**(已在全部 10 序列上量過),參數沒有。見 §3。
4. **本輪不訓練任何模型。** 外觀用的是既有的 DINOv2,不是 CHIRLA 訓出來的。
5. **CHIRLA 的授權**(HF 卡片)禁止「未經明確同意、針對真實人物的監控/識別/追蹤部署」。
   **本輪是離線驗證,不是部署**,符合;但不得把 CHIRLA 影像放進出貨產品或對外簡報的示範畫面。
6. **GT 配對門檻 IoU 0.5 是慣例不是實驗結果。** 換門檻會改變誤偵的判定邊界,
   原始配對結果要存檔以便重算。
7. **`videos/` 是 8.95 GB、70 支影片,本輪可能只跑得完一部分**(見 §5.2 的縮減規則)。
