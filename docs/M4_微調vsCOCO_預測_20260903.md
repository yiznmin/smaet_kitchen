# 跑之前先寫下預測:微調的 11 類模型能不能壓下靜止物件誤偵(2026-09-03)

> **本文件在全長跑完成之前寫下並提交 git。跑完只追加「結果」。**
> 執行:`results/m5_full9ft/` vs 既有的 `results/m5_full9/`

---

## 1. 要回答的問題

9/3 的九鏡頭全長跑(COCO 預訓 RF-DETR nano)發現:

- 幽靈框的 IoU 中位 **0.00** —— 不是同一個人被拆兩框,是別的位置有東西被當成人
- 看畫面確認全是**靜止物件**:牆上掛的袋子、水槽的金屬鍋具反光、砧板旁的木鏟
- **93 次綁定裡 38 次(41%)把靜止物件綁進廚師身份**

**問題:換成我們自己微調的 11 類廚房模型,這個情況會改善嗎?**

唯一的變因是 `--weights`(以及隨之自動切換的 `person_cls` 1 → 0),
拓撲、stride、TTL、閾值全部逐字相同。

---

## 2. 事先寫下的預測(可被否證)

| # | 預測 | 依據 |
|---|---|---|
| **1** | **微調的幽靈率不會明顯低於 COCO(差距 < 2pp)** | 微調的 11 類是**廚房物件**類別,訓練時「人」以外的類別是鍋碗瓢盆,**沒有教它「掛著的袋子不是人」**。誤偵的成因是背景物件像人形,不是領域不匹配 |
| **2** | **cam8 會變差** | smoke(25 迴圈)已看到 cam8 從 25 → 51 筆偵測,翻倍。若全長成立,表示微調在該視角**更容易**把鍋具當人 |
| **3** | 漏偵率兩者都 < 1% | COCO 已是 0.0~0.4%,人形偵測不是瓶頸 |
| **4** | **M5 仍是 1 個 chef_id、碎裂 0 次** | 只要重疊路徑還在給任何共現 track +5.0 nats,綁定結果就不會變 |
| **5** | **誤偵綁定率仍 > 20%** | 同上 —— 這是 `overlap_llr` 的結構問題,換偵測器救不了 |

⚠ **主預測是「沒有改善」。** 若被否證(微調顯著更好),那是好消息,
表示 M3 的微調學到了通用的人形先驗,而不只是廚房類別。

---

## 3. ⚠ 這個實驗**不能**回答什麼

1. **EPFL 是真實廚房,但不是我們微調時用的那個廚房。** 微調資料是 Roboflow
   廚房集(540 張),與 EPFL 的場景、機位、光照都不同 → 對微調模型而言仍是領域外。
   **所以「微調沒贏」不代表它在實際部署的廚房裡沒用。** 這條先寫死,
   防的是事後拿這個結果去否定 M3 的成果 ——
   與 `docs/CHIRLA_M4M5驗證_預先登記_20260903.md` §5.1 同一條規則。
2. **仍然是單人資料。** 誤併(人 vs 人)依舊結構上不可量測,
   本輪能量的只有「物件被併進人」。
3. **靜止判準(<2px 逐步位移、<60px 總範圍)是工程判斷**,沒有標註佐證。
   兩次跑用同一個判準,所以**比較**是有效的,但絕對值不是。

---

## 4. 判準(先寫死)

| 結果 | 解讀 |
|---|---|
| 誤偵綁定率下降 **> 10pp** | 微調有實質幫助,值得在 CHIRLA 驗證輪納入 `FT` 臂 |
| 下降 2~10pp | 有幫助但不足以解決,**仍須做靜止/非人過濾** |
| **變化 < 2pp 或變差** | **確認這是 `overlap_llr` 的結構問題,不是偵測器的問題** → 處置是給重疊證據加幾何一致性條件 |
