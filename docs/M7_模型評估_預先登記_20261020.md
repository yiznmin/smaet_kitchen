## 3. 階段 A:遮罩取代框(處理誤報)

**候選步**:該側近拍鏡頭上 `orig` 規則成立(物件與手的間距 ≤ d,不要求在動)的(步, 鏡頭, 物件框)。只在候選步跑分割(M6 守門 → M7 細分析)。

**做法**(每個候選物件):
1. 以 M3 的物件框、手框當提示,分割出 t 時刻的物件遮罩 O_t、手遮罩 H_t
2. 以**同一個物件框**當提示,在 t − 0.5 秒那幀分割 → O_{t−5}、H_{t−5}(物件沒動 → 同位置還是同一個物件)
3. 在動 = 排除手像素後的遮罩 IoU:IoU(O_t \ H, O_{t−5} \ H) < m,H = H_t ∪ H_{t−5}
   —— 手遮住的部分不算,遮擋不會再讓 IoU 下降
4. 接觸 = 手遮罩膨脹 r 像素後與物件遮罩有重疊
5. 關聯 = 接觸 ∧ 在動;其餘(上半身退路、平滑、融合)同 V

| 組 | 分割模型 | 權重 | 授權 |
|---|---|---|---|
| V | — | — | 對照組 |
| A-S2 | SAM 2.1 | `facebook/sam2.1-hiera-base-plus` | Apache 2.0 |
| A-ET | EdgeTAM | `facebook/EdgeTAM` | Apache 2.0 |
| A-EFT | EfficientTAM | 官方 repo `efficienttam_s` | Apache 2.0(需另裝官方 repo;裝不起來就記錄並跳過) |

網格:m ∈ {0.7, 0.8, 0.9}、r ∈ {0, 1%, 2% 人框高};d、thr_obj、thr_hand 同 V。

#### 8.3.2 檢討(看完結果後)

39 段錯誤(`results/m7/stage_a/error_segments.csv`):誤報段修好 EdgeTAM 9/18、SAM 2.1 6/18(V 0);漏報段補回 5/21、3/21。
→ 錯誤影像上的那些誤報**有被修**,但整體 F1 下降,代表另外損失了大量原本抓對的時間。

V 抓到、A 沒抓到的真值時間步,A 卡在哪一關(SAM 2.1;EdgeTAM 趨勢相同):

| 類 | 步數 | 遮罩沒接觸 | 沒有候選(選到較嚴的門檻) | 判為靜止 |
|---|---|---|---|---|
| 刀具 | 1,218 | 86% | 13% | 2% |
| 食材 | 3,613 | 46% | 39% | 15% |
| 鍋子 | 1,028 | 78% | 19% | 3% |
| 容器 | 1,070 | 67% | 23% | 10% |

1. **主因是「遮罩接觸」這一關太嚴**,不是「在動」判定:手和物件分別用各自的框切,兩個遮罩**相鄰但不重疊**。
   框已重疊(間距 0)的手—物配對中,遮罩重疊 > 0 的比例:r = 0 只有 32–38%,r = 1% 人高 82–83%,r = 2% 88–89%。
   選擇規則挑到 r = 0(提高 P),於是丟掉六成以上真正的接觸。
2. 「在動」判定本身有效:刀具、鍋鏟 P 0.82→0.88、0.89→0.93~0.96,R 不降反升 —— 這就是試跑看到的效果。
3. 食材 R 大降:番茄塊、蛋液是小而散的物件,框內常是一堆碎塊,遮罩不穩定;接觸與候選兩關都掉。
4. 遮罩扣掉手之後是空的(手遮罩把手上物件吃掉)的情況幾乎為 0,不是原因。
