### 3.1 三個 Level 的操作型定義

全部定義在 **stride 5 的取樣格點**上(GT 幀 = `video_fid` + 1)。
**獨佔** = 窗內每個取樣幀、每台選中的鏡頭,標註裡只有目標這一個人。

| Level | 定義 | 參數 |
|---|---|---|
| **L1** | 單鏡頭、獨佔、合併後**只有一個**在場區段 | 20~60 秒;`merge_gap` 15 幀(0.5 秒) |
| **L2** | 單鏡頭、獨佔(**連消失期間也不能有別人**)、**≥2 個**區段 | 每段 ≥3 秒;間隔 2~30 秒;依間隔分 `≤5 秒` / `>5 秒` 兩帶 |
| **L3S** | **同時**出現在 2~3 台鏡頭(在場區段在時間上重疊) | 重疊 ≥ 5 秒 |
| **L3T** | **先後**出現(離開 A、過一陣子出現在 B),時間不重疊 | Δt ≤ 30 秒 |

- L2 的兩帶分開報:**5 秒是 M4 的 `lost_track_buffer`** —— 帶內追蹤器自己該救回,帶外只能靠 M5。
- **L3 兩種分開報**(2026-09-16 使用者決定,定稿前修訂):需求寫的是「跨鏡頭**出現**」,
  同時被兩台看到與先後出現在兩台都符合字面,但**失敗方向相反** ——
  9/04 實測重疊路徑誤併 80.80% / 碎裂 2.71%,轉場路徑誤併 44.72% / 碎裂 54.42%。
  平均起來不描述任何真實部署,所以永遠分開列。
- **L3 的獨佔是屬性不是條件**:CHIRLA 全場只有一個人的時刻**只有 1 個**,硬性要求會挑不到窗。
  獨佔的**優先拍影片**(字面符合「單人」);非獨佔的才算得出誤併率(需要場上有 ≥2 個身份)。
- 影片挑選:固定排序鍵 `(level, split, seq, cameras, start_frame)` 取前 2,
  同一 `(seq, camera)` 最多一個。**`rendered` 絕不由結果好壞決定。**

## 6. 已知限制(報告要照抄,放在結論之前)

1. **系統層沒有學習成分。**「訓練側」= 參數推導用過的序列,**不是**梯度訓練。
2. **`seq_020` 兩邊都算**,所以兩邊都不放,單獨報。
3. **拓撲的 `overlapping` 有已揭露的洩漏**(來自全部 10 個序列);時間參數沒有洩漏。
4. **模型層是 closed-set、21 個身份、gallery/query 用到全部序列** → CMC/mAP **不可**宣稱跨身份泛化。
   ⚠ 出資方給的 PDF 正好警告這件事:「同一人相鄰時間、同套衣服分在 train/test 會造成不具部署意義的高估」,
   並建議 train/test 身份完全不重疊 —— **CHIRLA 官方切分做不到這件事**。
5. **評估看 2~3 台,但系統執行時 7 台都在線。** 這些數字不代表「只裝 2~3 台」的部署。
6. **12 段影片不是評估**:指標算**全部**窗,影片只渲染固定排序鍵選出的 1~2 段。
7. **CHIRLA 是辦公室、每個人衣服不同;廚房是口罩 + 同款制服 + 斜角鏡頭** → 每個數字都是上界。
8. EPFL 版本(若有)**僅供內部**,CC-BY-NC,不得交付、不得進報告。

彙總是**窗加權**,不是「每次綁定一票」。§3 沒有定義去重,事後改權重等於改判準 → 只揭露,不改。

## 8.4 發現的實作缺陷(看到結果後才發現,修正前後都保留)

**缺陷 1:彙總層的誤併率在「每個窗本身都量不到」時仍印出數字**

- `eval_levels.py` 把各窗的 records 串接後呼叫 `metrics.summarize`,
  它的可量測判定是「身份數 ≥ 2」—— 不同窗的不同人湊在一起就成立。
- A 套 L2 test 因此印出「誤併率 0.00%」,**正是 §4.1 禁止的形狀**;V4 只查逐窗,沒擋到。
- 修正:
  - L1/L2 彙總一律不可量測
  - L3 誤併率只彙集「窗本身量得到誤併」的窗
  - 原始串接值留在 `p_false_merge_pooled_all`
  - V4 延伸到彙總層
- 影響:
  - 逐窗數字與彙總層其他指標**完全不變**
  - A 套 L2 test 0.00% → 不可量測;L3 test 62.35% → 62.74%;L3 extra 64.97% 不變
- 修正前輸出:`results/levels/A/testextra_修正前/`

**缺陷 2:影片在人離開期間整段跳過**

- `render_level_video.py` 只迭代「選定鏡頭上有 track」的迴圈 → L2 的消失期間與 L3T 的轉場間隔**被剪掉**
  (例:`L2-test-seq_004-camera_7-002390` 96 / 130 幀)。V3 抓到 8/17 段,全是 L2 與 L3T。
- 修正:迭代窗內每個取樣幀。先驗證 10 個序列的 `tracks.csv` 全部 `video_fid == loop_i × 5`。
- 回歸:原本通過的 9 段**逐位相同**,原本失敗的 8 段改變;修正後 V3 17/17。
  抽離開期間中間一幀(t=90.83 秒)目視確認是真實畫面。

**缺陷 3:`eval_levels.py` 只依 Level 彙總,L3S 與 L3T 混在一起**

- 違反 §3.1「L3 兩種分開報」
- 處理:不改腳本,把 manifest 依 `selection_rule` 篩選後各跑一次(上表)

## 8.7 結論(照實)

1. **A 套的 L1 / L2 幾乎沒有樣本**(L1 共 2 窗、L2 共 4 窗)。原因是定義要求 20 秒以上、取樣幀全程獨佔,CHIRLA 很少有這種時段。這組數字只能當示範,不能當效能。
2. **L2 一旦離開再回來,碎裂率 100%**:3 個測試窗每次回來都被開成新身份,單鏡頭 IDF1 0.33~0.68。
3. **L3 誤併率 53~68%,正確率 11~28%**。這延續 9/15 的結論:M5 綁定分數不含「這是誰」的資訊。
4. 所有數字都是 CHIRLA(衣服各不相同)上的結果;廚房是口罩加同款制服,只會更難(§6-7)。
