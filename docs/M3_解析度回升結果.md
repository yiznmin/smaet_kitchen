# M3 解析度回升實驗結果(高解析度能否救回小物件)

> 承「小物件模擬」:對縮小後(s=0.25,刀已崩盤)的圖,提高模型輸入解析度,看 knife AP 是否回升。
> 回答「事後查詢可用高解析度 → 能救小物件嗎?」**答案:能,但有取捨,且仍需微調。**

| | |
|---|---|
| 資料 | Roboflow 廚房 330 張,縮小 s=0.25 模擬遠距小物件(也跑 s=1.0 對照) |
| 模型 | rfdetr_nano(predict shape,R=384/640/960/1280)、dfine_n(processor size,R=640/960/1280) |
| 註 | COCO 預訓練、**未微調** |

---

## 結果(s=0.25,小物件;這是重點)

| 模型 | 輸入解析度 | **knife AP** | 整體 mAP50 |
|---|---|---|---|
| rfdetr_nano | 384 | 0.024 | 0.487 |
| rfdetr_nano | 640 | 0.085 | 0.470 |
| rfdetr_nano | 960 | 0.134 | 0.401 |
| rfdetr_nano | **1280** | **0.153** | 0.353 |
| dfine_n | 640 | 0.030 | 0.469 |
| dfine_n | 960 | 0.096 | 0.450 |
| dfine_n | 1280 | 0.055 | 0.345 |

對照(s=1.0,大物件):rfdetr_nano 提高解析度 knife AP 幾乎不變(~0.19);dfine_n 反而下降(0.174→0.089)。

---

## 三個關鍵發現

1. **✅ 高解析度能救回小物件**:rfdetr_nano 的刀 AP 從 **0.024 → 0.153(約 6 倍)**,隨解析度單調上升。
   → 「事後查詢用高解析度救小物件」**方向正確、有效**。
2. **⚠️ 取捨:救小、傷大**:整體 mAP50 反而下降(0.487→0.353)—— 大物件在超高解析度下變差。
   高解析度對小物件有利、對大物件不利。
3. **RF-DETR 比 D-FINE 更耐高解析度**:rfdetr 到 1280 仍進步;**dfine 在 1280 崩**(CNN 離訓練解析度太遠就壞,
   RF-DETR 的 DINOv2 位置編碼內插較穩)。→ 高解析度策略下 **RF-DETR 是更佳選擇**。

## 誠實限制與結論

- **回升後刀 AP 仍只有 ~0.15** → 高解析度**有幫助但不夠**,光拉解析度不能解決。
- **真正解法 = 在適當較高解析度上「微調」** → 同時兼顧大小物件,而非無腦拉高(會傷大物件、且 dfine 會崩)。
- 灰底填充為人工背景;最終仍需**你鏡頭視角**的資料驗證。

## 對策略的意涵(事後查詢 = 準確度優先)
1. **可採高解析度**(系統不要即時,負擔得起)→ 對小物件(刀)有實質幫助。
2. **模型選 RF-DETR**(高解析度下表現穩、且最準)。
3. **務必微調**:高解析度 + 微調才能把刀從 ~0.15 拉到可部署,並避免傷大物件。
4. 部署解析度需**取捨**(救小 vs 傷大)→ 微調時就以目標解析度訓練,讓兩者兼顧。
