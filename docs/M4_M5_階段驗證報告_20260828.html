摘要
Summary

三句話的結論

一、M4 追蹤已完成並可驗證。 採用 ByteTrack(ECCV 2022,MIT 授權),在合成情境與 EPFL 真實影片上均通過; 第三方可自行執行我們的驗證腳本重現結果。

二、M5 的答案不在「認長相」,而在「空間與時間」。 實測顯示可商用的外觀模型跨視角認人的 Rank-1 只有 11%(比隨機猜還差), 而廚師穿同款制服只會更糟。我們把架構改成以相機拓撲、轉場時間、地面幾何與行走軌跡為主, 外觀退居輔助 —— 這個決定被蒙地卡羅實驗直接證實:把外觀品質從實測水準一路降到零, 碎裂率一個小數點都沒有動。

三、演算法已走到目前的極限,誠實的缺口是誤併率。 七輪下來誤併從 72% 壓到 5.6%,碎裂從 24.4% 壓到 5.2%(達標)。 但誤併距離食安追責所需的 1% 還差 5 倍,且目前沒有已知的演算法解 —— 這一段必須靠現場流程手段或下游設計補償,我們已備妥三條方案供選擇。

為什麼這兩種錯誤要分開報

碎裂(同一人被拆成多個身分)會讓事件序列斷掉、計時歸零 → 漏報。但它抓得到:系統報的身分數多於排班人數就會告警。

誤併(綁到別人身上)會讓 A 的行為記到 B 頭上 —— 冤枉一個、放過一個。而它完全靜默,下游的事件判定與資料庫全盤繼承,沒有任何機制驗得出來。

所以本專案對誤併的容忍度訂為碎裂的 1/5,所有取捨都以此為準。 把兩者合併成單一「準確率」會系統性隱藏最大的風險。

單幀偵測(M3)只知道「這一幀有一個人」,不知道下一幀是不是同一個人。 追蹤就是幫每個對象發一個身分證號並逐幀維持 —— 這是「同一個人停留超時」「未洗手」這類判斷的前提。

外觀實測

先問一個該問的問題:靠「長得像」認得出人嗎?

整個 M5 的架構選擇取決於這個答案。我們用 EPFL 廚房資料集的 6 個真實身份 × 5 個視角 × 15 個時刻 = 449 張人形影像, 以我們微調過的 RF-DETR 偵測人、再抽外觀特徵,做標準的 Re-ID 評測。

外觀模型授權同人相似度不同人Rank-1能否出貨
DINOv2(通用視覺)Apache-2.00.4900.46511%可
OSNet(Re-ID 專用)架構 MIT,權重研究限定0.6180.48892.7%否

隨機猜測的期望值約 17%。DINOv2 的同人與不同人相似度只差 0.025 —— 分不開。

這個結果構成一個兩難

能出貨的模型認不出人;認得出人的模型不能出貨。 OSNet 的現成權重訓練於 Market-1501 / MSMT17 / DukeMTMC,這些資料集條款均寫明僅供研究、不可商用, 而且授權會傳染 —— 拿它們自訓再出貨同樣不行。

更關鍵的是:這 6 個人穿著不同衣服都認不準,而真實廚房的廚師穿同一款制服。 所以即使解決了授權,外觀路線在本場域的天花板也很低。

那就別讓外觀當主角

我們把架構改成時空為主、外觀為輔,並用蒙地卡羅實驗直接檢驗這個決定值不值得: 把外觀品質從實測水準一路調降到完全無資訊(模擬全員同制服)。

碎裂率:24.8% → 24.8%

外觀從實測水準降到零,一個小數點都沒有動。

誤併率:5.1% → 5.6%

只惡化 0.5 個百分點,在雜訊帶邊緣。

解析式也印證:典型情境下「同時通過時間窗的假候選」期望值只有 0.14 —— 絕大多數綁定決策根本只有一個候選人,外觀連被用到的機會都沒有。

對投資決策的意涵

在這個架構下,無論是 NVIDIA TAO 模型的法務風險、或是自訓 Re-ID 模型的 GPU 工程成本, 買到的效益接近於零。這筆錢與時間應該投在相機佈設與地面校正上 —— 後面的數據會說明為什麼。

方法
Method

我們怎麼確保這些數字不是自己說了算

團隊無法自錄多人資料,所以 M5 的量化必須靠模擬。 模擬最大的風險是「用自己的假設出題、再用同一套假設答題」。我們用三個機制擋住它:

一、預先登記

每一輪實驗在寫任何程式之前,先把掃描網格、及格判準、以及可被否證的預測寫成文件提交進 git。 跑完只追加結果,不得回頭修改判準。七輪都留有時間戳可查。

二、世界模型刻意不一致

模擬器的「真實世界」用長尾分布產生轉場時間,而受測系統仍用高斯分布去判斷, 且模擬器刻意不引用系統的證據模組。量到的是「模型失配時會壞成什麼樣」,不是「用高斯驗高斯」。

三、解析 → 對拍 → 模擬

順序不可顛倒。先手算出理論門界,再用真實的系統物件反推同一個值來對拍 (誤差 0.002~0.004,等於掃描步長),確認實作與理論一致後才跑模擬。

四、消融夾擠

五組消融(全開新 / 純外觀 / 純時空 / 完整 / 上帝視角)吃同一個世界。 完整系統必須落在消融組與上帝視角之間,否則是模擬器有問題,不是系統有進步。

這套方法抓到了什麼(否則我們會報出錯的數字)

第五輪修完之後,指標顯示「碎裂 0% / 誤併 0% / A 級」—— 看起來完美。 但同一份資料的 IDF1 只有 0.264,揭露了真相:4 位廚師被全部併成 1 個身分。

兩個指標同時瞎了。判定綁定正確與否的邏輯把「和上次同一個編號」當成正確 —— 全部併成一個時,這個條件每次都成立;而人數告警只檢查「身分數多於人數」,沒檢查「少於」。 兩者都已修正(改用編號的歸屬判斷 + 雙向告警)。

第五輪報出的數字因此作廢並已在文件中標註(質性結論仍成立)。 教訓已寫進方法論:當一個修法讓所有指標同時變完美時,先懷疑指標。

有效的改善,全部來自「加一條新的證據軸」(位置、方向、全景鏡頭、地面幾何、行走軌跡)。

軌跡證據比預期穩健 —— 對佈署是好消息

我們登記的預測是「效益依賴行走慣性,τv=1 秒(接近隨機遊走)時幾乎無效」。 實際上 τv=1 秒仍從 20.5% 降到 7.8%。

原因:我們比的是同一瞬間兩個人的速度,不是預測未來。即使一個人的走法完全沒有慣性, 兩個不同的人在同一瞬間的速度仍然不一樣。因此不必先量測真實廚房的行走慣性才敢啟用這個功能。

直接檢驗:軌跡證據到底解決了哪一類誤併?

第七輪登記的預測 1 是「效益集中在兩人相距 0.5 公尺以內那一類」。 我們寫了診斷腳本,用同一組隨機種子只切換軌跡開關,量出每次誤併發生時兩人的實際距離:

< 0.5 公尺19838−81%
0.5 ~ 1.5 公尺04+4
1.5 ~ 3.0 公尺93−67%
> 3.0 公尺3257+78%

預測成立 —— 近距離模糊正是被解決的那一類,證據接在該接的地方。

但同時量到一個新的失效模式:相隔 3 公尺以上、剛好朝同方向以相近速度移動的兩個人, 誤併反而增加了 78%(絕對量約佔全部轉場的 1.7%,被近距離的改善淹沒)。 軌跡證據不是只會幫忙。這是下一步該處理的東西 —— 位置已判定「不可能是同一人」時,不該讓速度翻案。

我們自己犯的錯:同一個數學錯誤犯了兩次

第七輪登記時算出「0.5 秒的觀測窗已經足夠」,實跑卻只降到 11.5%,而 1.0 秒降到 7.9% —— 邊際效益完全沒有遞減。預測被自己的實驗否證。

根因:比較兩個有噪聲的觀測時,差值的標準差是單次的 √2 倍。 登記時用的是單次觀測的噪聲,系統性高估了鑑別力。

而這不是第一次 —— 第六輪的地面校正證據犯過完全一樣的錯,當時修掉了,第七輪又犯一次。 高估鑑別力的後果是把真的同一個人判成「對不上」而拒絕綁定:修正前碎裂 9.5%,修正後 6.0%。

已在程式碼中留下註解記錄這個教訓。連同第六輪與第七輪各一處登記時的算術失誤, 全部保留在文件裡,未回頭修改。

全景鏡頭的能力邊界(不可誤解)

全景鏡頭只負責「人」。我們的實驗顯示人的偵測相當耐得住縮小 (縮到四分之一時 Recall 仍保有 89%),但刀具那類小物件會崩(僅剩 11%)。

所以細節事件仍然需要近距鏡頭,這筆預算不能省。全景鏡頭是身分的骨幹,不是萬用鏡頭。

證據的物理天花板:為什麼規格訂在這些數字

每一條證據能提供的資訊量都有數學上限,而綁定決策的門檻是 1.61(單位:nats)。 資訊量低於門檻的證據,再怎麼調參數都沒有用 —— 這就是規格數字的來源,不是拍腦袋訂的:

地面校正殘差證據上限判定
0.2 公尺4.09可用
0.4 公尺2.70鑑別力下降
0.8 公尺1.32低於門檻,完全無用
軌跡觀測窗證據上限判定
0.5 秒1.95勉強過門檻

軌跡證據的代價是身分指派會延後約 1 秒(要先累積速度)。 本系統的資料流是事後查詢、非同步寫入,所以可接受;若日後有即時告警需求則需重新評估。

交付給業主的驗收套件

業主手上只有平面圖,沒有我們的上下文。 所以交付物的設計目標是:讓他們不需要理解演算法,也能自行量出可信的數字。 共六個步驟,每一步都有「做完怎麼確認」的檢查點。

步驟工具業主要做的事
1拓撲產生器填一張表:哪台鏡頭走得到哪台、步行路徑距離幾公尺(繞過障礙,不是直線)、視野有無重疊。腳本自動換算成設定檔
2—每台鏡頭在地面挑 4 個以上不共線的點,量平面圖座標 + 讀畫面像素座標。不用填精度參數 —— 系統自己從這些點算出標定殘差
3設定自檢還沒錄影就能跑。11 項檢查:拓撲填錯、單向連結、孤立鏡頭、轉場時間與追蹤模組衝突、時鐘容忍度、校正品質。必須 0 個 ERROR 才能往下
4走動測試記錄器單一 HTML 檔,手機平板都能開、離線可用。2~3 人穿實際制服來回走 20 分鐘,進出畫面時按一下,匯出真值 CSV
5端到端執行影片 → 偵測 → 追蹤 → 身分,輸出每次綁定決策的分數與候選數明細,可事後查「為什麼綁成這樣」
6驗收評分輸出 IDF1 / 碎裂率 / 誤併率,直接對照門檻。同時檢查「身分數 vs 實際人數」

驗收門檻與它的來源

指標門檻依據
IDF1≥ 0.90身分保持的整體品質,國際標準指標,第三方認得
碎裂率≤ 5%「未洗手」這類事件鏈約含 3 次跨鏡頭交接,要達 80% 召回 → 每次交接碎裂率須 ≤ 7.2%,留給偵測與追蹤的誤差預算後訂 5%

兩個「開了卻不生效、而且不報錯」的陷阱已補上防護

這類失效在本專案反覆出現,危險之處是看起來一切正常:

  • 人的類別編號依權重而異(COCO 預訓 = 1,我們微調的 11 類 = 0)。接錯時一個人都偵測不到,而且完全不報錯 → 已改為自動判斷,並在偵測數為 0 時明確提示
  • 地面校正沒做時,舊版會偷偷套用一個預設精度值 —— 那個精度下證據幾乎沒有鑑別力,但看起來是開著的 → 改為明確停用並記錄原因
  • 軌跡證據開啟但沒做地面校正時完全不生效(速度是從地面座標算出來的)→ 新增自檢項目,直接報 ERROR

誠實說明:目前已知的限制

最大的缺口

誤併率約 5~8%,而食安追責所需的門檻是 1%。

七輪下來從 72% 壓到 5.6%,但剩下這 5 倍缺口目前沒有已知的演算法解。 現有的證據軸(拓撲、時間、位置、方向、幾何、軌跡、外觀)大致已經用盡, 而七輪的規律說得很清楚:只有新的證據軸能帶來改善,重新分配既有信任不會。

若這個誤差不可接受,三條可行的補償路徑

手段作法預期效果成本
下游補償事件標上信心度;彙總報表註明誤差範圍;針對性調查時人工複核影片不降低誤併率,但讓它可見而非靜默最低
增加全景鏡頭第二台不同角度的俯瞰鏡頭,消除單一視角的遮擋未測,推估可再降三分之一一台鏡頭

視覺標記路線沒有授權問題,也不涉及生物特徵個資,是三者中效果與風險比最好的一條。

其他必須說清楚的四點

  • 目前的準確率數字全部來自模擬,尚未用真實的多人資料校準。 世界模型的行走過程、步速、慣性都是設定值不是實測值。我們量到的是「每條證據值多少」與「在什麼條件下會壞」, 不是絕對準確率。交付套件的步驟四到六就是為了取得那份資料 —— 業主的測試結果會用來修正這些預估。
  • 跨輪的絕對數字不可直接相比。世界模型在輪次之間有改動,會改變隨機數流。 輪內的受控對照才是有效比較,本報告中的 72% → 14.5% → 5.6% 是歷程敘述而非單次實驗結果。
  • 第五輪報出的數字已作廢(質性結論仍成立),原因是前述的指標盲點。已在原始文件中標註,未刪除。
  • 新的失效模式已量到但尚未處理:相隔 3 公尺以上、同方向同速度移動的兩人偶爾會被誤綁(約佔全部轉場的 1.7%)。
