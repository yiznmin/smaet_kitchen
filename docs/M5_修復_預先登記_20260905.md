## 1. 為什麼做這件事

2026-09-04 的 CHIRLA 2×2 網格,四格全部 C 級:

| | 驗收門檻 | 實測 |
|---|---|---|
| 誤併率 | **≤ 1%** | **58.84 ~ 67.23%** |
| 碎裂率 | ≤ 5% | 22.39 ~ 31.33% |

全部觸發預先登記 §6 先寫死的失敗條件(誤併 > 30%),定性是
**「架構層問題,不是調參可解」**。§6 也先寫死了兩個處置,本輪執行其中的下游部分。

### 診斷:病灶已定位

**(a) `log K` 稀釋在數學上不可能拒絕**(`identity_st.py:151`)

```
5.0 − log(k) + app_llr < 1.609  →  k > 29.7
```

而 CHIRLA 單台鏡頭同時最多 **9** 個身份。**無論畫面裡有多少人,
重疊路徑永遠至少產生一個通過門檻的候選。** 指紋:重疊路徑
`p_break = 2.71%`(幾乎從不拒絕)但 `p_false_merge = 80.80%`。

**(b) 過門檻後唯一的排序依據是外觀,而外觀是雜訊**

重疊路徑 `p_correct = 16.49%`,而同時在場的其他身份中位是 **7** 人:

```
1/7 = 14.3%     1/6 = 16.7%     實測 16.49%
```

**統計上與「隨機挑一個」無法區分。**

⚠ 本輪實作時量到一個更精確的數字:用 `AppearanceLR.MEASURED["dinov2"]`
(同人 0.490 / 不同人 0.465)產生的 embedding,**同人與不同人的 LLR 差距只有
0.062 nats**,而正確決策需要 log(5) = 1.609 —— **差 26 倍**。

## 2. 本輪的兩個修法(定死)

| 代號 | 修法 | 位置 | 預設 |
|---|---|---|---|
| **F1** | margin test:`best − second < margin` 時**開新身份**而不是綁 | `identity_st.py` 決策點 | **關閉** |
| **F2** | 同鏡頭互斥:chef 已在本鏡頭上有 track → 不列為候選 | `identity_st.py` 候選集 | **關閉** |

### 為什麼 F1 的門檻取 log(cost_false_merge_over_break)

與 `llr_threshold` **同源**。兩者都是「誤併比碎裂貴 5 倍」換算出來的:
差距小於它,表示區分兩個假設的證據還不足以承擔誤併的成本。
本專案的成本比是 **誤併 : 碎裂 = 5 : 1**(誤併靜默不可回復,碎裂看得見),
所以「分不出來」的正確處置是**碎裂**,而現行架構一律轉成**誤併** —— 方向剛好相反。

### ⚠ F1 有一個必須保留的例外

**只有一個候選時不套用 margin。** 那不是「分不出來」,是「沒有別人可混淆」。
擋掉它會把單人場景的正確綁定全部打成碎裂 ——
EPFL 兩輪的候選分布分別是 `{0:1, 1:92}` 與 `{0:1, 1:136}`,**全部是單候選**,
沒有這個例外的話那兩輪會從「碎裂 0 次」變成「全碎」。

## 4. 判準(先寫死)

### 4.1 主判準:加權成本

單看誤併或碎裂會誤導 —— F1 一定讓碎裂變差。依 5:1 成本比:

```
cost = 5 × p_false_merge + 1 × p_break
基線 coco_none = 5 × 0.5884 + 0.3133 = 3.255
```

| 結果 | 判定 |
|---|---|
| cost < 3.255 | 修法有效,保留 |
| cost ≥ 3.255 | **修法無效,關閉並照實記錄** —— 不得因為「誤併降了」就保留 |

### 4.2 硬性驗收(不通過就是實作錯,不是效果不好)

| # | 條件 |
|---|---|
| V1 | `base` 格與 2026-09-04 的 `coco_none` **逐位相同**(誤併/碎裂/正確率/IDF1) |
| V2 | `f2` 與 `f1f2` 的 `same_cam_conflicts` **= 0** |
| V3 | `base` 的 `same_cam_conflicts` **> 0**(否則表示這個病灶不存在,F2 是空修) |
| V4 | `f1`/`f1f2` 的 `margin_blocked` **> 0** |
| V5 | `git diff` 確認 `src/m5_sim/world.py` 未被動到 |

### 4.3 ⚠ 本輪特有的失敗條件

若 `f1` 的**碎裂率 > 90%**,判定為 **「margin test 在重疊路徑上等同於關閉該路徑」**。

處置先寫死:**不是調小 margin** —— 調小等於承認我們願意接受沒有依據的綁定。
正確的解讀是「重疊路徑在沒有幾何證據時本來就不該綁」,
處置是**進行 F4(幾何一致性)**,並在報告中把 F1 定位為
**診斷工具**(把靜默的 80% 誤併轉成看得見的碎裂)而非解方。

## 5. 事先寫下的預測(可被否證)

| # | 預測 | 依據 |
|---|---|---|
| **1** | `f1` 的重疊路徑誤併 **< 10%**(基線 80.80%) | 外觀只能拉開 0.062 nats,margin 要 1.609 → 幾乎所有多候選綁定都會被擋 |
| **2** | `f1` 的重疊路徑碎裂 **> 90%**(基線 2.71%),觸發 §4.3 | 同上,擋掉等於開新身份 |
| **3** | `f1` 的 **cost < 3.255**(通過主判準) | 粗估:重疊 922 決策全碎、轉場 814 不變 → cost ≈ 1.84 |
| **4** | `f2` 單獨的效果 **很小**(cost 變動 < 0.2) | 同鏡頭衝突是物理上不可能的綁定,但數量應遠少於一般誤併 |
| **5** | `f1f2` ≈ `f1`(差距 < 0.2) | 兩者作用在不同層(候選集 vs 決策),但 F1 的影響量級大得多 |

⚠ 預測 1 與 2 是**同一件事的兩面**,不是兩個獨立的預測 ——
若 1 成立而 2 不成立(誤併降了、碎裂沒漲),表示那些決策**憑空消失**了,
必須先查指標而不是慶祝。這是 2026-09-04 那次「碎裂 31.33% 但兩條路徑都 0.00%」
的同一種形狀。

## 6. 已知限制(報告要照抄,放在結論之前)

1. **這兩個修法都是「止血」不是「治病」。** 它們讓系統**不做沒有依據的綁定**,
   但**不會讓證據變得有依據**。真正的解方是 F4(重疊路徑的幾何一致性)。
2. **CHIRLA 是辦公室不是廚房。** 絕對值不能當廚房的預測值;
   可比的是**修法之間的相對改善**。
3. **仍然沒有相機標定**,所以 `GroundPlaneLR` 與 `VelocityLR` 在本輪依舊不生效,
   轉場路徑的 54.42% 碎裂**本輪不會改善**。
4. **加權成本 5:1 這個比值本身沒有實測來源**,與「每 2~5 分鐘跨一次鏡頭」
   同屬待校準的假設(`docs/M4_M5_階段驗證報告_20260828.md:378`)。
   主判準建立在它上面,換了比值結論可能反轉。
