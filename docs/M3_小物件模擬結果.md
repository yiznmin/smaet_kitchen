# M3 小物件模擬實驗結果(把物件人工縮小)

> 目的:資料集的刀是近景大特寫,但部署是俯視遠距(物件小)。用「縮小+灰底填充」模擬遠距,
> 看物件變小後模型還認不認得。**結論:物件縮小,刀的偵測會崩盤。**

| | |
|---|---|
| 做法 | 整張圖縮放 s 倍貼到原尺寸畫布(灰底),物件佔畫面比例變小;GT 框同步調整 |
| 縮放 | s = 1.0 / 0.5 / 0.25(面積 1、1/4、1/16) |
| 模型 | rfdetr_nano(準)、dfine_n(快),各自原生解析度 |
| 資料 | Roboflow 廚房 330 張(未微調的 COCO 現成模型) |

---

## 結果

| 模型 | 縮放 | mAP@50 | **knife AP** | 小物件 mAP |
|---|---|---|---|---|
| rfdetr_nano | 1.0 | 0.625 | **0.209** | 0.080 |
| rfdetr_nano | 0.5 | 0.615 | 0.180 | 0.169 |
| rfdetr_nano | **0.25** | 0.487 | **0.024** | 0.121 |
| dfine_n | 1.0 | 0.546 | 0.174 | 0.076 |
| dfine_n | 0.5 | 0.550 | 0.121 | 0.144 |
| dfine_n | **0.25** | 0.469 | **0.030** | 0.103 |

## 關鍵發現

1. **物件越小,刀的 AP 越崩**:
   - rfdetr_nano:0.209 → 0.180 → **0.024**
   - dfine_n:0.174 → 0.121 → **0.030**
   - **縮到 1/4 大小,刀幾乎完全偵測不到(AP ≈ 0.02–0.03)。**
2. **整體 mAP 掉得少**(0.625→0.487):冰箱/微波爐等**大物件縮小後仍可偵測** → 證明崩盤的**專屬於小物件**(刀)。
3. **視覺佐證**(`results/m3_acc/vis_small/`):縮到 0.25 時小刀全漏,模型只亂框一個大框。

> 註:`小物件 mAP` 在 s=0.5 反而上升,是因為該指標只看「落在小尺寸桶」的物件;縮放會改變哪些物件落入該桶,故非乾淨訊號。**knife AP 才是乾淨指標**,它單調崩盤。

## 對專案的意義

- **直接證實**:你的**俯視遠距商用廚房**裡,刀在畫面中又小又遠 → **現成模型對刀幾乎一定失效**。
- 因此**必須**:(a) **用你鏡頭視角、含刀的資料微調**;且/或 (b) **提高輸入解析度**(因系統是事後查詢、不要即時,可負擔高解析度)。

## 誠實限制
- 灰底填充是**人工背景**,非真實遠景紋理;為「尺寸效應」的受控實驗。
- 未測「提高輸入解析度能否救回」→ 列為下一個實驗(見下)。

## 下一個實驗(建議)
- 拿**縮小後(如 s=0.25)**的圖,把模型**輸入解析度拉高**(如 rfdetr 384 → 728),看 knife AP 是否回升。
  → 直接驗證「事後查詢用高解析度救小物件」這條路是否有效。
