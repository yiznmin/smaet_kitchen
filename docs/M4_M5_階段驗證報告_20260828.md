## 1. 三句話的結論

**一、M4 追蹤已完成並可驗證。**
採用 ByteTrack(ECCV 2022,MIT 授權),在合成情境與 EPFL 真實影片上均通過;
第三方可自行執行我們的驗證腳本重現結果。

**二、M5 的答案不在「認長相」,而在「空間與時間」。**
實測顯示可商用的外觀模型跨視角認人的 Rank-1 只有 **11%**(比隨機猜還差),
而廚師穿同款制服只會更糟。我們把架構改成以相機拓撲、轉場時間、地面幾何與行走軌跡為主,
外觀退居輔助 —— 這個決定被蒙地卡羅實驗直接證實:把外觀品質從實測水準一路降到零,
**碎裂率一個小數點都沒有動**。

**三、演算法已走到目前的極限,誠實的缺口是誤併率。**
七輪下來誤併從 72% 壓到 5.6%,碎裂從 24.4% 壓到 5.2%(達標)。
但誤併距離食安追責所需的 1% 還差 5 倍,且目前沒有已知的演算法解 ——
這一段必須靠現場流程手段或下游設計補償,我們已備妥三條方案供選擇。

### 為什麼這兩種錯誤要分開報

| 錯誤 | 後果 | 抓不抓得到 |
|---|---|---|
| **碎裂**(同一人被拆成多個身分) | 事件序列斷掉、計時歸零 → 漏報 | ✅ **抓得到**:系統報的身分數多於排班人數就會告警 |
| **誤併**(綁到別人身上) | A 的行為記到 B 頭上 → **冤枉一個、放過一個** | ❌ **完全靜默**,下游事件判定與資料庫全盤繼承,沒有任何機制驗得出來 |

所以本專案對誤併的容忍度訂為碎裂的 **1/5**,所有取捨都以此為準。
把兩者合併成單一「準確率」會系統性隱藏最大的風險。

## 2. M4 多目標追蹤

單幀偵測(M3)只知道「這一幀有一個人」,不知道下一幀是不是同一個人。
追蹤就是幫每個對象發一個身分證號並逐幀維持 —— 這是「同一個人停留超時」「未洗手」這類判斷的前提。

### 2.1 選型與依據

| 項目 | 決定 | 理由 |
|---|---|---|
| 追蹤器 | **ByteTrack** | ECCV 2022(arXiv:2110.06864);純運動 Kalman + IoU + 匈牙利配對,CPU 即時 |
| 實作來源 | `supervision` 的 `sv.ByteTrack` | **MIT 授權,可合法閉源商用**;直接吃 RF-DETR 的偵測輸出 |
| 不含 | 外觀 / Re-ID 特徵 | 屬 M5。M4 維持純運動 → 授權乾淨、CPU 快 |

> ByteTrack 在公開權威評測 **MOT17 測試集**的成績:**MOTA 80.3 / IDF1 77.3 / HOTA 63.1**,單 GPU 30 FPS。
> 這些是公開競賽數據,任何第三方都能自行查證。

### 2.2 驗證結果

| 情境 | 斷言 | 結果 |
|---|---|---|
| S1 單一對象移動 | 全程維持同一 ID | ✅ PASS |
| **S2 兩對象交叉** | **交會後不互換,ID-switch = 0** | ✅ PASS |
| S3 短暫遮擋(小於緩衝) | 復現時沿用同一 ID | ✅ PASS |
| S3b 遮擋過久 | 正確判為新對象 | ✅ PASS |
| S4 真實影片(EPFL 廚房) | 單一廚師全程同一編號 | ✅ PASS |

追蹤器本身耗時(排除偵測)遠低於規格要求的 5 ms/幀,純 CPU。
S2 是單人資料集給不了的多目標檢查,用合成序列補上。

**重現方式**(第三方可自行執行):

```bash
python scripts/verify_m4.py          # 合成驗證,數秒、免顯卡,逐項印出 PASS/FAIL
python scripts/m4_track_video.py     # 真實影片 demo,輸出標註幀可肉眼確認
```

### 2.3 誠實的限制

可用的公開資料(EPFL)**是單人場景**,所以真實的多目標 ID-switch 率無法用它量化 ——
我們用合成序列當站位。真正的廚房驗證需要自錄多人跨工作站影片,
這是交付給業主的測試套件要取得的東西。

### 2.4 為了接上 M5 而修正的三個事件語意問題

端到端串接才會浮現、單看 M4 驗不出來的問題:

| 問題 | 後果 | 修法 |
|---|---|---|
| 軌跡從遮擋恢復時**不發任何事件** | M5 把該廚師標成「已離開」後**永遠卡住**,綁定永久遺失 —— 最高頻且靜默 | 新增 `reacquired` 事件 |
| 離場時間戳取自 `removed` | 離場時間系統性延後約 1 秒,使所有轉場時間差偏小,時間窗判斷失準 | 改取自 `lost_track` 當下 |
| 離場紀錄從不清除 | 300 人次洩漏 500 筆 → 違反規格的記憶體驗收標準 | 加 `_forget()` 回收 |

## 3. M5 的前提:靠「長得像」認得出人嗎?

整個 M5 的架構選擇取決於這個答案。我們用 EPFL 廚房資料集的
**6 個真實身份 × 5 個視角 × 15 個時刻 = 449 張人形影像**,
以我們微調過的 RF-DETR 偵測人、再抽外觀特徵,做標準的 Re-ID 評測。

| 外觀模型 | 授權 | 同人相似度 | 不同人 | Rank-1 | 能否出貨 |
|---|---|---|---|---|---|
| **DINOv2**(通用視覺) | Apache-2.0 | 0.490 | 0.465 | **11%** | ✅ 可 |
| **OSNet**(Re-ID 專用) | 架構 MIT,**權重研究限定** | 0.618 | 0.488 | **92.7%** | ❌ 否 |

隨機猜測的期望值約 17%。DINOv2 的同人與不同人相似度只差 **0.025** —— 分不開。

### 3.1 這個結果構成一個兩難

**能出貨的模型認不出人;認得出人的模型不能出貨。**

OSNet 的現成權重訓練於 Market-1501 / MSMT17 / DukeMTMC,這些資料集條款均寫明僅供研究、不可商用,
而且授權會傳染 —— 拿它們自訓再出貨同樣不行。

更關鍵的是:這 6 個人**穿著不同衣服**都認不準,而真實廚房的廚師穿同一款制服。
所以即使解決了授權,外觀路線在本場域的天花板也很低。

### 3.2 那就別讓外觀當主角

我們把架構改成**時空為主、外觀為輔**,並用蒙地卡羅實驗直接檢驗這個決定值不值得:
把外觀品質從實測水準一路調降到完全無資訊(模擬全員同制服)。

| 指標 | 外觀=實測水準 | 外觀=完全無資訊 |
|---|---|---|
| 碎裂率 | 24.8% | **24.8%**(一個小數點都沒動) |
| 誤併率 | 5.1% | 5.6%(雜訊帶邊緣) |

解析式也印證:典型情境下「同時通過時間窗的假候選」期望值只有 **0.14** ——
絕大多數綁定決策**根本只有一個候選人**,外觀連被用到的機會都沒有。

> **對投資決策的意涵**:在這個架構下,無論是 NVIDIA TAO 模型的法務風險、
> 或是自訓 Re-ID 模型的 GPU 工程成本,**買到的效益接近於零**。
> 這筆錢與時間應該投在相機佈設與地面校正上。

## 4. 方法論:怎麼確保這些數字不是自己說了算

團隊無法自錄多人資料,所以 M5 的量化必須靠模擬。
模擬最大的風險是「用自己的假設出題、再用同一套假設答題」。我們用四個機制擋住它:

**一、預先登記。**
每一輪實驗在**寫任何程式之前**,先把掃描網格、及格判準、以及可被否證的預測寫成文件**提交進 git**。
跑完只追加結果,不得回頭修改判準。七輪都留有時間戳可查。

**二、世界模型刻意不一致。**
模擬器的「真實世界」用長尾分布產生轉場時間,而受測系統仍用高斯分布去判斷,
且模擬器**刻意不引用系統的證據模組**。量到的是「模型失配時會壞成什麼樣」,不是「用高斯驗高斯」。

**三、解析 → 對拍 → 模擬,順序不可顛倒。**
先手算出理論門界,再用**真實的系統物件**反推同一個值來對拍
(誤差 0.002~0.004,等於掃描步長),確認實作與理論一致後才跑模擬。

**四、消融夾擠。**
五組消融(全開新 / 純外觀 / 純時空 / 完整 / 上帝視角)吃同一個世界。
完整系統必須落在消融組與上帝視角**之間**,否則是模擬器有問題,不是系統有進步。

### 4.1 這套方法抓到了什麼(否則我們會報出錯的數字)

第五輪修完之後,指標顯示「碎裂 0% / 誤併 0% / A 級」—— 看起來完美。
但同一份資料的 **IDF1 只有 0.264**,揭露了真相:**4 位廚師被全部併成 1 個身分**。

兩個指標同時瞎了:

- 判定綁定正確與否的邏輯把「和上次同一個編號」當成正確 —— 全部併成一個時,這個條件每次都成立
- 人數告警只檢查「身分數**多於**人數」,沒檢查「**少於**」

兩者都已修正(改用編號的**歸屬**判斷 + 雙向告警)。
**第五輪報出的數字因此作廢並已在文件中標註**(質性結論仍成立)。

> 教訓已寫進方法論:**當一個修法讓所有指標同時變完美時,先懷疑指標。**

## 5. 七輪實驗:每一輪的假設與結果

輪次順序有因果意義 —— 每一輪的結果決定了下一輪要試什麼。
以下包含四次失敗,它們和成功的三次一樣重要。

| # | 假設 | 結果 | 判定 |
|---|---|---|---|
| **01** | 補三個結構缺口:繞路、逗留、同鏡頭斷軌重關聯 | 診斷正確(84% 碎裂來自這三者),但三個修法沒一個改善加權成本;同鏡頭重關聯反而讓誤併 4.8% → 10.2% | ❌ 未改善 |
| **1b** | 改為引入**位置**這條新證據(同鏡頭內人不會瞬間移動) | 加權成本 −3.1 | ✅ 有效 |
| **02** | 換用重尾分布、重估背景到達率與逗留比例 | 零和交換 —— 碎裂降多少,誤併就升多少。登記時挑的旋鈕本身也選錯方向 | ❌ 零和 |
| **03** | 引入**方向**證據(從哪個出入口離開/進入) | 碎裂 19.2% → 13.7%,加權成本 −4.5。**但預測錯在危險的方向**:標錯的出入口區域不只是沒用,而是**主動有害** | ✅ 有效 |
| **04** | 離線重關聯 + 排班人數約束 | 又是零和交換。其中一個登記的機制最終沒有執行,已如實記錄為執行落差 | ❌ 零和 |
| **05** | **全景鏡頭** —— 一台看得到整個廚房的鏡頭 | 碎裂 18.8% → 0.1%。前四輪所有失敗都源自**盲區**(系統只能猜「他走了幾秒」);全景鏡頭讓身分在畫面裡連續維持,其他鏡頭靠幾何重疊掛上去 | ✅ 解決 |
| **06** | **地面校正**(homography):把畫面像素換算成廚房平面上的公尺 | 誤併 72% → 14.5%。讓「重疊鏡頭裡有人」升級為「就是站在那個座標的那一個人」。本輪修掉六個 bug,並發現前述的指標盲點 | ✅ 關鍵 |
| **07** | **軌跡證據**:兩個站在同一位置的人,是從不同方向走過來的 | 誤併 18.6% → **5.6%**,碎裂同步 7.3% → **5.2%** | ✅ 有效 |

### 5.1 七輪最可複用的一條規律

> **有效的改善,全部來自「加一條新的證據軸」**(位置、方向、全景鏡頭、地面幾何、行走軌跡)。
> **失敗的,全部是「在既有證據上重新分配信任」**(換分布、調門檻、改權重、強制合併)。

這條規律在七輪中沒有例外,也是我們判斷「還有沒有路可走」的依據 ——
目前可用的證據軸大致已經用盡,這正是誤併停在 5.6% 的原因。

### 5.2 誤併率的下降歷程

```
誤併率
 80% ┤
     │ ● 72%
 60% ┤ │  只有重疊鏡頭
     │ │  (4 人被併成 1 個身分)
 40% ┤  ╲
     │   ╲
 20% ┤    ╲___● 14.5%
     │        │ ＋地面校正       ● 5.6%  ＋軌跡證據(現況)
  0% ┤────────┴─────────────────┴──────────  ← 預算 1%
     └──────────────────────────────────────
       第六輪前     第六輪            第七輪
```

⚠ **這三個數字不是同一次執行的**:世界模型在輪次之間有改動,會改變隨機數流,
所以**跨輪的絕對值嚴格來說不可直接相比**。輪內的對照(第七輪 18.6% → 5.6%)才是受控比較。

## 6. 第七輪詳細數據

### 6.1 完整掃描網格(4 位廚師,地面校正 σ=0.1 m,全景鏡頭開啟)

格式:**碎裂率 / 誤併率**。τ_v = 人走路方向的持續性(速度自相關時間)。

| 軌跡觀測窗 | τ_v = 1.0s | τ_v = 3.0s | τ_v = 8.0s |
|---|---|---|---|
| **無軌跡(基準)** | 7.0% / **20.5%** | 7.3% / **18.6%** | 7.5% / **16.3%** |
| 0.5 秒 | 6.1% / 13.1% | 6.0% / 11.5% | 6.0% / 10.2% |
| **1.0 秒(建議)** | 5.3% / 7.8% | **5.2% / 7.9%** | 5.1% / 6.5% |
| 2.0 秒 | 5.4% / 6.7% | 5.2% / **5.6%** | 5.0% / **5.1%** |

8 位廚師時:無軌跡 29.1% → 軌跡窗 1.0 秒 **11.2%**。

### 6.2 軌跡證據比預期穩健 —— 對佈署是好消息

我們登記的預測是「效益依賴行走慣性,τ_v=1 秒(接近隨機遊走)時幾乎無效」。
實際上 τ_v=1 秒仍從 20.5% 降到 7.8%。

原因:我們比的是**同一瞬間**兩個人的速度,不是預測未來。
即使一個人的走法完全沒有慣性,兩個不同的人在同一瞬間的速度仍然不一樣。

> **因此不必先量測真實廚房的行走慣性才敢啟用這個功能。**

### 6.3 直接檢驗:軌跡證據到底解決了哪一類誤併?

第七輪登記的預測 1 是「效益集中在兩人相距 0.5 公尺以內那一類」。
我們寫了診斷腳本(`scripts/diag_merge_distance.py`),用同一組隨機種子只切換軌跡開關,
量出每次誤併發生時兩人的實際距離:

| 誤併時兩人距離 | 軌跡關 | 軌跡開 | 變化 |
|---|---|---|---|
| **< 0.5 公尺** | 198 | 38 | **−81%** |
| 0.5 ~ 1.5 公尺 | 0 | 4 | +4 |
| 1.5 ~ 3.0 公尺 | 9 | 3 | −67% |
| **> 3.0 公尺** | 32 | 57 | **+78%** ⚠ |

**預測成立** —— 近距離模糊正是被解決的那一類,證據接在該接的地方。

**但同時量到一個新的失效模式:**相隔 3 公尺以上、剛好朝同方向以相近速度移動的兩個人,
誤併反而增加了 78%(絕對量約佔全部轉場的 1.7%,被近距離的改善淹沒)。
軌跡證據不是只會幫忙。這是下一步該處理的東西 ——
位置已判定「不可能是同一人」時,不該讓速度翻案。

### 6.4 我們自己犯的錯:同一個數學錯誤犯了兩次

第七輪登記時算出「0.5 秒的觀測窗已經足夠」,實跑卻只降到 11.5%,而 1.0 秒降到 7.9%
—— 邊際效益完全沒有遞減。**預測被自己的實驗否證。**

根因:**比較兩個有噪聲的觀測時,差值的標準差是單次的 √2 倍。**
登記時用的是單次觀測的噪聲,系統性高估了鑑別力。

而這**不是第一次** —— 第六輪的地面校正證據犯過完全一樣的錯,當時修掉了,第七輪又犯一次。
高估鑑別力的後果是把真的同一個人判成「對不上」而拒絕綁定:
**修正前碎裂 9.5%,修正後 6.0%。**

已在程式碼中留下註解記錄這個教訓。連同第六輪與第七輪各一處登記時的算術失誤,
全部保留在文件裡,未回頭修改。

## 7. 佈署硬性規格

以下每一項都是實驗量出來的硬條件,不滿足就不必往下做。
這也是七輪實驗最有商業價值的產出 —— 它把「準不準」變成「在什麼條件下準」。

| 項目 | 規格 | 不滿足的後果 |
|---|---|---|
| **地面校正殘差** | **≤ 0.2 公尺** | **最關鍵的一項。**沒做的話 4 位廚師會被全部併成 1 個身分(誤併 72%,8 人時 85%)。殘差 ≥ 0.8 公尺時這條證據的資訊量低於判定門檻,**完全無用**。實測隨手標也能達到 0.08 公尺,不難 |
| **全景/廣角鏡頭** | 至少 1 台 | 俯瞰主要工作區。沒有它,系統只能猜「他走了幾秒」—— 前四輪所有失敗的共同根源 |
| **人在畫面中的大小** | ≥ 畫面高度 18% | 低於此偵測率掉到 0.88 以下。⚠ 要用畫面中**最遠最小**的那個人量,不是平均 |
| **推論解析度** | **1280** | 704 只能做到 26%,1280 可到 18% → **單台涵蓋面積翻倍**。系統是事後查詢用,不需即時,所以這個成本可接受 |
| **鏡頭時鐘同步** | 殘餘偏移 ≤ 0.2 秒 | 2 秒偏移會讓誤拒率從 18% 跳到 49%,而症狀是「一直開新身分」—— 現場看不出原因 |
| **視野重疊** | 盡量有 | 重疊 = 直接看到同一個人;不重疊 = 只能推測轉場時間,誤差大得多 |

### 7.1 全景鏡頭的能力邊界(不可誤解)

全景鏡頭**只負責「人」**。我們的實驗顯示人的偵測相當耐得住縮小
(縮到四分之一時 Recall 仍保有 **89%**),但刀具那類小物件會崩(僅剩 **11%**)。

> 所以**細節事件仍然需要近距鏡頭,這筆預算不能省**。全景鏡頭是身分的骨幹,不是萬用鏡頭。

### 7.2 證據的物理天花板:為什麼規格訂在這些數字

每一條證據能提供的資訊量都有數學上限,而綁定決策的門檻是 **1.61**(單位:nats)。
資訊量低於門檻的證據,再怎麼調參數都沒有用 —— 這就是規格數字的來源,不是拍腦袋訂的:

| 地面校正殘差 | 證據上限 | 判定 |
|---|---|---|
| 0.2 公尺 | 4.09 | ✅ 可用 |
| 0.4 公尺 | 2.70 | ⚠ 鑑別力下降 |
| 0.8 公尺 | 1.32 | ❌ 低於門檻,完全無用 |

| 軌跡觀測窗 | 證據上限 | 判定 |
|---|---|---|
| 0.5 秒 | 1.95 | ⚠ 勉強過門檻 |
| 1.0 秒 | 3.34 | ✅ 建議值 |
| 2.0 秒 | 4.72 | ✅ 最準,但身分指派延後 2 秒 |

軌跡證據的代價是**身分指派會延後約 1 秒**(要先累積速度)。
本系統的資料流是事後查詢、非同步寫入,所以可接受;
若日後有即時告警需求則需重新評估。

## 8. 交付給業主的驗收套件

業主手上只有平面圖,沒有我們的上下文。
所以交付物的設計目標是:**讓他們不需要理解演算法,也能自行量出可信的數字。**
共六個步驟,每一步都有「做完怎麼確認」的檢查點。

| 步驟 | 工具 | 業主要做的事 |
|---|---|---|
| 1 | 拓撲產生器 | 填一張表:哪台鏡頭走得到哪台、**步行路徑距離**幾公尺(繞過障礙,不是直線)、視野有無重疊。腳本自動換算成設定檔 |
| 2 | — | 每台鏡頭在地面挑 4 個以上不共線的點,量平面圖座標 + 讀畫面像素座標。**不用填精度參數** —— 系統自己從這些點算出標定殘差 |
| 3 | 設定自檢 | 還沒錄影就能跑。11 項檢查:拓撲填錯、單向連結、孤立鏡頭、轉場時間與追蹤模組衝突、時鐘容忍度、校正品質。**必須 0 個 ERROR 才能往下** |
| 4 | 走動測試記錄器 | 單一 HTML 檔,手機平板都能開、離線可用。2~3 人穿實際制服來回走 20 分鐘,進出畫面時按一下,匯出真值 CSV |
| 5 | 端到端執行 | 影片 → 偵測 → 追蹤 → 身分,輸出每次綁定決策的分數與候選數明細,可事後查「為什麼綁成這樣」 |
| 6 | 驗收評分 | 輸出 IDF1 / 碎裂率 / 誤併率,直接對照門檻。同時檢查「身分數 vs 實際人數」 |

詳細操作見 `docs/M5_業主驗收操作手冊.md`。

### 8.1 驗收門檻與它的來源

| 指標 | 門檻 | 依據 |
|---|---|---|
| **IDF1** | ≥ 0.90 | 身分保持的整體品質,國際標準指標,第三方認得 |
| **碎裂率** | ≤ 5% | 「未洗手」這類事件鏈約含 3 次跨鏡頭交接,要達 80% 召回 → 每次交接碎裂率須 ≤ 7.2%,留給偵測與追蹤的誤差預算後訂 5% |
| **誤併率** | ≤ 1% | 廚師每 2~5 分鐘跨一次鏡頭 → 8 小時班次 96~240 次決策。目標「每人每班身分污染少於 1 次」。因為靜默不可偵測,門檻嚴 5 倍 |

### 8.2 兩個「開了卻不生效、而且不報錯」的陷阱已補上防護

這類失效在本專案反覆出現,危險之處是**看起來一切正常**:

- 人的類別編號依權重而異(COCO 預訓 = 1,我們微調的 11 類 = 0)。
  接錯時**一個人都偵測不到,而且完全不報錯** → 已改為自動判斷,並在偵測數為 0 時明確提示
- 地面校正沒做時,舊版會偷偷套用一個預設精度值 —— 那個精度下證據幾乎沒有鑑別力,
  **但看起來是開著的** → 改為明確停用並記錄原因
- 軌跡證據開啟但沒做地面校正時完全不生效(速度是從地面座標算出來的)
  → 新增自檢項目,直接報 ERROR

## 10. 誠實說明:已知的限制

### 10.1 最大的缺口

> **誤併率約 5~8%,而食安追責所需的門檻是 1%。**

七輪下來從 72% 壓到 5.6%,但剩下這 5 倍缺口**目前沒有已知的演算法解**。
現有的證據軸(拓撲、時間、位置、方向、幾何、軌跡、外觀)大致已經用盡,
而七輪的規律說得很清楚:只有新的證據軸能帶來改善,重新分配既有信任不會。

### 10.2 若這個誤差不可接受,三條可行的補償路徑

| 手段 | 作法 | 預期效果 | 成本 |
|---|---|---|---|
| **下游補償** | 事件標上信心度;彙總報表註明誤差範圍;針對性調查時人工複核影片 | 不降低誤併率,但讓它**可見**而非靜默 | 最低 |
| **增加全景鏡頭** | 第二台不同角度的俯瞰鏡頭,消除單一視角的遮擋 | 未測,推估可再降三分之一 | 一台鏡頭 |
| **可辨識標記** | 帽子或圍裙上不同顏色色塊,或 AprilTag 之類的視覺標記 | **可望接近 0%** —— 把「認人」變成「認標記」 | 需人員配合 |

視覺標記路線沒有授權問題,也不涉及生物特徵個資,是三者中效果與風險比最好的一條。

### 10.3 其他必須說清楚的四點

1. **目前的準確率數字全部來自模擬,尚未用真實的多人資料校準。**
   世界模型的行走過程、步速、慣性都是設定值不是實測值。
   我們量到的是「每條證據值多少」與「在什麼條件下會壞」,不是絕對準確率。
   交付套件的步驟四到六就是為了取得那份資料 —— **業主的測試結果會用來修正這些預估。**
2. **跨輪的絕對數字不可直接相比。** 世界模型在輪次之間有改動,會改變隨機數流。
   輪內的受控對照才是有效比較,本報告中的 72% → 14.5% → 5.6% 是歷程敘述而非單次實驗結果。
3. **第五輪報出的數字已作廢**(質性結論仍成立),原因是 §4.1 的指標盲點。已在原始文件中標註,未刪除。
4. **新的失效模式已量到但尚未處理:**相隔 3 公尺以上、同方向同速度移動的兩人偶爾會被誤綁
   (約佔全部轉場的 1.7%)。
