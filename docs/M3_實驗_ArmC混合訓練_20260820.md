## 為什麼要跑這一臂

Arm B(分階段)的 null result 混了兩個無法分離的原因:「Roboflow 沒用」和「stage1 學到的東西被 stage2 的 60 epoch 洗掉了(catastrophic forgetting)」。

混合訓練沒有遺忘問題,Roboflow 的梯度全程存在。**如果這份資料真有價值,混訓比分階段更有機會顯示出來。**

## 設定

| | Arm A | Arm B | **Arm C** |
|---|---|---|---|
| 訓練資料 | EPFL 540 | Roboflow 40ep → EPFL 60ep | **EPFL train + Roboflow train 合併,一次訓** |
| train 圖數 | 360 | 360(+100 在 stage1) | **460** |
| train 框數 | 3394 | 3394(+160 在 stage1) | **3554** |
| 設定 | 60ep / 704 / bs4 / ga4 / lr1e-4 | stage2 同左 | **同左** |

- **valid / test 維持純 EPFL**(各 90 圖),三臂評估完全可比。
- 評估函式從原 notebook **逐字複製**(thr=0.3、IoU 0.5)。
- **A、B 未重訓**,直接引用 2026-08-10 的記錄值。
- 訓練耗時 **2h43m**(T4)。

## 結果

### Test 整體(EPFL test 90 圖,thr=0.3)

| | Precision | Recall | F1 |
|---|---|---|---|
| Arm A(EPFL-only) | 0.795 | 0.819 | 0.807 |

→ C 落在 A 與 B 之間,偏 A。**三臂全距只有 0.028 F1。**

## 兩個實質發現

### 1. 事前預測的「漏標污染」沒有發生 ❌

跑之前的預測是:Roboflow 圖裡大量物件沒標(`kitchenwoodcounter27` 畫面中央的砧板+食材完全沒框、`knife32` 一個框包住 4 把刀+砧板佔全圖 49.6%),DETR 的 Hungarian matching 會把未匹配的 query 推向 no-object,**應該會壓低砧板/食材/手**。

實測 val per-class AP@50:95,對照 Arm B:

| 類別 | Arm B | **Arm C** | 差異 |
|---|---|---|---|
| 砧板 | 0.727 | **0.754** | +0.027 |
| 食材 | 0.649 | **0.666** | +0.017 |
| 手 | 0.454 | **0.472** | +0.018 |
| 鍋鏟 | 0.744 | **0.764** | +0.020 |
| 抹布 | 0.849 | **0.874** | +0.025 |
| 人 | **0.867** | 0.851 | −0.016 |
| 鍋子 | **0.761** | 0.749 | −0.012 |

**沒有一個「受害類」被壓,反而全部微升。預測不成立。**

合理解釋:**訊號量太小**。Roboflow 佔 21.7% 的影像,但只佔 **4.5% 的標註框**;而真正有嚴重漏標的場景照只有 10 張(佔全 train 的 2%)。這個比例下,好處壞處都推不動指標。

> 這也修正了先前對這份資料的風險評估:標註品質確實差(79/100 張只有 1 個框,抽查 3 張全有缺陷),但**在這個混入比例下不足以造成可測量的傷害**。若 Roboflow 佔比拉高到 30~50%,結論可能不同。

### 2. 唯一一致的負面訊號:容器 ⚠

**容器是 Roboflow 貢獻最多的類**(137 / 160 框 = 86%),理論上最該受益。實測反而是三臂最差:

- test F1:A 0.856 → **C 0.838**(比完全不用 Roboflow 還低)
- 掉在 **precision**:0.841 → 0.811(−0.030),recall 幾乎沒動(0.872 → 0.866)

precision 掉 = **誤報變多**,符合「學了商品照/白底特寫的容器外觀 → 在真實廚房場景亂開火」。416×416 拉伸圖上採樣到 704 也會加劇這個問題。

⚠ **但 val 沒有複製這個訊號**(C 的容器 val AP 0.777,反而是三臂最高)。所以這是單一數據點,不能斷言。

---

## 結論:三臂全部打平

- **test F1 全距 0.028**(0.807 / 0.835 / 0.814),test 只有 90 圖,±2~3 分本就在雜訊範圍。val 上三臂互有勝負,沒有一致方向。
- **混合訓練沒有比分階段好**。原本「混訓能避開遺忘、更有機會顯示價值」的假設,實測不成立 —— 因為根本沒有價值可以顯示。
- **算力還不對等**:C 的 60 epoch 跑 460 張,比 A 多約 28% 的 step 數,拿了這個便宜仍沒贏過 B → **更說明這份資料的影響 ≈ 0**。
- Arm B 的 null result 現在可以確定**不是**被遺忘造成的。三種接法(不用 / 分階段 / 混訓)結果一樣。

### 採用建議

**維持 Arm A(純自標資料),最單純。** Roboflow 保留作為可商用授權素材(見 [資料集_Roboflow廚房_說明_20260820.md](資料集_Roboflow廚房_說明_20260820.md)),但**訓練上不必納入** —— 三種混法都證明沒有增益,還多一份標註品質不可控的相依。

這與 2026-08-10 的結論一致,並且更強:**提升模型的關鍵是標註貼近實際場景的資料,不是混入更多不相關的公開資料。**
