### 1.1 排除 camera_5 / camera_6 的理由

那兩台對著玻璃面,人影倒影會被偵測器框成人,佔「幾乎不碰到人」那類誤偵的 **80.2%**;
逐片段實測誤偵框比例中位 19.4%,其他鏡頭 1.1%(17 倍)。
依 2026-09-28 的決定:**M4 的訓練與測試一律排除這兩台**,M5 跨鏡頭維持 7 台並標註受影響的數字。

## 2. 主結果:再取得率

**定義**:人消失又出現,出現後拿到的編號與消失前是否相同。
**分母**:間隔兩側都有綁定的事件數,13 段共 **14 個事件**。

| 設定 | 再取得率 | 事件 | 95% 區間 |
|---|---|---|---|
| 外觀關閉(基準) | **7.1%** | 1 / 14 | 0.013 – 0.315 |
| armS0 · w = 0.2 | **21.4%** | 3 / 14 | 0.076 – 0.476 |
| **DINOv2 · w = 0.5** | **100%** | **14 / 14** | **0.785 – 1.000** |

**DINOv2 的區間下界 0.785,與基準的上界 0.315 完全分離。**
以 14 個事件的樣本而言,這個差距不是雜訊。

### 3.1 兩個關鍵的交叉驗證

1. **IoU 三格幾乎不動**(0.9152 / 0.9138 / 0.9127),而召回率反而上升。
   → 框一直貼在人身上,**改善來自身份判斷,不是框位移動**。
   這排除了「框變寬所以看起來連續」這個替代解釋。
2. **編號被誤偵佔用比例三格皆為 0**。
   → 改善不是靠把編號掛到誤偵框上換來的。

## 5. 設定

| 項目 | 值 | 說明 |
|---|---|---|
| 相似度 | `(1−w) × 框重疊 + w × 外觀` | 外觀 = `0.5 × (1 + 餘弦)`,映射到與 IoU 同尺度 |
| 外觀模型 | DINOv2-S(384 維) | Meta,**Apache-2.0,可商用** |
| 權重 w | 0.5 | **只從推導集 seq_000/001/002 估**,評估集未參與 |
| 套用階段 | 僅第一輪關聯(`_sim_high`) | 低信心偵測的裁圖品質差,不採用 |
| track 特徵更新 | EMA,動量 0.9 | BoT-SORT 標準值,未調整 |
| 追蹤器基底 | `rf_mcbyte_nomask` | w=0 時與其**逐位相同**(6/6 檔案 sha256 一致) |
| 跟丟緩衝 | 30 次更新 = 5 秒 | 涵蓋本批片段 1.1–4.9 秒的間隔 |
| 對照組 | `w = 0`(完全不呼叫 embedder) | 不是 `rf_cbiou` —— 見下方註 |

⚠ **對照組的選擇**:`AppearanceMcByteTracker` 繼承的是 `DCMMcByteTracker`(McByte 無遮罩版),
不是 C-BIoU。所以 `w = 0` 的歸零點是 `rf_mcbyte_nomask`,用它當對照才是乾淨的單變數比較。
逐位比對已驗證(推導集 6/6 檔案 sha256 相同)。

### 5.1 相容性

- `scripts/m5_track_video.py` 原本沒有傳 `frame=`,McByte 系列會直接丟例外。
  已加 `KitchenTracker.needs_frame`,只在需要時付 BGR→RGB 的轉換成本。
- **V0 回歸**:交付設定(`rf_cbiou`)重跑兩段,`tracks.csv` / `track_events.csv` /
  `chef_events.jsonl` 全部 sha256 **逐位相同** —— 交付路徑未被改動。

## 6. 這份結果不能推論到哪裡

| 邊界 | 依據 |
|---|---|
| **多人同場:已實測會變糟** | 在 5 台鏡頭 × 7 個完整序列的**多人**資料上,同一組 DINOv2 w=0.5 設定讓**混雜 track** 從 **14.3%** 升到 **64.5%**。混雜 track = 同一個編號被戴到兩個不同的真人身上(見 §9.13)。本文件 13 段皆為獨佔片段,畫面裡沒有第二個人,這個代價在此**結構上量不到**。 |
| **跨鏡頭:增益為 0** | L3S 跨鏡頭一致率三格皆為 **5/16**,L3T 皆為 **0/5**,逐段查證 12 段中 **0 段**有變動。外觀只用在同一台鏡頭的關聯成本裡,跨鏡頭綁定由 M5 決定,而本批 M5 未啟用外觀(見 §9.14)。 |
| **樣本規模** | 再取得的分母是 **14 個事件**,一個事件等於 7.1 個百分點。連續率的分母較大(539 個取樣格),區間也較窄。 |
| **現場會更差** | CHIRLA 每個人衣著不同;廚房為**同款制服加口罩**,外觀的鑑別力會明顯低於此處。**本文件數字是上界。** |
| **預先登記判準未通過** | 2026-09-28 的預先登記以 5 台多人序列的 IDF1 與 ID 切換次數為判準,兩格皆未通過(見 §9.5)。本文件是在較窄範圍內的另一組量測,**不取代該判定**。 |
| **w 仍在範圍邊界** | 推導集掃描到 w = 0.5 時 IDF1 仍在上升,但登記寫死掃到 0.5,事後不得延長範圍。 |

## 7. 結論

**在單鏡頭、單人、走出畫面後數秒內返回這個情境下,把外觀特徵加進 M4 的關聯成本是可行的。**

- 身份相關的四項指標全部大幅改善,再取得率的信賴區間與基準完全分離。
- 偵測與定位維持不變(IoU 0.915 → 0.913,召回 93.3% → 97.3%),證明改善來自**身份判斷**而非框位移動。
- 代價是誤偵框比例上升 **7.0 個百分點**(14.1% → 21.1%)。

要把這個結論擴大到**多人**或**跨鏡頭**,需要另外的證據 —— 目前手上的證據指向相反方向(§6)。
