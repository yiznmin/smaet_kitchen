## 0. 關於 w = 0.7 的選定方式(先講)

本文件以 **w = 0.7** 為主結果。這個值**不是**預先登記選出來的,必須照實說明:

| 事實 | 內容 |
|---|---|
| 預先登記的掃描範圍 | `w ≤ 0.5`(§3.1 寫死),而推導集在上界仍在上升 |
| 延伸掃描 | 2026-09-29 應使用者要求把範圍延伸到 **1.0**,兩組資料各掃一次 |
| 推導集上的排名 | w=0.7 的 IDF1 **0.7420**,是**第二高**(最高是 w=1.0 的 0.7632) |
| 為何不選 w=1.0 | 它在 L2 上**崩潰**(連續率 0.7342),且 IDSW 衝到 455(基準 264) |
| 紀律上的合法選擇 | 加「IDSW ≤ 264」約束後會選到 **w=0.6**(IDF1 0.7365) |
| w=0.7 被排除的理由 | IDSW **280 > 264**(多 16 次,推導集共 539 秒) |
| **選定 w=0.7 的實際依據** | **看過 L2 結果後決定**(0.9963 vs w=0.6 的 0.9278) |

⚠ **這是事後選值(evaluation-informed),不是預先登記的驗證結果。**
要把 w = 0.7 當成正式結論,必須另立一份預先登記,把「IDSW 可放寬到多少」先寫死再跑。
本文件的數字是真實量測,但**選值程序不符合本專案的預先登記紀律**,引用時要一併說明。

支持 w=0.7 不是雜訊的證據:**w = 0.7 / 0.8 / 0.9 三格數字完全相同**(平坦高原),
且 w=0.7 在**推導集**的 IDF1 也高於 w=0.6。詳見 §10。

## 2. 主結果:再取得率

**定義**:人消失又出現,出現後拿到的編號與消失前是否相同。
**分母**:間隔兩側都有綁定的事件數,13 段共 **14 個事件**。

| 設定 | 再取得率 | 事件 | 95% 區間 |
|---|---|---|---|
| 外觀關閉(基準) | **7.1%** | 1 / 14 | 0.013 – 0.315 |
| armS0 · w = 0.2 | **21.4%** | 3 / 14 | 0.076 – 0.476 |
| **DINOv2 · w = 0.7** | **100%** | **14 / 14** | **0.785 – 1.000** |

**DINOv2 的區間下界 0.785,與基準的上界 0.315 完全分離。**

### 2.1 這個 100% 是真的(w = 0.5 時不是)

再取得的判準是「**間隔前後編號是否相同**」,它不檢查那個編號**對不對**。
身份若在間隔**之前**就已經翻掉並穩定下來,前後兩側都會是那個錯誤編號 → 仍判成功。

實際檢查(再取得判成功,但該段結尾的編號 ≠ 第一次綁到的編號 `c0`):

| 設定 | 假成功的段數 |
|---|---|
| 外觀關閉 | 0 段 |
| armS0 w=0.2 | **1 段**(`seq_000-c1-3-003910`,c0=1 → 結尾=3) |
| DINOv2 w=0.5 | **1 段**(`seq_025-c3-7-007115`,c0=1 → 結尾=2) |
| **DINOv2 w = 0.7** | **0 段** |

**w = 0.7 沒有假成功,14/14 全部是真的。**
`seq_025-c3-7-007115` 正是 w=0.5 時那段假成功的片段,w=0.7 把它修好了
(連續率 **0.328 → 0.966**)。

## 7. 指標怎麼算

全部實作在 `src/common/clip_metrics.py`(335 行),本節逐項對應到程式。
**所有率都只有一條計算路徑** —— 先產生逐幀列,再從那份列算出所有純量,
不存在「第二種算法」可以挑。

### 7.1 資料流

```
三個輸入
  gt      {鏡頭: {真值幀(1-based): [(gt_id, bbox)]}}     ← 資料集標註
  tracks  {(鏡頭, fid): [(track_id, bbox 或 None)]}      ← M4 輸出,None = 空轉
  chefs   {(鏡頭, track_id): chef_id}                    ← M5 綁定
      ↓  per_frame_rows()
逐幀列(每個「鏡頭 × 取樣幀」一列,含目標不在場的格)
      ↓  iou_stats / identity_rates / switches / ghost_stats / l2_reacquire
純量指標
```

⚠ **目標不在場的格也要留**,L2 的間隔與誤偵都靠它才算得出來。
⚠ 真值幀是 1-based、`fid` 是 0-based,對應關係固定為 `gt_frame = fid + 1`。

### 7.2 逐幀配對(所有指標的共同基礎)

`assign_frame()`:

1. 取該幀**所有**真值框與**所有**有框的 track(空轉的 track 不參與)。
2. 算出 IoU 矩陣,`IoU = 交集面積 / 聯集面積`。
3. 用匈牙利演算法(`scipy.optimize.linear_sum_assignment`)求**全域最佳**配對。
4. 只保留 **IoU ≥ 0.50** 的配對;低於門檻的視為沒配到。

⚠ **配對前先依 `gt_id` / `track_id` 升冪排序**。平手時匈牙利的選擇取決於矩陣順序,
不排序的話同一份資料兩次執行可能得到不同配對。

### 7.3 兩個分母(寫死,不可換)

| 記號 | 定義 | 用在哪 |
|---|---|---|
| **T** | 目標**有標註框**的取樣格數 | 召回率、IoU 統計 |
| **B** | 目標**被配對且該 track 有編號**的格數 | 三個身份率 |

`T ≥ B`。兩者的差距由「沒配到」與「配到但沒編號」兩部分構成,兩者分開報。

### 7.4 各指標的算法

| 指標 | 公式 | 分母 | 註 |
|---|---|---|---|
| **目標召回率** | 配到目標的格數 / T | T | 只看目標,不看別人 |
| **IoU 平均(配對成功者)** | 配到的那些格的 IoU 平均 | 配到的格數 | 本文件用的是這個 |
| （IoU 平均,含未配到） | 同上但未配到記 0 | T | 較保守,本文件未採用 |
| **IoU ≥ 0.75 比例** | IoU ≥ 0.75 的格數 / T | T | 未配到記 IoU = 0,故算失敗 |
| **綁定率** | B / 配到目標的格數 | 配到的格數 | 配到了但 M5 沒給編號的比例 |
| **連續率** | 編號 == `c0` 的格數 / B | B | `c0` = **第一次綁到的編號** |
| **多數率** | 編號 == `c*` 的格數 / B | B | `c*` = 出現最多次的編號,平手取較小者 |
| **排他率** | 「同一幀沒有別人戴著目標這格編號」的格數 / B | B | 獨佔片段回 `None`,**不可回 1.0** |
| **編號切換次數** | **逐鏡頭沿時間**數相鄰兩格編號不同的次數,再相加 | — | 見 7.5 |
| **track 切換次數** | 同上,但比的是 `track_id` | — | M4 層的斷點 |
| **不同編號個數** | B 那些格出現過的相異 `chef_id` 個數 | — | 理想值 = 片段數 |
| **誤偵框比例** | 沒配到任何真值的框數 / 系統畫出的框總數 | 畫出的框總數 | **= 看影片時數得到的比例** |
| **誤偵 track 比例** | 窗內配對率 < 0.5 的 track 數 / 窗內 track 總數 | 窗內 track 數 | 配對率只在**窗內**算 |
| **編號被誤偵佔用比例** | 同一幀另有一個框也戴著 `c*` 的格數 / B | B | 抓「編號被誤偵搶走」 |

### 7.5 ⚠ 編號切換為何要逐鏡頭算

2026-09-24 使用者指出「L2 怎麼會有 1,400 多次切換」。查證後是**定義寫錯**:
原本把所有鏡頭的格子依 `(fid, camera)` 混在一起排序後數相鄰變化,
對**多鏡頭片段**量到的其實是「兩台鏡頭彼此不一致」,不是「身份隨時間改變」。

實例:`L3S-seq_004-c6+c7-8-008115` 的 camera_7 全程編號 1、camera_6 全程編號 3,
逐鏡頭各 0 / 1 次切換,混排後卻報 **359 次**。

→ 主數字改為 **`chef_switches`(逐鏡頭沿時間算再相加)**。
**單鏡頭片段兩者相同**,所以本文件的 L2 數字不受此更正影響。

### 7.6 L2 再取得率怎麼判

`l2_reacquire(rows, appearances, k=5)`:

1. 依標註的「出現區段」把逐幀列切成數段。
2. 每一對相鄰區段:
   - **間隔前** = 前段**最後 k 個**有綁定格的多數編號
   - **間隔後** = 後段**最前 k 個**有綁定格的多數編號
3. 兩者相同 → 記一次成功。
4. 任一側沒有綁定格 → **該對排除**,計入 `n_pairs_dropped`,不計入分母。

本文件同時報 **k=5** 與 **k=1**,兩者結果相同。

⚠ **這個判準比的是「間隔前 vs 間隔後」,不是「對不對」。**
身份若在間隔**之前**就已經翻掉並穩定下來,前後兩側都會是那個錯誤編號 → 判成功。
§2.1 已逐段檢查過:**w = 0.7 沒有這種情形**。

### 7.7 Wilson 95% 區間

```
p = k / n
d = 1 + z²/n                    (z = 1.96)
中心 = (p + z²/2n) / d
半寬 = z · √( p(1−p)/n + z²/4n² ) / d
區間 = [max(0, 中心 − 半寬), min(1, 中心 + 半寬)]
```

用 Wilson 而不是常態近似,是因為本輪很多分母極小(L2 再取得只有 14),
常態近似在 p 接近 0 或 1 時會給出超出 [0,1] 的區間。

### 7.8 彙總怎麼加總

**一律彙集逐幀列後再算一次**,不是「先算每段的率再平均」。

```
彙集:  率 = Σ(各段分子) / Σ(各段分母)
逐段平均(未採用):  率 = mean(各段的率)
```

逐段平均會讓 3 秒的片段與 29 秒的片段權重相同,而本批片段長度差 9 倍。

### 7.9 三個身份率的關係(最容易誤讀的地方)

- **連續率**與**多數率**都**無法否證**「整段被綁成同一個錯誤編號」——
  那種情況下兩者都是 100%。
- 能否證它的只有**排他率**,但排他率需要窗內有第二個真人。
- **窗內只有一個身份時,排他率結構上不可量測** → 回 `None`,印「不可量測」,
  **不可印 100%**。

本文件 13 段皆為獨佔片段 → 排他率全部不可量測。這就是 §6 第一條邊界的來源。

**連續率是主指標、多數率是輔助**:2026-09-24 使用者指出「我們要量測的是
一開始編號他連續的狀態,而不是錯誤的連續也算的正確」。

## 11. 結論

**在單鏡頭、單人、走出畫面後數秒內返回這個情境下,把外觀特徵(DINOv2,w = 0.7)
加進 M4 的關聯成本是有效的。**

- 再取得率 **7.1% → 100%(14/14)**,且**沒有假成功**(w=0.5 有 1 次)。
- 連續率 **37.5% → 99.6%**:540 個綁定格裡只有 2 格編號是錯的。
- 13 段中 **12 段連續率剛好 1.000**,第 13 段 0.966。
- 偵測與定位維持不變(IoU 0.915 → 0.913,召回 93.3% → 97.5%),
  證明改善來自**身份判斷**而非框位移動。
- 隔離後的**外觀淨貢獻**是連續率 **+0.2356**、再取得 +1 個事件,代價近乎零(§9)。
