# M6 人—物關聯:文獻方法調研(2026-10-19)

> 目的:查清楚「人(手)與物品的關聯」在學界 / 業界一般怎麼建立、怎麼評估,
> 對照我們 M6 第一輪的做法,決定哪些可以直接採用、哪些留作升級、哪些不適用。
> 約束(`original_info/智慧廚房系統_專案說明.md` §E):集中式版本**不引入 LLM / VLM**,事件判斷用可解釋規則。
> 本文數字皆引自各論文自述,未在本專案重現。

## 1. 方法總覽(五大類)

| 類別 | 代表作 | 怎麼建立關聯 | 需要的訓練資料 | 對我們的適用性 |
|---|---|---|---|---|
| A. 幾何規則 | 100DOH 的 Simple Baseline;MECCANO 的距離門檻 | 先各自偵測手與物件,再用框中心距離 / 距離門檻配對 | 只要偵測器 | **就是 M6 第一輪的做法**,可直接用 |
| B. 手部接觸狀態分類 | 100DOH hand_object_detector(Shan 等,CVPR 2020);ContactHands(NeurIPS 2020) | 偵測器對每隻手多輸出「接觸狀態」與「指向被接觸物件的偏移向量」 | 手框 + 接觸狀態標註(公開資料集已有) | **升級候選**:當作額外證據,過濾「手只是靠近物件」 |
| C. 影像 HOI 偵測 | 兩階段:iCAN、UPT、PViC;一階段:CDN 等;HO-RCNN 的 Interaction Pattern | 兩階段:先偵測人與物,再對每一對分類互動動詞;一階段:直接輸出〈人, 動詞, 物〉三元組 | 〈人, 動詞, 物〉三元組標註(HICO-DET、V-COCO) | 第一輪不當主線;可做對照實驗(§3.5) |
| D. 影片 HOI(時序) | ST-HOI / VidHOI | 把人與物的**軌跡**、姿態、局部特徵一起當輸入;強調單幀猜不出時序動作 | 影片 HOI 標註 | 觀念可借:時序平滑、軌跡;模型本身不採用 |
| E. 動作分段 | EPFL-Smart-Kitchen-30 的基準(MS-TCN++、C2F-TCN 等) | 不做配對,直接把整段時序分類成動作 | 逐幀動作標註 | 評估方式可借;不是關聯方法 |

另外一條線(食安應用面):

| 類別 | 代表作 | 做法 |
|---|---|---|
| F. 洗手合規 | Purdue 商用廚房洗手偵測(J. Imaging 2021);Food Control 工廠洗手 / PPE 系統;Fujitsu Actlyzer | 單用 RGB CNN 在未剪輯廚房影片表現差 → 改用 RGB + 光流 + 手部遮罩 + 骨架的階層式系統;業界產品則檢查洗手步驟 |

## 2. 各類的重點發現

### A. 幾何規則(我們這輪的做法)

- **100DOH 的 Simple Baseline**:用一般偵測器分別偵測手與物件,把每隻手配給框中心最近的物件,理由是「被操作的物件通常靠近手」。
  論文的學習式方法在同一批偵測到的手框上贏過這個基準線 → 規則法是**公認的基準線**,不是錯的方法,但有上限。
- **MECCANO(工業場景第一人稱)**:以平均距離當門檻區分 active / passive 物件,AP 33.33%;**拿掉門檻反而 38.14%**。
  → 對我們的警示:**單靠距離門檻可能比不用門檻更差**;要靠時序平滑或接觸狀態補強,並且一定要報「不用距離」的基準線(我們的 base_person / base_present 就是在檢驗這件事)。

### B. 手部接觸狀態分類

- **100DOH hand_object_detector**(Faster R-CNN、ResNet-101):每隻手輸出位置、左右手、接觸狀態(無接觸 / 自我接觸 / 接觸他人 / 接觸可攜物件 / 接觸固定物件)、
  以及指向被接觸物件框的偏移向量。資料集 100K 幀標註。程式碼公開(GitHub ddshan/hand_object_detector),依賴舊版 PyTorch(1.12 / CUDA 11.3)。
- **ContactHands**(Narasimhaswamy 等):四種接觸狀態(無 / 自我 / 他人 / 物件),用兩個注意力模組把手和周圍可能接觸的區域關聯起來;
  約 21K 張影像,聯合手部偵測 + 接觸狀態 mAP 約 57%。程式與資料公開(cvlab-stonybrook/ContactHands)。
- **Lu 等(第一人稱)**:用手部姿態 + 手物遮罩判斷是否互動,EPIC-KITCHENS 選定影像上 89%(100DOH 為 92%),但速度 30+ FPS(100DOH 1–2 FPS)。
- ⚠ 兩個資料集與權重的**授權是否允許商用尚未查證**,採用前要查。

### C. 影像 HOI 偵測

- 兩階段(先偵測再配對分類)可解釋性較好,但會繼承第一階段偵測的錯誤、配對列舉效率差;一階段速度較快。準確度上**兩者沒有明顯優劣**(綜述結論)。
- 2026 年的失效模式研究指出:兩階段模型在**多人、共用物件**的場景容易出錯,基準上的高分不代表真的理解人物關係 —— 正好是真實廚房(多廚師)的情境。
- 另有 training-free、靠多模態大模型的 HOI 方法 → **違反不用 VLM 的約束,不考慮**。

### D. 影片 HOI

- ST-HOI 的主張:有些互動(拿起 vs 放下)單幀無法判斷,把靜態影像 HOI 方法直接套到影片只是在猜;
  它的做法是把人與物件的軌跡、姿態特徵一起餵進模型。VidHOI 上約 17.6 mAP,整體仍低。
- 對我們的啟示:時序資訊必要 → 第一輪已有遲滯平滑;之後若要分「拿 / 放 / 持有」需要物件軌跡(M4 的物件追蹤)。

### E. EPFL 自己的基準

- EPFL-Smart-Kitchen-30:16 位受試者、29.7 小時、每分鐘 33.78 段動作。動作分段基準用身體 / 手部姿態或 VideoMAE 特徵,
  模型為 MS-TCN++、EDTCN、C2F-TCN 等,**評估指標是逐幀 F1、F1@50、edit distance**;作者表示這個基準對現有演算法仍有挑戰性。
- 這是我們能對齊的社群評估方式(見 §3.2)。

### F. 洗手

- Purdue 的經驗:單純 RGB 分類在真實廚房效果差,需要多模態(光流、手部遮罩、骨架)與階層式設計。
- Fujitsu 指出洗手時雙手重疊、起泡會遮住關鍵點 → 洗手的「步驟正確性」很難;**我們下一輪只判「有沒有在洗手台停留夠久」**,難度低很多。
- 資料多為各團隊自有資料集,數字不可外推到別的廚房。

## 3. 對 M6 的結論與做法

### 3.1 第一輪(進行中)維持不變的部分

- 「偵測手與物件 → 幾何配對 → 時序平滑」= 文獻上的標準基準線(A 類)+ 影片 HOI 的時序觀念(D 類),方向正確,且完全可解釋。
- 兩條基準線(畫面有物件、物件與人框 IoA)要保留:MECCANO 顯示距離門檻不一定有幫助,必須實測證明「用手」比較好。

### 3.2 建議補進預先登記的評估項(還沒 commit,可以加)

- **逐段 F1@τ(τ = 0.1、0.25、0.5)**:與 MS-TCN / EPFL 基準的 F1@50 同一套定義(預測段與 GT 段時間 IoU ≥ τ 且一對一配對)。
  現有的「覆蓋比例」定義保留為主指標,F1@τ 當對外可比較的輔助指標。

### 3.3 升級路線(第一輪結果出來後,依誤差來源決定)

| 若第一輪的主要錯誤是… | 升級方向 | 依據 |
|---|---|---|
| 手沒偵測到 / 手框位置不準 → 漏報 | 改用全身姿態估計的手腕 / 指尖關鍵點代替手框 | Lu 等、ST-HOI 都用姿態特徵 |
| 手靠近但沒拿(經過、旁邊放著)→ 誤報 | 加手部接觸狀態分類當第二道證據(100DOH 或 ContactHands 類) | B 類 |
| 偵測正確但規則本身不夠 | 用 EPFL 3D 手部姿態投影做上限實驗,先量規則的天花板 | 交接單 §4.4 |
| 物件類別對、但分不出拿 / 放 / 持有 | 需要物件軌跡(M4 物件追蹤)+ 時序規則 | D 類 |
| 要像素級的「刀在生肉上」 | M7 的 SAM 2 遮罩重疊(專案原本規劃) | 專案說明 §B M7 |

### 3.4 不採用

- 任何以 LLM / VLM 判斷互動的方法:違反集中式版本的約束。

### 3.5 HOI 偵測器(C、D 類):不是不能用,是第一輪不當主線

專案約束是不用 LLM / VLM,**沒有禁止學習式模型**;HOI 偵測器的輸出可以當 M6 規則的一條證據。
第一輪不用它當主線的理由(皆為推論,尚未實測):

| 理由 | 說明 |
|---|---|
| 類別對不上 | 公開 HOI 模型多在 HICO-DET / V-COCO 上訓練,物件是 COCO 80 類:有刀、碗、瓶子,**沒有砧板、平底鍋、鍋鏟、番茄、抹布、夾子、手套**。我們 7 個計分類別大多不在裡面 |
| 重訓要的標註我們沒有 | 要涵蓋我們的類別得重訓,需要逐幀的〈人框, 動詞, 物件框〉。EPFL 只有「時間段 + 動詞 + 名詞」,沒有框 |
| 視角差距 | HICO-DET 多是近拍網路照片;我們是天花板遠距視角、手很小。能不能轉移要實測 |
| 不易歸因 | 黑盒輸出錯了時,分不出是偵測錯還是關聯錯;規則法每條關聯都記證據,可以逐條追 |
| 影片 HOI 的前提 | ST-HOI 要人與**物件**的軌跡,我們的 M4 只追蹤人;它在 VidHOI 上約 17.6 mAP,整體仍低 |
| 授權未查 | HICO-DET 資料與各模型權重能否商用,尚未查證 |

**可做的對照實驗**(不影響第一輪):拿公開的 HOI 偵測器權重(UPT / PViC),只比 COCO 有的類別(刀、碗、瓶子),
在 EPFL 同一套真值與指標上和規則法比。贏了 → 列為證據來源;輸了 → 這段推論有了實測依據。

### 3.6 名詞解釋:影像 HOI 與影片 HOI 是什麼

HOI = Human-Object Interaction(人—物互動)。輸出是一組組「三元組」:**〈人框, 動作, 物件框〉**,
例如〈人, cut_with, 刀〉、〈人, hold, 碗〉。跟我們 M6 要的東西本質相同,差在「規則算」還是「模型學」。

| | 影像 HOI | 影片 HOI |
|---|---|---|
| 輸入 | 單張影像 | 一段影片 |
| 輸出 | 這一張裡的〈人, 動作, 物〉 | 帶時間的〈人, 動作, 物〉,能分「拿起 / 放下 / 持有」 |
| 代表作 | iCAN(2018):兩階段,先偵測人與物,再用「以人為中心的注意力」對每一對分類動作<br>UPT(2022)、PViC(2023):同樣兩階段,建在 DETR 偵測器上,用 Transformer 讓人—物配對互相參考,並加入兩框相對位置的空間資訊 | ST-HOI(2021):在影像 HOI 上加入時間,把人與物件的**軌跡**、人體姿態一起餵進模型 |
| 常用訓練資料 | HICO-DET:約 4.7 萬張影像,80 類物件 × 117 個動詞(600 種組合);V-COCO | VidHOI(建在 VidOR 影片資料集上) |
| 與 M6 規則法的關係 | 規則法用「手與物件的距離」人工定義關聯;HOI 模型從標註資料學出「怎樣算互動」 | 對應我們的「遲滯平滑」,但改由模型從軌跡學時序 |

### 3.7 做 HOI 對照實驗需要追加的人工標註

依投入由小到大分三級:

| 級別 | 做什麼 | 要追加的人工標註 | 估計工作量 |
|---|---|---|---|
| **A. 直接用公開權重**(建議先做) | UPT / PViC 的 HICO-DET 權重直接跑 EPFL,只比刀、碗、瓶子(容器) | **不用新標註**。沿用 EPFL 動作標註當真值;只需定一張「HICO 動詞 → 是否算接觸」對照表(hold、cut_with、carry、wash… 算接觸) | 對照表 < 1 小時 |
| **B. 用我們的類別微調** | 讓 HOI 模型認得砧板、鍋子、鍋鏟、食材、抹布 | 逐幀的「人—物配對」標註:**人框、物件框、這一對有沒有接觸(可再加動詞)**。<br>捷徑:M3 round2 的 540 張圖**已經有框**,只要對每張圖的每個「人—物件」配對點「接觸 / 未接觸」 | 540 張 × 平均約 7 個物件 ≈ 3,800 個配對;另需從**其他場次**補圖 —— s1(270 張)就是 YH2040,拿來訓練會汙染開發集 |
| **C. 影片 HOI** | ST-HOI 類模型 | 物件**跨幀追蹤框**(同一把刀在每一幀的框與 ID)+ 每一對的接觸起訖時間 | 最貴;且我們的 M4 不追蹤物件。**不建議** |

**B 級的附帶好處**:EPFL 真值是「這個時間有接觸」,不分鏡頭;某鏡頭被遮住時,單視角一定漏,目前無法區分「規則錯」還是「這台本來就看不到」。
B 級的逐幀、逐鏡頭配對標註同時就是 M6 規則法缺的**逐鏡頭真值**。即使不做 HOI 微調,
先標一小批(例如 2 個鏡頭 × 150 幀)也能用來評估規則法本身。
