# M5 廚師身份管理(Re-ID)— 階段總結(2026-08-12)

> M5 = 把 M4 的本地 `track_id` 綁成全域 `chef_id`(跨鏡頭認出「同一位廚師」),供 M6 判事件。
> 本份總結 M5 這一階段的歷程、關鍵發現、決策與產出。**核心結論:改用「空間+時序為主、外觀為輔」的 Camera Link Model,全可商用。**

---

## 1. 三階段歷程與結論

| 階段 | 做了什麼 | 結論 |
|---|---|---|
| **① 邏輯層** | 建 IdentityManager(gallery/餘弦/TTL/跨鏡頭)+ 合成驗證 S1–S4 | ✅ 綁定邏輯正確 |
| **② 外觀實測**(EPFL 6 身份) | DINOv2(可商用) vs OSNet(Re-ID 專用)比 Rank-1/綁定 | DINOv2 **11%** ❌;OSNet **93%** ✅ 但**權重研究限定不可出貨** |
| **③ 空間+時序 v2** | Camera Link Model:時空為主、DINOv2 外觀為輔 + 合成驗證 S1–S6 | ✅ 邏輯通過;**外觀弱(0.15)也靠時空綁對**;全可商用 |

**②的翻轉**:同一批俯視廚房資料,OSNet 93% → **不是「域」的問題,是「通用模型不夠、Re-ID 專用可行」**。但能出貨的 DINOv2 不夠好、夠好的 OSNet 不能出貨 → 走 ③。

## 2. 決策圖

```
                能不能用「外觀」認出同一位廚師?
                              │
         ┌────────────────────┼────────────────────┐
   DINOv2(可商用)        OSNet(Re-ID專用)       純外觀出貨?
   Rank-1 11% ❌          Rank-1 93% ✅            兩難:
   → 通用特徵不夠         但權重研究限定 ❌         好的不能賣、能賣的不好
                              │
                              ▼
        ✅ 決策:Camera Link Model(空間+時序為主、外觀為輔)
        ───────────────────────────────────────────────
        時空門先把候選縮到 1–2 個  →  外觀(DINOv2)只需破平手
        → 整條無研究限定元件、可出貨;制服相同也適用(外觀更弱、時空照扛)

   出貨用更強外觀時:自訓 OSNet(架構 MIT + 自錄乾淨資料),把 w_app 調高即可
```

## 3. 資料流圖(M5 v2)

```
每台相機:M3 偵測(人) → M4 追蹤(ByteTrack)
   │  事件 + (camera_id, track_id, bbox, frame)
   ▼
SpatioTemporalIdentityManager（src/m5_reid/identity_st.py）
   ├ on_track_lost → 記出口(cam, 時間)進 recently_disappeared
   └ on_new_track  → ① which_zone 判入口
                     ② CameraTopology.transition_gate:有連結? Δt 在高斯時間窗?
                     ③ fused = 0.7·時空 + 0.3·外觀(DINOv2 cosine) ≥ 0.35 → 綁 chef_id
   │
   ▼
chef_id  →  M6 事件判斷(同一廚師停留超時 / 未洗手 / 跨區污染;配 zones)
```

四線索(Camera Link Model):**相機拓撲 + 轉場時間高斯 + 移動方向 + 外觀(輔助)**。

## 5. 誠實限制與授權

| 項目 | 狀態 |
|---|---|
| M5 邏輯 + 時空 v2 | ✅ 合成驗證通過 |
| **真實跨站準確率** | ⬜ **待自錄多人跨站資料**(2–3 人、走動、離開再現、標 chef_id+鏡頭+時間) |
| **相機拓撲 / 轉場時間** | ⬜ **需真實佈署量測**填入 config(現為示例) |
| 授權 | ✅ 全條可商用(時空邏輯自有 + DINOv2 Apache);OSNet/EPFL/Market 僅驗證不出貨 |

> EPFL 是**重疊同步、單人** → 只能驗跨視角與邏輯,**無法**驗「不重疊跨時轉場」;那需自錄。

## 6. 下一步

1. **自錄多人跨站廚房資料**(穿實際制服)→ 量測相機拓撲/轉場時間、驗真實 chef_id 準確率。
2. (可選)**自訓可商用 OSNet**(架構 MIT + 自錄資料)→ 提高外觀權重。
