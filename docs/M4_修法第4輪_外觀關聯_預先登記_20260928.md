## 1. 為什麼還要做第 4 輪(前三輪都無效)

工作規則是「同一問題 3 輪無效就停下」。9/15 的三輪確實都無效:

| 輪 | 方法 | 改的是什麼 | 單鏡頭 IDF1(基準 0.4599) |
|---|---|---|---|
| 1 | McByte(CVPRW 2025) | 用**分割遮罩**取代方框判斷重疊 | 0.4710(最好,但遮罩權重不可商用) |
| 2 | SparseTrack(TCSVT 2024) | 用框底位置當**偽深度**分層 | 0.4619(ID 切換反而增加) |
| 3 | Hybrid-SORT(AAAI 2024) | 加**弱線索**(分數變化、框高比例) | 0.4419(變差) |

**三輪的共同點:全部都在「運動與幾何」裡打轉** —— 遮罩、深度、框形狀,都是位置資訊的不同切法。
兩人交錯時位置本來就重疊,換哪種切法都分不開(9/15 實測:第一次換人時兩人框重疊 94.6%)。

本輪要加的是**位置以外的證據**,性質不同。另外有兩件新事實支持:

1. **9/28 的上限實驗把瓶頸明確指到 M4**:給 100% 準確的身份訊號,M5 誤併率仍有 30.79%;
   `cue100_on` 誤併 35.65% > 10% → 該實驗 §5.1 先寫死的處置就是「**回到追蹤層**」。
2. **同鏡頭的外觀鑑別力遠高於跨鏡頭**:`docs/M4_誤偵組成診斷_20260915.md` §13 實測,
   同一台鏡頭、沒被擋時可出貨的 armS **d′ = 2.39**(跨鏡頭只有 0.118)。

⚠ **這仍然是第 4 輪。** 若本輪也無效,依規則停止在追蹤層調整,回報使用者。

## 2. 要改什麼(只加一項,不換追蹤器)

**不換掉 C-BIoU** —— 它是 9/15 層 0 實測選出來的(斷點比例 29.85% → 20.14%),換掉等於丟掉那輪成果。

現在的關聯成本只有一項:

```
相似度 = 框重疊(放大後的 IoU)
```

本輪改成:

```
相似度 = (1 − w) × 框重疊  +  w × 外觀相似度
外觀相似度 = 0.5 × (1 + cosine(偵測特徵, track 特徵))      ← 映射到 [0, 1],與 IoU 同尺度
```

**做法沿用 9/15 已經拆好的掛勾**(`src/m4_track/sparse_dcm.py` 的 `_sim_high` / `_sim_low` /
`_before_association` / `_on_matched`),新增子類別 `AppearanceMcByteTracker`,不動既有類別。

| 決定 | 值 | 理由 |
|---|---|---|
| 外觀只用在**第一輪關聯**(`_sim_high`) | 是 | ByteTrack / BoT-SORT 的慣例:低信心偵測的裁圖品質差,外觀不可信 |
| track 特徵更新 | EMA,動量 **0.9** | BoT-SORT 的標準值,**不調** |
| 特徵維度 | 模型原生(DINOv2-S 384、armS0 2048) | 不降維 |
| 裁圖 | 偵測框原樣,resize 到模型輸入 | 不加 padding、不做對齊 |
| `w`(外觀權重) | **只從推導集估**,見 §3.1 | 拓撲與關聯參數一律不得用評估集校準 |

## 9. 結果(2026-09-28,跑完後追加;§1–§8 未修改)

### 9.1 先說結論

**兩格都無效。在追蹤層加外觀,不足以解決交錯遮擋時的混人 → §5.1 的失敗條件成立。**

### 9.2 ⚠ 必須先更正的一件事:§3/§4 的比較基準寫錯了

補跑 V1 時發現:新增的 `AppearanceMcByteTracker` **繼承 `DCMMcByteTracker`(McByte 無遮罩版)**,
不是繼承 C-BIoU。所以 `w = 0` 的歸零點是 **`rf_mcbyte_nomask`**,不是 `rf_cbiou`。

推導集逐位比對(`results/m4_round4/verification.json`):

| 與 `dino_w0.0` 的 dump 比 | 逐位相同 | 推導集 track 數 |
|---|---|---|
| `armS0_w0.0` | **6 / 6** | 299 |
| `rf_mcbyte_nomask` | **6 / 6** | 299 |
| `rf_mcbyte_nomask_dcm` | **6 / 6** | 299 |
| `rf_cbiou`(§7 V1 寫的基準) | **0 / 6** | 275 |

`src/m4_track/tracker.py:87` 的註解本來就寫對了(「w=0 → 與 `rf_mcbyte_nomask` 逐位相同」),
是**本文件 §7 V1 的條文把基準寫成 cbiou**,而 §2 又寫「不換掉 C-BIoU」—— 兩處都是我寫錯。
差別在 `rf_cbiou` 有 `buffer_ratio_first/second`(框放大)、McByte 系列沒有,改走自己的重疊判斷。

**處置(不改 §1–§8,改在這裡揭露)**:
- **V1 按字面判 FAIL**(w=0 與 cbiou 不同),**按意圖判 PASS**(關掉外觀後不改變任何數值路徑)。
- 判準 M1 / M2 的**數字**是登記時寫死的(0.4680、2,497),照原數字判一次;
  **另外**以正確的 w=0 基準 `nomask`(IDF1 **0.4511** / IDSW **2,619**,`results/m4_round1/idf1_nomask.json`,
  同 5 台、同 7 序列、同 stride 5、`tracker_kwargs` 只差三個惰性外觀欄位)再判一次。
- **兩種讀法的結論相同(都無效)**,所以這個錯誤不改變處置,但必須揭露。

### 9.6 為什麼 IDF1 升了、ID 切換卻也升了

`app_dino` 的 FN 從 10,115 降到 8,519(少漏 1,596),但 FP 從 36,695 升到 41,757(多出 5,062),
MOTA 從 0.6361 掉到 0.6079。外觀項讓追蹤器**更敢把框接上去**:接對的變多(IDF1、召回升),
接錯的也變多(FP、切換升)。這正是 §6 第 1 條先寫下的「換人那一刻選對率只有 62.3%」的後果 ——
**外觀在該發揮作用的時刻不可靠,卻在其他時刻放大了關聯的膽量。**

### 9.11 失敗原因的歸因診斷(2026-09-28 追加,`results/m4_round4/diag_app_floor.json`)

9.6 只說了「FP 變多」,那是現象不是原因。追查後找到**機制**,而且它同時解釋了兩格為什麼分裂。

#### 原因鏈

**① 門檻套在「合併後」的相似度矩陣上,不是只套在框重疊上。**

`trackers` 2.6.0 的 `core/mcbyte/tracker.py:1047` 是
`if similarity_matrix[row, col] >= min_similarity_thresh`,
而我們餵進去的矩陣是 `(1−w) × 框重疊 + w × 外觀`
(`src/m4_track/sparse_dcm.py:264` 用 `minimum_iou_threshold_first_assoc = 0.2` 當門檻)。
→ 外觀項可以**單獨**把一對送過門檻。

**② 外觀項有一個很高的「地板」。**

推導集真值框上實測(1,361 張裁圖,`app = 0.5 × (1 + cos)`):

| | DINOv2 cos | DINOv2 app | armS0 cos | armS0 app |
|---|---|---|---|---|
| 同一人、相鄰取樣格 | +0.977 | 0.989 | +0.985 | 0.993 |
| **同幀不同人** | **+0.440** | **0.720** | **+0.804** | **0.902** |
| 跨單元不同人 | +0.391 | 0.696 | +0.786 | 0.893 |

兩個模型都**不是**為「把不同人推開」做度量學習的(DINOv2 是通用視覺特徵、
armS0 是 ImageNet 起始的分類骨幹)→ 不同人的裁圖餘弦仍然很高。
armS0 的分離度尤其小:同人 − 不同人 只有 **0.181**(DINOv2 是 0.537)。

**③ 當 `w × 地板 ≥ 0.2`,門檻就被廢掉。**

「外觀項單獨」越過 0.2 門檻的比例(= 框完全不重疊也能配上):

| w | DINOv2 | armS0 |
|---|---|---|
| 0.1 | 0.0% | 0.0% |
| **0.2** | **0.0%**(w·app 中位 0.144) | **0.0%**(0.180,餘裕只有 0.020) |
| 0.3 | 73.1% | **100%** |
| 0.4 | 100% | 100% |
| **0.5** | **100%** | 100% |

而**同幀不同人的框重疊中位是 0.000,IoU < 0.2 佔 98.8%** ——
也就是說門檻一破,原本被框重疊擋掉的 98.8% 的錯配對全部變成候選。

**④ 推導程序本身在挑「把門檻弄壞」的 w。**

§3.1 寫死「取推導集 IDF1 最高的 w」。門檻被廢掉會**提高召回**(FN 少 1,596),
IDF1 跟著升 → **選 w 的規則直接獎勵把門檻弄壞**。結果:

| 格 | 選到的 w | 門檻狀態 | ΔIDF1(對 nomask) | ΔIDSW |
|---|---|---|---|---|
| `app_dino` | **0.5** | **全破**(100% 越過) | +0.0190 | **+241** |
| `app_armS0` | **0.2** | **完好**(0% 越過,餘裕 0.020) | +0.0048 | **−79** |

**兩格的分裂完全由「門檻有沒有破」解釋**,不是由模型好壞解釋 ——
armS0 的鑑別力明顯**較差**(分離度 0.181 vs 0.537),卻因為選到的 w 剛好沒破門檻而「比較安全」。

#### 所以「在 M4 加外觀可行嗎」的答案

- **門檻完好時,實測增益 +0.0048 IDF1 / −79 IDSW**(`app_armS0` w=0.2,唯一一個門檻完好的評估集格)
  —— 幾乎等於沒有。
- **門檻破掉時,IDF1 的升幅是假的**:多接回 1,596 個真框、同時多接 5,062 個假框,
  MOTA 0.6682 → 0.6079、切換 +241。

#### ⚠ 這同時是一個實作瑕疵的自我揭露

**本輪實際測到的不是「加入外觀證據」,而是「把框重疊門檻放寬」。** 這是我的實作方式造成的:
加權和 + 單一門檻,讓外觀項可以獨力過關。BoT-SORT 的標準做法**不是加權和** ——
它對框重疊與外觀**各設一道門檻**,兩道都不過就直接封鎖(取 `min` 而非加權平均),
正是為了避開這個問題。§2 把「加權和」寫死成設計決定時沒有意識到這一點。

因此:
- §9.5 的「兩格都無效」**仍然成立**(數字是真的,判準是先寫死的)。
- 但「在追蹤層加外觀無效」這個**推論的強度要降級** —— 本輪只證明了
  **「用加權和 + 單一門檻的方式加外觀」無效**,沒有測到 BoT-SORT 式的雙門檻做法。
- §5.1 的處置(停止追蹤層調整)是否執行,**交由使用者決定**,並附上這個瑕疵的揭露。
  若要再測,必須另立預先登記,且至少要改兩件事:
  (a) 門檻只套框重疊、外觀另設一道(BoT-SORT 式);
  (b) 選 `w` 的規則不能只看 IDF1(它會獎勵放寬門檻),要加「IDSW 不得上升」的硬約束。

#### 診斷本身的限制

1. 裁圖取自**真值框**,實際追蹤時餵的是**偵測框**(會有偏移、截斷) → 真實的 app 地板可能更高(更糟)。
2. 只量了推導集(`seq_000/001/002`)、5 台鏡頭、1,361 張裁圖。
3. 「越過門檻比例」是對**門檻的上游**做的推算,不是逐次配對的實測計數 ——
   實際還要看同一深度層裡有沒有別的候選競爭。方向與量級可信,精確值不可引用。

### 9.13 決定性的一項:混雜 track 比例(2026-09-29)

§9.12 的 L2 觀察測不到「編號黏到別人身上」,因為**全部 67 段片段都是獨佔的**
(逐片段清單重查:`n_other_ids > 0` 的片段 **0 段**)。
→ 片段這條路**結構上無法**回答「多人時會不會混」。唯一有多人的資料是**全長序列**。

`scripts/eval_m4_chirla.py` 早就在算這個數字:**混雜 track** =
這條 track 裡第二多的那個真人也佔了 ≥ 3 幀 = **同一個編號被戴到兩個不同的人身上**。

5 台 × 7 評估序列、stride 5、thr 0.10:

| 格 | track 總數 | 誤偵 track | 對到人的 | **混雜** | **混雜比例** |
|---|---|---|---|---|---|
| `nomask`(w=0,真正的基準) | 2,320 | 541 | 1,779 | 254 | **14.3%** |
| `cbiou`(交付基準) | 2,070 | 506 | 1,564 | 297 | 19.0% |
| `app_armS0` w=0.2 | 1,548 | 267 | 1,281 | 307 | **24.0%** |
| `app_dino` w=0.5 | **663** | 106 | **557** | 359 | **64.5%** |

#### 這解釋了 §9.12 為什麼那麼好看

`app_dino` 的 track 數從 1,779 崩到 **557**(少 69%),每位真人每台鏡頭的 track 中位數
從 7 條變成 **2 條**。track 又少又長 → **連續率、再取得率、編號切換全部變漂亮**。

但其中 **64.5% 混了兩個以上的人**。也就是說:那條又長又連續的 track,
有將近三分之二的機率中途換過人。單人片段上看不出來,因為沒有別人可換。

#### 對「都用 dino 就好」的回答

**不行。** 以出貨標準看,這是把「一個編號 = 一個人」直接打破:
- `nomask` 14.3% → `app_dino` **64.5%**(4.5 倍)
- 連 `app_armS0 w=0.2`(門檻完好那格)也從 14.3% 升到 **24.0%**

→ **在關聯成本裡加外觀,兩格都讓身份混雜變嚴重**,差別只是幅度。
§9.4 的 IDF1 +0.0190 是**用混雜 track 換來的**,不是真的變準。

這也是 §9.11 那條原因鏈的最後一塊:門檻被廢掉 → 配對放寬 → track 接得更長 →
**表面指標變好、實際身份變糟**。IDF1 對這種錯誤不敏感,混雜 track 比例才看得出來。

#### 這一項改變了什麼

§9.5 判兩格「無效」時,理由是 M2(ID 切換)沒過。現在有更強的理由:
**兩格都讓混雜 track 上升**,而那正是本專案要解決的問題本身(M5 的誤併)。
若未來要再試(§9.11 提的 BoT-SORT 式雙門檻),**混雜 track 比例必須進判準**,
不能只看 IDF1 與 IDSW。

|---|---|---|---|---|
| **L1**(單鏡頭連續,30 段) | 連續率 | 0.9758 | **0.9987** | 0.9978 |
| | 誤偵框比例 | 0.0940 | 0.1083 | 0.1044 |
| **L2**(離開再回來,13 段) | **再取得(k=5)** | **1/14(7.1%)** | 3/14(21.4%) | **14/14(100%)** |
| | 連續率 | 0.3753 | 0.5019 | **0.9276** |
| | 誤偵框比例 | 0.1412 | 0.1405 | **0.2108** |

三個等級的 IoU 幾乎不動(L1 0.897、L2 0.913、L3S 0.938)→ 定位一直是好的,變的只有身份。

#### 結論一:改善**只發生在 L2**

- **L1 本來就接近天花板**(0.9758),加外觀只到 0.998 —— 沒有診斷價值。
- **L2 是唯一有大幅改善的**:再取得 7.1% → 100%,連續率 0.375 → 0.928。
- **L3 完全沒有改善**。

#### 結論二:跨鏡頭三格**逐字相同**,而且這是結構必然

L3S 三格都是 **5/16**、L3T 三格都是 **0/5**。這不是巧合:

**外觀特徵只用在 M4 的「同一台鏡頭」關聯成本裡**(這一幀的偵測 vs 這台鏡頭的 track)。
**跨鏡頭綁定是 M5 的工作,而 M5 全程 `--embedder none`。**
→ 外觀根本沒有進到跨鏡頭那個決定裡,所以跨鏡頭數字一個位元都不會變。

**§5 的預測 P2 若套用到這裡會被否證**:事前以為「跨鏡頭位置線索斷掉,外觀是唯一剩下的證據,
應該在 L3 看到最大增益」。實際上增益是 **0**,因為證據根本沒送到需要它的那一層。

#### 這對「要不要用外觀」的意義

在**目前的接法**(外觀只進 M4 關聯成本)下:

| 想解決的問題 | 有沒有幫助 |
|---|---|
| 同鏡頭、短暫遮擋(L1) | 幾乎沒有(本來就 0.976) |
| 同鏡頭、離開再回來(L2) | **有,而且很大**(7.1% → 100%) |
| **跨鏡頭(L3,= M5 的誤併問題)** | **完全沒有(0)** |
| 多人同場(§9.13) | **變糟**(混雜 track 14.3% → 64.5%) |

→ 外觀要對跨鏡頭有用,必須接進 **M5**(`AppearanceLR`),不是 M4 的關聯成本。
  但 9/28 的量測顯示可出貨模型跨鏡頭只提供 ~0.007 nats,而門檻是 1.609 ——
  那條路先前已經量過是走不通的。
