## 1. 為什麼還要做第 4 輪(前三輪都無效)

工作規則是「同一問題 3 輪無效就停下」。9/15 的三輪確實都無效:

| 輪 | 方法 | 改的是什麼 | 單鏡頭 IDF1(基準 0.4599) |
|---|---|---|---|
| 1 | McByte(CVPRW 2025) | 用**分割遮罩**取代方框判斷重疊 | 0.4710(最好,但遮罩權重不可商用) |
| 2 | SparseTrack(TCSVT 2024) | 用框底位置當**偽深度**分層 | 0.4619(ID 切換反而增加) |
| 3 | Hybrid-SORT(AAAI 2024) | 加**弱線索**(分數變化、框高比例) | 0.4419(變差) |

**三輪的共同點:全部都在「運動與幾何」裡打轉** —— 遮罩、深度、框形狀,都是位置資訊的不同切法。
兩人交錯時位置本來就重疊,換哪種切法都分不開(9/15 實測:第一次換人時兩人框重疊 94.6%)。

本輪要加的是**位置以外的證據**,性質不同。另外有兩件新事實支持:

1. **9/28 的上限實驗把瓶頸明確指到 M4**:給 100% 準確的身份訊號,M5 誤併率仍有 30.79%;
   `cue100_on` 誤併 35.65% > 10% → 該實驗 §5.1 先寫死的處置就是「**回到追蹤層**」。
2. **同鏡頭的外觀鑑別力遠高於跨鏡頭**:`docs/M4_誤偵組成診斷_20260915.md` §13 實測,
   同一台鏡頭、沒被擋時可出貨的 armS **d′ = 2.39**(跨鏡頭只有 0.118)。

⚠ **這仍然是第 4 輪。** 若本輪也無效,依規則停止在追蹤層調整,回報使用者。

## 2. 要改什麼(只加一項,不換追蹤器)

**不換掉 C-BIoU** —— 它是 9/15 層 0 實測選出來的(斷點比例 29.85% → 20.14%),換掉等於丟掉那輪成果。

現在的關聯成本只有一項:

```
相似度 = 框重疊(放大後的 IoU)
```

本輪改成:

```
相似度 = (1 − w) × 框重疊  +  w × 外觀相似度
外觀相似度 = 0.5 × (1 + cosine(偵測特徵, track 特徵))      ← 映射到 [0, 1],與 IoU 同尺度
```

**做法沿用 9/15 已經拆好的掛勾**(`src/m4_track/sparse_dcm.py` 的 `_sim_high` / `_sim_low` /
`_before_association` / `_on_matched`),新增子類別 `AppearanceMcByteTracker`,不動既有類別。

| 決定 | 值 | 理由 |
|---|---|---|
| 外觀只用在**第一輪關聯**(`_sim_high`) | 是 | ByteTrack / BoT-SORT 的慣例:低信心偵測的裁圖品質差,外觀不可信 |
| track 特徵更新 | EMA,動量 **0.9** | BoT-SORT 的標準值,**不調** |
| 特徵維度 | 模型原生(DINOv2-S 384、armS0 2048) | 不降維 |
| 裁圖 | 偵測框原樣,resize 到模型輸入 | 不加 padding、不做對齊 |
| `w`(外觀權重) | **只從推導集估**,見 §3.1 | 拓撲與關聯參數一律不得用評估集校準 |

## 9. 結果(2026-09-28,跑完後追加;§1–§8 未修改)

### 9.1 先說結論

**兩格都無效。在追蹤層加外觀,不足以解決交錯遮擋時的混人 → §5.1 的失敗條件成立。**

### 9.2 ⚠ 必須先更正的一件事:§3/§4 的比較基準寫錯了

補跑 V1 時發現:新增的 `AppearanceMcByteTracker` **繼承 `DCMMcByteTracker`(McByte 無遮罩版)**,
不是繼承 C-BIoU。所以 `w = 0` 的歸零點是 **`rf_mcbyte_nomask`**,不是 `rf_cbiou`。

推導集逐位比對(`results/m4_round4/verification.json`):

| 與 `dino_w0.0` 的 dump 比 | 逐位相同 | 推導集 track 數 |
|---|---|---|
| `armS0_w0.0` | **6 / 6** | 299 |
| `rf_mcbyte_nomask` | **6 / 6** | 299 |
| `rf_mcbyte_nomask_dcm` | **6 / 6** | 299 |
| `rf_cbiou`(§7 V1 寫的基準) | **0 / 6** | 275 |

`src/m4_track/tracker.py:87` 的註解本來就寫對了(「w=0 → 與 `rf_mcbyte_nomask` 逐位相同」),
是**本文件 §7 V1 的條文把基準寫成 cbiou**,而 §2 又寫「不換掉 C-BIoU」—— 兩處都是我寫錯。
差別在 `rf_cbiou` 有 `buffer_ratio_first/second`(框放大)、McByte 系列沒有,改走自己的重疊判斷。

**處置(不改 §1–§8,改在這裡揭露)**:
- **V1 按字面判 FAIL**(w=0 與 cbiou 不同),**按意圖判 PASS**(關掉外觀後不改變任何數值路徑)。
- 判準 M1 / M2 的**數字**是登記時寫死的(0.4680、2,497),照原數字判一次;
  **另外**以正確的 w=0 基準 `nomask`(IDF1 **0.4511** / IDSW **2,619**,`results/m4_round1/idf1_nomask.json`,
  同 5 台、同 7 序列、同 stride 5、`tracker_kwargs` 只差三個惰性外觀欄位)再判一次。
- **兩種讀法的結論相同(都無效)**,所以這個錯誤不改變處置,但必須揭露。

### 9.6 為什麼 IDF1 升了、ID 切換卻也升了

`app_dino` 的 FN 從 10,115 降到 8,519(少漏 1,596),但 FP 從 36,695 升到 41,757(多出 5,062),
MOTA 從 0.6361 掉到 0.6079。外觀項讓追蹤器**更敢把框接上去**:接對的變多(IDF1、召回升),
接錯的也變多(FP、切換升)。這正是 §6 第 1 條先寫下的「換人那一刻選對率只有 62.3%」的後果 ——
**外觀在該發揮作用的時刻不可靠,卻在其他時刻放大了關聯的膽量。**
