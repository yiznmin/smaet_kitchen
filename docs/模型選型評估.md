# M3 物件偵測 — 可商用模型選型評估

> 目的：本案為產學合作、**最終要交付業者(商用)**，模型授權必須可商用(Apache-2.0 / MIT / BSD 等)。
> 本文件列出**所有可商用候選**並逐一評估，作為 M3 速度 benchmark 的選型依據。
> 文件版本 v1（2026-05-31）。數字均註明來源與測試硬體。

---

## 0. 為什麼不用(主流)YOLO

關鍵不是 YOLO 不好，而是**最常見的那幾版 YOLO 授權不可商用閉源出貨**：

| YOLO 版本 | 授權 | 可出貨 | 備註 |
|---|---|---|---|
| Ultralytics YOLOv5 / v8 / v11 / v12 | AGPL-3.0 | ❌ | 須開源整個應用，或向 Ultralytics 付費購買商業授權 |
| YOLOv10（清華 THU-MIG） | AGPL-3.0 | ❌ | |
| YOLOv7 / YOLOv9（原版） | GPL-3.0 | ❌ | |
| YOLOv6（美團） | GPL-3.0 | ❌ | |
| **YOLOX（曠視 Megvii）** | **Apache-2.0** | ✅ | 這個 YOLO 可商用 |

→ 結論：我們不是「不用 YOLO」，而是**只用可商用授權的偵測模型**（含 YOLOX 這種 Apache 的 YOLO）。
況且 2025 後的 DETR 系（RF-DETR、D-FINE）在準度-延遲上已超越 YOLO，且為 Apache，避開 AGPL 反而拿到更好的模型。

## 1. 評選標準

| 標準 | 說明 |
|---|---|
| 授權可商用 | **硬條件**：必須 Apache-2.0 / MIT / BSD;排除 AGPL / GPL / CC-NC |
| 效率 | 參數量、延遲、可支援鏡頭數(多鏡頭即時是本案重點) |
| 準確度 | COCO AP;尤其**小物件**(刀、器具、食材)表現 |
| 微調容易度 | 要在自有廚房類別上 fine-tune |
| 部署支援 | 是否支援 ONNX / TensorRT 匯出(本案用 ONNX Runtime 統一後端) |
| 成熟度 | 文件、社群、長期維護 |

> ⚠ **延遲數字不可直接互比**：各 repo 測試硬體不同(T4 / V100 / 未註明)。
> 此表僅供初篩,**最終延遲必須在目標部署主機上以同一後端(ONNX Runtime)重測**(說明文件 C.4 #4)。

## 3. 逐一評估

### ⭐ RF-DETR（Roboflow, 2025）— 準確度王
- **授權**：nano/small/medium/large 為 Apache-2.0；**XL/2XL 為 PML 1.0（不可商用）**。
- **強項**：首個 COCO >60 AP 的即時模型；DINOv2 backbone，**小物件特別強**（對廚房的刀、器具有利）；**官方主打 fine-tuning**。
- **弱項**：Transformer 較吃 VRAM，**微調對小 GPU(如 3050 4GB)吃力**(推論還好)；須注意只能用到 Large。
- **適合本案**：✅ 準確度與小物件需求；微調建議在較大 GPU 上做。

### ⭐ D-FINE（2024）— 效率王
- **授權**：Apache-2.0（全部變體）。
- **強項**：參數極小（N 僅 4M）、**內建 ONNX + TensorRT 匯出**；同延遲下精度優於多數 YOLO。
- **弱項**：DETR 訓練收斂需技巧（可搭 DEIM 改善）。
- **適合本案**：✅ 目標 GPU 不大 / 鏡頭多時的首選。

### LW-DETR（Baidu, 2024）— 輕量 DETR
- **授權**：Apache-2.0。
- **強項**：tiny 僅 2.0ms、large 56.1 AP，延遲-精度佳；支援 ONNX。
- **弱項**：延遲測試硬體未註明，需自測；社群較小。
- **適合本案**：✅ 候選，需自行 benchmark 驗證。

### DAMO-YOLO（阿里, 2022）— 含 CPU 變體
- **授權**：Apache-2.0。
- **強項**：T4 上 T 變體 2.78ms/43.6AP；**有 CPU 輕量變體(Ns/Nm/Nl)**，邊緣/無 GPU 也能跑;TRT FP16/INT8。
- **弱項**：較舊，精度上限(L 51.9)低於新 DETR。
- **適合本案**：✅ 若有 CPU/低階硬體 fallback 需求。

### YOLOX（曠視, 2021）— 成熟可商用 YOLO
- **授權**：Apache-2.0。
- **強項**：成熟穩定、部署生態最廣(ONNX/TensorRT/ncnn/OpenVINO);微調簡單。
- **弱項**：年代較久，精度(X 51.1)落後新模型;延遲以 V100 量，與他者不可直比。
- **適合本案**：✅ 穩健基準/部署相容性高;可作對照。

### RT-DETRv2（Baidu, 2024）
- **授權**：Apache-2.0。
- **強項**：RT-DETR 改良版，DETR 系成熟基線;PaddleDetection 與 PyTorch 移植皆有。
- **適合本案**：✅ 候選，D-FINE/RF-DETR 多以它為比較對象。

### RTMDet（OpenMMLab, 2022）
- **授權**：Apache-2.0（mmdetection）。
- **強項**：精度-速度均衡，mmdeploy 部署完整。
- **弱項**：依賴 mmdet 生態,環境較重。
- **適合本案**：🟡 可選,環境較重。

### PP-YOLOE+（Baidu, 2022）
- **授權**：Apache-2.0（PaddleDetection）。
- **弱項**：以 PaddlePaddle 為主,與 PyTorch 工具鏈整合較麻煩。
- **適合本案**：🟡 除非已用 Paddle，否則優先序低。

### NanoDet-Plus — 超輕量(邊緣/CPU)
- **授權**：Apache-2.0。
- **強項**：極小、可在 CPU/手機即時。
- **弱項**：精度低(~34 AP)，僅適合算力極受限場景。
- **適合本案**：🟡 僅備援（若部署主機極弱）。

### DEIM（訓練框架, 2025）
- **授權**：Apache-2.0。
- **說明**：**不是模型**，是改進 DETR 匹配的訓練法，套在 D-FINE / RT-DETRv2 上可提精度、省一半訓練時間（DEIM-D-FINE-X 達 56.5 AP）。
- **適合本案**：✅ 訓練階段加掛,不影響推論授權。

## 5. benchmark 建議入選清單

無法把 10 個都跑（且部分框架環境互斥），建議 M3 速度 benchmark 先測**代表性的 5 個**，全部 Apache-2.0、皆支援 ONNX：

1. **D-FINE-N / S** — 效率代表
2. **RF-DETR-S / M** — 準確度代表（小物件）
3. **LW-DETR-tiny / small** — 輕量 DETR 對照
4. **DAMO-YOLO-T / S** — 含 CPU 變體的 YOLO 代表
5. **YOLOX-S** — 成熟基準對照

> 全部匯出成 ONNX → 用 ONNX Runtime 在**目標主機**上以同一後端、同解析度、同批次測延遲/FPS/GPU 記憶體，產出可比較的選型表。
