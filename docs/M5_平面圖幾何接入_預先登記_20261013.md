# 預先登記:把 CHIRLA 交接包的平面圖與網格幾何接進 M5(2026-10-13)

> **本文件在跑任何一格之前定稿並提交 git。** 跑完只追加 §9 之後,§1–§8 不得修改。
> ⚠ 本輪是**修法第 1 輪**(問題:多人誤併、轉場通不過門檻)。依既定規則,最多 3 輪。

---

## 1. 為什麼跑這一輪

外部交接包 `CHIRLA_L3_handover`(位於 `../CHIRLA_輔助線索與2D平面和網格程式/`)在 CHIRLA 上
評估「外觀以外的輔助線索」,單人 L3 連續率 1.000、多人 L3S 0.904 / L3T 0.981。
但它的前提是**標註軌跡當作單鏡頭追蹤結果**,沒有回答「換成真實 M3 偵測 + M4 追蹤後還成不成立」。

本專案 M5 目前兩個未解問題(`docs/M5_跨鏡頭身份綁定_L3結果彙整_20261006.md`):

| 問題 | 現況 |
|---|---|
| 多人全長序列 | 修拓撲 + dinov2:誤併 82.96% / 碎裂 1.24%(加權成本 416.0);既有交付 base:58.84% / 31.33%(325.5)。重疊路徑的常數 `overlap_llr = 5.0` 無法拒絕任何候選 |
| L3T 轉場 | 分數天花板 1.484 < 門檻 1.609,5 段只過 2 段 |

M5 早有地面座標介面(`world_xy` → `GroundPlaneLR`),在 CHIRLA 上一直關著,
原因寫在拓撲檔:「CHIRLA 沒有提供相機標定參數」。交接包提供的正是這個缺口:
7 台攝影機到場地示意圖的投影矩陣、房間與出入口、可行走網格。

**接法**:不搬它的管線(訓練標籤與校正都依賴標註身分),只把**場地幾何資料**餵進既有的證據介面,
再補一條轉場路徑的位置證據。

## 4. 執行網格(定死)

M4、偵測快取、偵測門檻、TTL、embedder 全部與既有結果相同,**只有 M5 拓撲不同**。

| 格 | 拓撲 | 平面圖座標 | 重疊路徑 | 轉場路徑位置證據 | 距離 |
|---|---|---|---|---|---|
| `base`(參考,**不重跑**) | `configs/fix_grid/base.yaml`、無外觀 | 無 | 常數 5.0 | 無 | — |
| `C0` | `configs/fix_grid/base_overlapfix.yaml` | 無 | 常數 5.0 | 無 | — |
| `P1` | C0 + 平面圖 | 地標投影矩陣 | `GroundPlaneLR` | 無 | 房間出入口路徑 |
| `P2` | P1 + `plan_transit` | 地標投影矩陣 | `GroundPlaneLR` | 有 | 房間出入口路徑 |
| `G2` | 同 P2 | `walk_pairs_final5h`(逐序列留一) | `GroundPlaneLR` | 有 | 4 像素可行走網格測地距離 |

- 四格 M5 embedder 皆為 `dinov2`。
- 每序列的投影矩陣 = 平面圖投影矩陣 × 該序列的畫面對齊矩陣(`camera_align.json`)。
- 地標投影矩陣 = 交接包 `landmark_homographies()` 的作法(人工地標 + 出入口區域中位點,最小平方)。
- 接地點 = 框底邊中點,不另加站姿過濾(M4 的框就是部署時拿得到的東西)。

## 5. 參數來源(不得回頭用評估集校準)

只用**推導集 seq_000 / 001 / 002** 的標註、**原始時間戳**(不套時間偏移,與現行部署一致):

| 參數 | 估法 |
|---|---|
| σ | 同一人同一影格被兩台看到時,兩邊接地點投影到平面圖後的距離;取穩健尺度 σ_pair = 距離中位數 ÷ 1.1774(二維等向高斯下,距離中位數 = 每軸標準差 × √(2 ln 2))。寫入設定的是**成對值 ÷ √2**,因為 `GroundPlaneLR` 內部會再乘 √2 |
| 速度 | 同鏡頭相隔 1 秒(30 影格)的平面圖位移中位數 |
| 面積 | 可行走區面積(示意圖像素²) |

- 單位一律是**示意圖像素**。示意圖不按比例,不硬換算成公尺;三個數同單位即可。
- P 格與 G 格各自用自己的投影矩陣估 σ 與速度(距離種類不同,不可共用)。
- `plan_transit` 與 `ground_plane` 用同一組 σ、速度、面積,`clip` 沿用 8.0。

### 5.1 資訊洩漏(照實揭露)

| 項目 | 洩漏 |
|---|---|
| 地標投影矩陣(P 格) | 人工點選,不含身分標註;參考畫面取自 seq_020(評估集)。出入口區域中位點來自 seq_000~020 的標註(含 4 個評估序列)。視為場地事實,與現有重疊清單同級 |
| `walk_pairs_final5h`(G 格) | 逐序列留一,用到**其他評估序列**的身分標註與時間對應表。**G 格數字只能當上限參考** |
| 畫面對齊矩陣 | 由背景影像算出,不含標註 |
| 可行走網格 | 由示意圖與出入口位置算出,不含標註 |

## 6. 判準(先寫死)

### 6.1 硬性驗收(不過就不看指標)

| 編號 | 內容 |
|---|---|
| V0 | C0 重跑的 `tracks.csv`、`chef_events.jsonl` 與 `results/single_best/runs`(17 段)及 `results/m5_topofix/B_fixtopo_dino`(7 序列)**逐位相同** |
| V1 | P1 / P2 / G2 的 `run_meta.json`:片段與全長的 `n_homographies` = 該次鏡頭數、`ground_plane_effective = true` |
| V2 | 校正報告:7 台都有矩陣;σ 對應的證據上限 `log(A / 2πσ_pair²)` 必須 > 門檻 1.609,否則該格**不跑**,照實記錄 |

### 6.2 主判準(多人 7 序列)

加權成本 = 5 × 誤併率 + 碎裂率(百分點)。

| 結果 | 條件 |
|---|---|
| 成功 | 加權成本 < 325.5(既有交付)**且**誤併率 < 58.84% |
| 部分 | 325.5 ≤ 加權成本 < 416.0(C0) |
| 失敗 | 加權成本 ≥ 416.0 |

### 6.3 硬性約束(單人 17 段)

L3S 跨鏡頭一致不得低於 **13/16**(C0 為 14/16)。低於就算該格不合格,不論多人結果。

## 8. 這次不能回答什麼

- **現場泛化**:廚房為同款制服加口罩、不鏽鋼反光;CHIRLA 每人衣著不同。
- **時間同步後的表現**:本輪不接 M1,各鏡頭用原始時間戳。
- **倒影誤偵**:本輪不接 M4 入口把關,誤偵綁定率預期維持在 30% 上下。
- **樣本數**:單人 L3S 分母 16 個鏡頭對、L3T 只有 5 段。
- **G 格的真實水準**:含洩漏,只能當上限。
- **示意圖不按比例**:平面圖距離不是真實公尺,σ 與面積只在本場地有意義。
