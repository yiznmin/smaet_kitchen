## 1. 為什麼跑這一輪

外部交接包 `CHIRLA_L3_handover`(位於 `../CHIRLA_輔助線索與2D平面和網格程式/`)在 CHIRLA 上
評估「外觀以外的輔助線索」,單人 L3 連續率 1.000、多人 L3S 0.904 / L3T 0.981。
但它的前提是**標註軌跡當作單鏡頭追蹤結果**,沒有回答「換成真實 M3 偵測 + M4 追蹤後還成不成立」。

本專案 M5 目前兩個未解問題(`docs/M5_跨鏡頭身份綁定_L3結果彙整_20261006.md`):

| 問題 | 現況 |
|---|---|
| 多人全長序列 | 修拓撲 + dinov2:誤併 82.96% / 碎裂 1.24%(加權成本 416.0);既有交付 base:58.84% / 31.33%(325.5)。重疊路徑的常數 `overlap_llr = 5.0` 無法拒絕任何候選 |
| L3T 轉場 | 分數天花板 1.484 < 門檻 1.609,5 段只過 2 段 |

M5 早有地面座標介面(`world_xy` → `GroundPlaneLR`),在 CHIRLA 上一直關著,
原因寫在拓撲檔:「CHIRLA 沒有提供相機標定參數」。交接包提供的正是這個缺口:
7 台攝影機到場地示意圖的投影矩陣、房間與出入口、可行走網格。

**接法**:不搬它的管線(訓練標籤與校正都依賴標註身分),只把**場地幾何資料**餵進既有的證據介面,
再補一條轉場路徑的位置證據。

## 5. 參數來源(不得回頭用評估集校準)

只用**推導集 seq_000 / 001 / 002** 的標註、**原始時間戳**(不套時間偏移,與現行部署一致):

| 參數 | 估法 |
|---|---|
| σ | 同一人同一影格被兩台看到時,兩邊接地點投影到平面圖後的距離;取穩健尺度 σ_pair = 距離中位數 ÷ 1.1774(二維等向高斯下,距離中位數 = 每軸標準差 × √(2 ln 2))。寫入設定的是**成對值 ÷ √2**,因為 `GroundPlaneLR` 內部會再乘 √2 |
| 速度 | 同鏡頭相隔 1 秒(30 影格)的平面圖位移中位數 |
| 面積 | 可行走區面積(示意圖像素²) |

- 單位一律是**示意圖像素**。示意圖不按比例,不硬換算成公尺;三個數同單位即可。
- P 格與 G 格各自用自己的投影矩陣估 σ 與速度(距離種類不同,不可共用)。
- `plan_transit` 與 `ground_plane` 用同一組 σ、速度、面積,`clip` 沿用 8.0。

### 5.0 開跑前修訂(2026-10-13,寫建置腳本時發現,**尚未跑出任何數字**)

上表「速度」原定為全部樣本的位移中位數。CHIRLA 多數時間人是坐著的,全部樣本的中位數會接近 0,
不代表「走路的人一秒走多遠」。改為**只取走動中的樣本**:
前後 0.5 秒(±15 影格)影像接地點位移 ≥ 0.15 倍框高者(交接包 `level3_geometry.walking` 的判定),
取其 1 秒平面圖位移的中位數。此修訂在第一次執行建置腳本之前提交。

### 9.4 檢討:為什麼變差

量測:推導集標註框逐鏡頭對的平面圖距離(同一人同一影格)。

| 鏡頭對 | 樣本 | 地標:中位 / P90 | 重新擬合:中位 / P90 |
|---|---|---|---|
| 2+3 | 6,002 | 10.6 / 23.4 | 12.0 / 22.6 |
| 1+3 | 2,084 | 12.5 / 20.9 | 11.3 / 21.7 |
| 1+2 | 681 | 24.3 / 54.6 | 17.0 / 31.3 |
| 2+5 | 648 | 18.0 / 26.7 | 17.7 / 29.0 |
| 6+7 | 344 | 18.6 / 39.3 | 17.7 / 39.3 |
| 4+5 | 298 | 26.6 / 47.9 | 25.0 / 38.8 |
| 3+4 | 158 | 47.8 / 78.7 | 37.1 / 93.3 |
| 1+5 | 29 | 8.3 / 14.5 | 25.0 / 37.0 |
| 3+5 | 12 | 249.6 / 255.5 | 143.2 / 159.4 |
| 2+4 | 9 | 71.7 / 73.4 | 61.0 / 76.8 |

17 段裡真值目標同時在兩台時的距離(標註框):`c6+c7` 各段中位 20~41 像素(seq_004 為 92),
`c1+c2` 29~45,`c4+c6` 182。

**原因**:

1. **單一全域 σ 是錯的。** 10.8 像素被 `2+3`(佔樣本 58%)主導,而 17 段有 9 段是 `6+7`。
   σ = 10.8 時距離 23 像素以上就低於門檻(3.95 − d²/234 < 1.609),`6+7` 的真配對多數被拒。
   這違反了 `CrossViewLR` 早就寫下的原則:「逐對估,每一對帶著自己實測的 σ」。
2. **結構上的差別**:C0 的常數 5.0 在只有一個候選時必過(單人片段沒有別人可綁錯);
   換成絕對的位置證據後,單一候選也要自己拿到 1.609 nats,投影誤差大的鏡頭對就過不了。
3. **L3T 掉到 0/5**:`c5+c6` 在拓撲裡列為重疊,C0 靠常數綁上的 2 段現在被位置證據擋下;
   轉場位置證據(P2)沒有補回來。

## 10. 第 2 輪修法 —— 預先登記(2026-10-13,在跑第 2 輪之前提交)

### 10.1 要解決的問題

§9.4 的原因 1:單一全域 σ 讓投影誤差較大的鏡頭對把真配對擋掉(單人 L3S 14/16 → 4/16)。

查到的現有作法:地面平面上的跨鏡頭關聯普遍用**帶不確定度的距離(Mahalanobis)**做閘門,
不確定度隨視角而異;以單一誤差尺度套用到所有視角會造成漏配。
(UCMCTrack:https://arxiv.org/html/2312.08952v2 ;On-the-Fly Homographies Calibration for Multi-Camera Tracking:
https://arxiv.org/html/2609.18582v1 ;Tracklet-to-Target Assignment 指出只用位置會因平面投影誤差而錯配:
https://www.researchgate.net/publication/339786508_Multi-Target_Multi-Camera_Tracking_by_Tracklet-to-Target_Assignment )
本專案的 `CrossViewLR` 也早已寫下同一個原則:逐對估,每一對帶著自己實測的 σ。

### 10.2 兩格(M4、偵測、其餘設定與 P1 相同;投影 = 地標,距離 = 房間出入口路徑,不開轉場位置證據)

| 格 | 重疊路徑的位置證據 |
|---|---|
| `Q1` 逐對絕對 | 每個鏡頭對用自己的 σ:分數 = `GroundPlaneLR_pair.llr_dist(d)` + 外觀。候選此刻在哪一台重疊鏡頭,就用那一台的框算平面圖位置(`_bbox`,與 `CrossViewLR` 相同的取法;多台可用時取證據絕對值最大者) |
| `Q2` 逐對份額 | 分數 = `overlap_llr`(5.0)+ log(份額)+ 外觀;份額 = L_i / Σ_j L_j,L = (1 − ε) × 高斯密度 + ε / A,ε = 0.05(沿用 `PositionLR` 的均勻混合值),j 跑遍此刻在重疊鏡頭上且有可用鏡頭對的所有候選。也就是把原本的均勻稀釋 `− log k` 換成依位置分配;只有一個候選時份額 = 1,分數與 C0 相同 |

**可用鏡頭對**(兩格共用,先寫死):推導集同人成對樣本 **≥ 100** 且該對證據上限 `log(A / 2πσ_pair²)` **> 1.609**。
不可用的鏡頭對**退回原本的常數路徑**(與 `CrossViewLR` 缺單應性時的行為一致)。
逐對 σ_pair = 該對距離中位數 ÷ 1.1774,只用推導集,全部樣本(不抽樣)。

依 §9.4 的表,預期可用的是 2+3、1+3、1+2、2+5、6+7、4+5 共 6 對;3+4(上限約 1.30)與樣本不足的對退回常數。
