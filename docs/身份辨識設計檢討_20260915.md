# 身份辨識的設計檢討(2026-09-15)

> 起因:使用者問「為什麼沒有偵測到一個人就給身份,再給 M5 綁定?我們是設計上有問題嗎?」
> 這份是設計問題的紀錄,不是預先登記;每個數字都附來源。

---

## 1. 結論

**是,設計上有問題,而且有兩層:**

1. **結構問題**:身份只在 track 出生時決定一次,之後不再檢查 → 系統的正確性被 M4 的連續性綁死
2. **場域條件問題**:廚師**戴口罩、穿同款制服**(使用者 2026-09-15 確認),鏡頭是**斜角**的(使用者確認)。
   在這個條件下,**目前沒有任何證據能在每次偵測時直接分辨「這是誰」**

「偵測到人就給身份」要成立,前提是每個框裡有能分辨人的訊號。外觀做不到;**可辨識標記**(帽子或肩膀的色塊、編號標籤)是目前唯一能提供這個訊號的方法。是否採用要由業主決定。

---

## 2. 現行設計:身份只決定一次

```
M3 偵測框 → M4 把框串成 track(只看框的位置、大小、運動)
          → track 出生時 M5 決定一次身份
          → 之後這條 track 一直沿用
```

| 事實 | 來源 |
|---|---|
| runner 只在 `new_track` 事件呼叫 `m5.on_new_track`;`reacquired` / `lost_track` / `removed` 只更新狀態 | `scripts/m5_track_video.py`(`ev.kind ==` 分支) |
| 身份決策在 `on_new_track`;`on_track_update` 主要回報位置 | `src/m5_reid/identity_st.py` |
| 唯一的「重新檢查」是 P1 累積投票(預設關閉)。9/13 開啟後投了 **52,259 票只改判 423 次(0.81%)** —— 當時 `embedder none`,外觀向量全零,沒有證據可投 | `docs/M5_修復P1_預先登記_20260913.md` §8 |
| 探索格 `p1dino`(DINOv2 外觀)只改判 **79 次(0.15%)**,IDF1 沒有變好 | 同上 §8.8 |

**後果**:
- M4 的 track 中途換成另一個人(混人)→ 身份跟著被帶到別人身上,M5 不知道
- M4 每斷一次、重開 track → M5 就要重新猜一次
- 所以 M4 做不到完美,整套就不能用 —— M4 三輪修法都沒有有效解決,最好 IDF1 **0.4710**
  (`docs/M4_修法輪次_20260915.md` §5)

## 3. 為什麼外觀不能用來「每次偵測都認人」

| 情況 | 外觀分辨力 | 來源 |
|---|---|---|
| 同一台鏡頭、沒被擋 | d′ 2.21~2.39(分得開) | `docs/M4_誤偵組成診斷_20260915.md` §13 |
| 人擠在一起、框重疊的時刻 | 換人時刻選對約 60%、模糊出生 d′ 0.20~0.37(分不開) | 同上 §13、§14 |
| 不同鏡頭之間 | 可出貨的 armS d′ **0.118** | `docs/CHIRLA_預先登記_20260901.md` §9.5 |

⚠ 以上都是在 **CHIRLA(辦公室、每個人衣服不同)** 量的。實際廚房**戴口罩、穿同款制服**,外觀差異只會更小 ——
連「同鏡頭沒被擋時分得開」這一條都不能假設在廚房成立。**事先登記照片也沒用**(大家登記起來都一樣)。

8/28 的設計早已據此決定「不靠長相,靠空間與時間」(`docs/M4_M5_階段驗證報告_20260828.md`、`docs/M5_業主驗收操作手冊.md`)。

---

## 4. CHIRLA 測的是缺零件的版本

原設計(8/28)的身份證據:

| 證據 | 原設計 | CHIRLA 評估時 |
|---|---|---|
| 俯視全景鏡頭 | 身份骨幹,遮擋少 | ❌ 斜角鏡頭 |
| 地面校正(畫面座標 → 平面圖座標) | 業主驗收步驟 2 | ❌ 沒有標定資料,關閉 |
| 行走軌跡(速度、方向) | 需要地面校正 | ❌ 跟著關閉 |
| 重疊鏡頭的位置一致性 | 地面座標比對 | ❌ 退化成「k ≤ 8 必綁」的常數分數(`docs/M5_綁定規則實測_20260915.md`) |

→ **CHIRLA 的 M5 結果不能代表原設計**。

⚠ 但使用者確認**實際廚房的鏡頭也是斜角**:
- 原設計假設的「俯視、遮擋少」**在現場不成立**
- **M4 在 CHIRLA 上查到的遮擋問題(框重疊時分不出人、同一人被多開 track、交錯時換人)適用實際廚房**

## 5. 原設計零件齊全時的天花板

`docs/M4_M5_階段驗證報告_20260828.md` §10.1(模擬,未用真實多人資料校準):

| 項目 | 數值 |
|---|---|
| 地面校正 + 軌跡證據後的誤併率 | **約 5.6%**(報告寫 5~8%) |
| 驗收門檻 | 誤併率 ≤ 1%、IDF1 ≥ 0.90、碎裂率 ≤ 5% |
| 報告原話 | 「剩下的 5 倍缺口**目前沒有已知的演算法解**」 |
| 報告 §10.2 列出的補償 | 下游補償(事件標信心度、人工複核)、增加鏡頭(未測)、**可辨識標記(可望接近 0%,需人員配合)** |

⚠ 那個模擬假設俯視鏡頭;現場是斜角,實際可能更差(未量)。

## 7. 這份檢討不能回答什麼

1. 廚房的實際人數、鏡頭解析度與安裝高度都還不知道
2. 外觀在「口罩 + 同款制服」下的鑑別力沒有量過(推論只會比 CHIRLA 更差)
3. 可辨識標記在斜角鏡頭、實際距離下能不能穩定讀到,沒有測
4. 原設計的 5.6% 來自模擬,假設俯視鏡頭
