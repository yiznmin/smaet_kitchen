# M5 實際在用什麼規則綁定身份 —— M4 改善後仍綁不對的原因(2026-09-15)

> **探索性調查,不是預先登記。** 沒有事先寫下的判準與預測,結論只用於決定下一步,不作為任何修法的判定依據。
> 資料:`results/m5_step3/m5_cbiou`(最好的 M4 設定,主)與 `results/m5_step3/m5_base`(對照)。
> 每個結論都附驗證方式與可重現的工具;**未驗證的部分另外標明**。

---

## 1. 要回答的問題

步驟 3(`docs/M5_步驟3_追蹤器傳導_預先登記_20260915.md` §8)顯示,M4 換成 `cbiou` 之後:

| | `m5_base` | `m5_cbiou` |
|---|---|---|
| M5 要判斷的次數(可歸因) | 2,461 | 2,101 |
| 認對 | 257 | **210** |
| 誤併 | 1,433 | 1,251 |
| 碎裂 | 771 | 640 |
| 正確率 | 10.44% | 10.00% |

M4 少斷了,判斷次數少了,**認對的卻沒有增加**。為什麼 M4 做好了,M5 仍然無法正確綁定?

---

## 2. 結論

**在這個設定下,M5 決定「綁給誰」的分數,不含任何關於「這個人是誰」的資訊。**實際在運作的規則只剩兩條:

1. **有候選掛在重疊鏡頭上** → 分數 = `3.806 − ln k`(k 是那台重疊鏡頭上掛著的身份條目數)
   → **k ≤ 8 必定綁定** → 綁給 k 最小的那一個,**同分就任選一個**
2. **其他所有情況** → **結構上無法綁定** → 開新身份

規則 1 製造誤併,規則 2 製造碎裂。**M4 的改善只能改變這兩條規則各被觸發幾次,改變不了規則本身**,
所以判斷次數少了,正確率卻不動。這是 M5 評分在目前參數下的結構性質,不是 M4 的問題。

---

## 3. 證據

### 3.1 每一次綁定都來自重疊常數分數(資料)

判斷當下的候選組成(`m5_cbiou`,括號內為其中成功綁定的次數):

| | 沒有任何候選 | 第一名是常數重疊分數 | 第一名是非常數分數 |
|---|---|---|---|
| 真人決策 | 49(0) | 1,581(**1,488**) | 530(**0**) |
| 誤偵決策 | 17(0) | 878(**798**) | 218(**0**) |

- **成功綁定 2,286 次,全部來自常數分數**(工具內建一致性檢查);`m5_base` 為 2,600 次,同樣全部
- 第一名是非常數分數的判斷,分數最高 **−0.815**(`m5_base` −0.497),**0 次過門檻、0 次綁定**
- 綁定時的 k 分布:1 → 818 次、2 → 558、3 → 338、4 → 240、5 → 139、6 → 83、7 → 55、8 → 55
- 第一名是常數分數卻**沒綁定**的 172 次(`m5_base` 197 次),**全部是 k ≥ 9**,沒有任何 k ≤ 8 卻沒綁的

### 3.2 轉場路徑在結構上無法綁定(數學 + 程式碼)

工具:`scripts/diag_m5_score_ceiling.py`(直接呼叫 `CameraTopology` 的實作)。

**外觀項是負證據,不是中性。**`embedder none` 讓 cosine 恆為 0,而 `app_lr.llr(0) = −1.1937`
(對照:真的不同人 `llr(μ_diff = 0.465) = −0.031`)。**每個候選都被扣 1.19 分。**

各路徑理論上限(轉場項在最有利的 Δt + 外觀項;同鏡頭另加位置項最高值),門檻 **1.6094**:

| 路徑 | 轉場項最高 | 理論上限 | 過門檻? | 若外觀項為中性 0 |
|---|---|---|---|---|
| 同鏡頭 | 2.334(Δt 0.01 秒) | 5.211 | 是(但見下) | 6.404 |
| 有連結 camera_2 → 6 | 1.415 | 0.222 | 否 | 1.415 |
| 有連結 camera_6 → 7 | 2.678 | **1.484** | **否** | 2.678 |
| 有連結 camera_7 → 5 | 0.706 | −0.488 | 否 | 0.706 |
| 無連結(例 camera_1 → 2) | −1.219 | −2.412 | 否 | −1.219 |

**同鏡頭路徑的上限只在 Δt ≈ 0 時成立,而 Δt 實際上不可能那麼小:**

- 離場時間戳取自**跟丟當下**(`src/m5_reid/identity_st.py` 第 547–554 行,`_pending_exit`)
- 廚師要到**名下 track 全部 removed**(跟丟緩衝 5 秒到期)才進入轉場候選池 `gone`(第 576–580 行)
- 所以轉場路徑最早在 **Δt ≥ 5 秒**才會評分到這位廚師

| Δt | 同鏡頭總分(位置完全相同的最有利情況) | 過門檻? |
|---|---|---|
| 1 秒 | 2.792 | 是 |
| 2 秒 | 1.331 | 否 |
| **5 秒** | **−0.732** | **否** |
| 15 秒 | −5.732 | 否(超過 15 秒直接拒絕) |

**→ 在目前參數下,轉場路徑能拿到的最高分是 1.484,低於門檻 1.609。沒有任何一次綁定可能來自轉場路徑。**
而重疊路徑在沒有地面校正、F4 關閉時,分數就是 `overlap_llr(5.0) − ln k + (−1.1937)`。3.1 的資料是這個推導的佐證,不是證明的依據。

### 3.3 常數分數不能拒絕,也不含身份資訊

- **不能拒絕**:`3.8063 − ln k ≥ 1.6094` 等價於 k ≤ 8(k = 9 時 1.6090,差 0.0004 不過)
- **不含身份資訊**:k 只取決於那台重疊鏡頭上掛著幾個身份條目,**與這個人是誰無關**。
  ⚠ k 不是真人數:它是 `identity_st` 的 `overlap_pool`,包含誤偵開出的身份與跟丟未移除的 track;實測不綁定的判斷中 k 高達 20 以上

後果(`m5_cbiou`):

| 情況 | 次數 | 說明 |
|---|---|---|
| **正確的人在候選裡卻輸了(L3)** | 242 | 95 次**與第一名同分**、102 次**他所在的鏡頭 k 較大**、45 次他拿到的是非常數分數(轉場路徑,依 3.2 必定低於門檻) |
| **一個人第一次出現就被綁到別人身上** | 59 人中 **27** | 只要重疊鏡頭上有人掛著,新出現的人也一定會被綁走 |
| **認對的判斷** | 962 | 954 次有多個候選,**全部靠常數分數**;其中 156 次與第二名同分 —— **認對也是碰巧** |

### 3.4 誤併的源頭

把每個「真人 g 綁到不屬於他的身份 c」的配對,追到 g **第一次**被綁到 c 的那個判斷,並以後續綁定次數加權
(`m5_cbiou`:189 組配對、後續 1,183 次):

| 第一次綁入時的層 | 配對 | 後續綁定 | 佔比 |
|---|---|---|---|
| L3 正確的人在候選裡卻輸了 | 98 | 480 | 40.6% |
| L2 正確的人不在候選裡 | 66 | 397 | 33.6% |
| L0 第一次出現 | 23 | 299 | 25.3% |
| L4 | 2 | 7 | 0.6% |

- **57.1%** 的源頭判斷,當下與第二名**同分**
- **30.1%** 的誤併綁到**由誤偵開出的身份**上(誤偵開出 315 個身份,其中 21 個後來被真人綁入,共 448 次)
- 源頭判斷的分數**全部**是常數重疊分數(k = 1~8)

### 3.5 碎裂的來源

`m5_cbiou` 碎裂 640 次 = L2 547 + L3 45 + L4 48。依 3.2,**正確的人若只能經由轉場路徑回來,結構上必定碎裂**。

### 3.6 對照:M4 改變,結構不變

`m5_base` 的每一項都呈現同樣結構:2,600 次綁定全部來自常數分數;誤併源頭 L3 37.7% / L2 34.9% / L0 27.3%;
第一次出現 59 人中 27 人被綁到別人身上;非常數分數最高 −0.497。**換 M4 沒有改變 M5 的判斷規則。**

## 4. 更正先前的說法

1. **`docs/M5_根因分解_20260913.md` §8.1 層 1**:「誤併目標 99.2% 曾綁過誤偵 → embedding EMA 被污染」——
   9/12 以來的網格都是 `embedder none`,外觀向量恆為零,**外觀污染不成立**。
   誤偵的實際影響是:開出身份、被真人綁入、以及**被計入 k**(改變常數分數與排序)
2. **9/13 根因分解 §4.3 與步驟 3 預先登記 §1.1**:說重疊路徑「只掃**看得到**的 chef」—— 不精確。
   重疊路徑看的是廚師名下的 track 清單,track 要到 removed 才剪除(`identity_st.py` 第 566 行),**跟丟未移除的也算**。
   四層分解的次數本身不受影響
3. **本次調查過程中我報過三個錯誤數字,已在工具中修正**:
   - 「沒有任何候選 1,162 次」→ 實為 **66 次**(誤偵決策沒有 `n_cands` 診斷欄位,被讀成 0)
   - 「非常數分數最高 0.762」→ 那是 **k = 21 的常數分數**(3.80625 − ln 21 = 0.7617),被過小的 k 上限誤判
   - 早期版本判斷「是否為常數分數」在 k 空間用 ±0.01 比對,k 大時比對窗過寬;把常數由寫死的 3.8063 換成精確值時有 18 次判斷的分類翻轉,因此改在分數空間比對。**假命中率沒有另外量測**

## 5. 這對下一步的意義

### 5.1 已由本調查證明

在目前參數下,**M4 或偵測的任何改善(層 0、層 1),都只能改變「幾次判斷走進常數規則、幾次開新身份」,
不能讓任何一次判斷依據「這是誰」做選擇。**步驟 3 決策表指向層 1(誤偵過濾),
本調查顯示那個順序**不會改變綁定規則本身**。

### 5.2 推論(未驗證)

1. **補拓撲(層 2 的 overlapping)**會讓更多鏡頭對進入常數規則 → 預期把碎裂換成盲目綁定,誤併上升
2. **移除 cosine = 0 的 −1.19 懲罰**(換成真的 embedder,或把「沒有外觀」實作成中性)會讓 camera_6 → 7
   這條連結在數學上可以綁定;但 9/4 的 `coco_dino`(IDF1 0.1472)與 9/13 的 `p1dino`(0.1460)用 DINOv2
   都沒有比 `coco_none`(0.1512)好 —— **移除懲罰不等於有鑑別力**
3. 要讓 M5 真正選對人,需要**在重疊路徑上以能區分身份、而且能拒絕的證據,取代常數 `overlap_llr`**,
   並讓跟丟期間的廚師在非重疊鏡頭上也有被評分的機會

**下一步由使用者決定。**
