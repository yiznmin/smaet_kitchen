## 1. 為什麼要有 F4

F1/F2 是「不做沒有依據的綁定」,**它們不會讓證據變得有依據**。
2026-09-04 診斷出的主因是:

> `overlap_llr = 5.0` 這個常數在數學上**不可能拒絕**任何重疊候選
> (5.0 − log(k) + app < 1.609 需要 k > 29.7,而 CHIRLA 單台鏡頭同時最多 9 人)。

後果:重疊路徑 `p_break = 2.71%`、`p_false_merge = 80.80%`、
`p_correct = 16.49%`(≈ 1/6,與隨機挑一個無法區分)。

`GroundPlaneLR` 的類別說明早就寫了正解:

> 它取代 `overlap_llr = 5.0` 這個常數 —— 那是編的…**這是架構裡最後一個沒有物理依據的參數。**

但 `GroundPlaneLR` 要相機標定,而 **CHIRLA 沒有**。專案因此擱置了兩輪。

### 本輪的關鍵觀察

**沒有標定,但有逐幀真值身份。** 同一時刻兩台看到同一個人 → 那就是一組地面
對應點(取 bbox 底邊中點)。夠多組就能用 RANSAC 解出單應性 **H_AB**。

⚠ 這**不是**度量標定 —— 沒有公尺、沒有外參。它只回答
「這兩個觀測落在地面的同一點嗎」,而那正是重疊路徑缺的那條證據。

## 2. 設計(定死)

`CrossViewLR`(`src/m5_reid/evidence.py`),與 `GroundPlaneLR` 同一套數學:

```
LLR = log A − log(2πσ²) − d²/(2σ²)

d = A 的腳點經 H_AB 投到 B 之後,與 B 的腳點的殘差(B 的像素)
σ = 該鏡頭對的**實測**殘差尺度(像素)
A = 該對的共視區面積(B 的像素²)
```

**它取代 `overlap_llr` 常數,不是相加** —— 兩者回答同一個問題,相加會把
同一份證據算兩次。

### 三條先寫死的方法論規則

| # | 規則 | 防的是什麼 |
|---|---|---|
| **R1** | 單應性**只從推導集** `seq_000/001/002` 估 | `docs/CHIRLA_M4M5驗證_預先登記_20260903.md` §3 的紅線。腳本**硬編** DERIVATION,不提供 CLI 覆寫 |
| **R2** | σ 用**留出樣本**(30%)估,不是擬合殘差 | 擬合殘差系統性低估 → LLR 過度自信 → **把真正的同一人判成位置對不上**。合成實測:低估 16%,對真同人多扣 0.48 nats |
| **R3** | σ 是 pairwise 殘差,**不可再乘 √2** | 它已含兩台鏡頭的誤差。專案已在 `GroundPlaneLR`(第六輪)與 `VelocityLR`(第七輪)各踩一次,不要第三次 |

### 逐對估,不串接

`H_1→R = H_1→3 · H_3→R` 會累積誤差,而 CHIRLA 有些鏡頭對的共現只有 3 次。
逐對估的代價是沒有全域座標,好處是**每一對帶著自己實測的 σ,品質差的那對自己弱**。

### 沒有單應性的鏡頭對:自動退回舊常數路徑

CHIRLA 有 21 對相機,共現夠多的只有一部分。硬要求全有會直接不能跑。
**退回不是錯誤,但必須在結果裡報告有幾對退回了** —— 那些對的行為與基線相同。

## 4. 判準(先寫死)

### 4.1 主判準:加權成本(與 F1/F2 那輪同一個)

```
cost = 5 × p_false_merge + 1 × p_break
基線 coco_none = 5 × 0.5884 + 0.3133 = 3.255
```

### 4.2 F4 特有的主判準:**正確率**

F1/F2 只能把誤併換成碎裂,**不可能提升正確率**。F4 是本專案第一個
「把該綁哪一個判對」的修法,所以它要用正確率評:

| 結果 | 判定 |
|---|---|
| 重疊路徑 `p_correct` **> 50%** | F4 有效,重疊路徑不再是隨機猜 |
| 30 ~ 50% | 部分有效,要逐對看哪些鏡頭對沒改善 |
| **≤ 30%** | **F4 無效**。⚠ 但先查 R1~R3 有沒有實作錯,再下這個結論 |

基線是 **16.49%**(≈ 1/6,與隨機無異)。

## 6. 已知限制(報告要照抄,放在結論之前)

1. **單應性是用真值身份估的。** 在部署時,對應的是業主手冊的**安裝走動校正**
   (請一個人走過各鏡頭的重疊區)。**這個對應關係必須在報告裡講明**,
   否則會被當成用答案訓練。⚠ 而且要誠實說:安裝校正拿到的對應點數量與品質
   會低於 CHIRLA 推導集的三個序列。
2. **不是度量標定。** 沒有公尺,無法回答「兩人相距幾公尺」,
   也**不能**用來驅動 `VelocityLR`(它需要世界座標速度)。
3. **只修重疊路徑。** 轉場路徑的 54.42% 碎裂(病灶 5)本輪不動。
4. **CHIRLA 是辦公室不是廚房。** 絕對值不能當廚房預測值。
5. **`min-pairs = 200` 與 `ransac-px = 25` 是工程判斷不是實驗結果。**
   換門檻會改變哪些鏡頭對被建立。原始診斷存在 `crossview_fit.json`,可重算。
6. **內點率是診斷不是判準。** 合成測試中真實外點 10% 但內點率量到 0.73 ——
   RANSAC 的內點判定比預期保守。不得拿它當「H 好不好」的門檻,V3 用留出殘差。
