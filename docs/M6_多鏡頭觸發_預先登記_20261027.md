# M6 多鏡頭觸發 + 違規判定 —— 預先登記 2026-10-27

> 使用者 2026-10-27 指定範圍:觸發 + 違規判定都做。本節以上在跑之前寫好並 commit,結果只往 §8 之後追加。

## 1. 目的

目前每個觸發只用 1~2 台鏡頭:垃圾桶 = Aoutput1 手 + output0 身體;洗手 = Boutput1 / Boutput2 上方鏡頭。
EPFL 有 9 台鏡頭,同一個區域常有好幾台拍得到。本輪回答:

1. 多台鏡頭一起判斷,觸發是否更準?
2. **任一台鏡頭壞掉 / 被擋住時**,觸發還撐不撐得住?(多鏡頭真正的價值)
3. 接進違規判定(FSM)後,正確率有沒有變化?

## 2. 區域(zone)

SAM 3 在 9 台鏡頭各自提案(`scripts/m6_zone_proposals_multiview.py`,`results/m6/multiview/zones/`),目視後採用:

| 區域 | 鏡頭 | 來源 |
|---|---|---|
| 垃圾桶區 | output0、Aoutput1 | 既有(事件測試第 3 輪凍結,不改) |
| 垃圾桶區 | **Aoutput0、Aoutput2** | 新提案(35 / 41、37 / 41 場次找到) |
| 洗手台 | output0、Boutput1、Boutput2 | 既有(第 2 輪使用者確認) |
| 洗手台 | **Boutput0、Boutput3** | 新提案(41 / 41 場次;Boutput0 在畫面底緣) |

不採用:Aoutput0 / 1 / 2 的洗手台(只拍到遠處一角)、其餘鏡頭的垃圾桶(2–11 / 41 場次,目視為誤認)。
新 zone 寫在 `integrated/configs/zones/epfl_{Aoutput0,Aoutput2,Boutput0,Boutput3}.json`,**待使用者確認**;確認前只跑開發集。

偵測快取:事件片段原本只有 6 台,本輪補 Aoutput0、Boutput0、Boutput3(同設定:nano Arm A、704、stride 3、thr 0.05、全類別)。

## 3. 觸發 1:垃圾桶(事件片段分類)

資料、指標、切分全部沿用事件測試(`docs/M7_事件測試_預先登記_20261020.md`):
開發 = train 場次、測試 = test 場次(排除 YH2003/2023_05_17_09_08_58);垃圾桶片段為正例、其他類別為負例;片段層級 R / P / F1 / FAR;
遲滯平滑 (3, 2, 5) 後連續成立 ≥ T 秒即觸發。

| 組 | 內容 |
|---|---|
| base | 既有 trash_body 凍結設定(Aoutput1 手在 zone 且 output0 人框蓋 zone,±0.5 秒;thr_hand 0.2、x 0.2、T 1) |
| single_<鏡頭> | 單台:手中心在垃圾桶區(4 台各自一組) |
| kofn | 4 台的「手在 zone」各自 ±0.5 秒放寬後,至少 k 台成立(k = 1, 2, 3) |
| kofn_body | kofn 且 output0 人框蓋 zone(±0.5 秒) |

網格:thr_hand {0.2, 0.3} × T {0.5, 1, 2} × k {1, 2, 3}(kofn 類)× x {0.2}(body)。
「手」用不要求歸屬人框的版本(`zone_any_hand_series`,單人情境;近拍鏡頭常只拍到手臂)。
開發集選 F1 最高(同分取 R 高、再取 k 小),測試集只跑一次。

**斷鏡頭測試**(只用凍結設定,不再調):每次拿掉 4 台中的 1 台(該台輸出全設為不成立),重算測試集 F1。
base 只用 2 台,拿掉其中任一台就等於整組失效(拿掉 Aoutput1 → 手永遠不成立;拿掉 output0 → body 永遠不成立)。

## 4. 觸發 2:洗手 + 違規判定(FSM)

沿用 `docs/M6_違規判定_單人_預先登記_20261021.md` 的 24 個「沒洗手」事件、真值、FSM、計分(違規 R、合格辨識率、正確率;「未解除」算違規)。
這 24 個只有 2 個在 test 場次,太少,沿用第 1、2 輪作法:全部 24 個一起報,**網格小、結論保守**。

洗手方式:

| 組 | 內容 |
|---|---|
| close_hand(基準,第 2 輪凍結) | Boutput1、Boutput2 任一台手在洗手台 |
| close4_k | Boutput0–3 四台,至少 k 台手在洗手台(±0.5 秒放寬;k = 1, 2) |
| close4_k_body | close4_k 且 output0 人框蓋洗手台(±0.5 秒) |

網格:上述 × wash_s {1, 2} × D {1}(第 2 輪最佳 D)。
L1:觸發時刻 = 標註起點 + D(同第 2 輪)。
L2:垃圾類 8 個,觸發改用 §3 凍結的多鏡頭垃圾桶觸發,洗手用 L1 最佳組。

斷鏡頭測試:L1 最佳組每次拿掉 Boutput0–3 其中 1 台,重算正確率。

## 5. 假說與判準

| 編號 | 假說 | 成立條件 |
|---|---|---|
| MV-H1 | 多鏡頭垃圾桶觸發不比 base 差 | 測試集 F1 ≥ base 的 0.938 − 0.03,且 FAR ≤ 0.15 |
| MV-H2 | 多鏡頭垃圾桶觸發可承受單台失效 | 斷任一台時測試集 F1 都 ≥ 0.80(base 斷任一台必為 0) |
| MV-H3 | 4 台上方鏡頭看洗手不比 2 台差 | L1 最佳組正確率 ≥ 0.79(第 2 輪) |
| MV-H4 | 洗手可承受單台失效 | 斷 Boutput0–3 任一台時正確率都 ≥ 0.75 |
| MV-H5 | L2 用多鏡頭垃圾桶觸發仍可用 | 8 個中觸發偵測到 ≥ 7 個,且判對 ≥ 7 / 8 |

預期:MV-H1 大概成立(base 已經很高,難再提升);MV-H2 是本輪重點;MV-H3 大概持平(第 2 輪的錯誤來自觸發時間代理,不是洗手);
MV-H4 不確定(Boutput0 只拍到洗手台邊緣)。

## 6. 已知限制

- 測試集垃圾桶只有 15 個正例,F1 差 0.03 約等於 1 個片段。
- 違規 24 個事件全部用來選設定,正確率有過度樂觀的可能;只看相對比較。
- 斷鏡頭用「該台全無偵測」模擬,不是真的畫面遮擋(真的遮擋可能產生錯誤偵測而不是沒有偵測)。
- 新 zone 是 SAM 3 第一幀提案,鏡頭若在場次中移動會偏;§2 的 sessions 圖已看過大致一致。
