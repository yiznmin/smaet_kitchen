# M3 物件層評估方式 — 說明、為什麼、範例

> 目的:講清楚「怎麼量化評估 M3 偵測得好不好」、**為什麼用這些指標**、以及**具體範例**。
> 給不熟物件偵測評估的人也能看懂。版本 v1(2026-07-07)。

---

## 0. 為什麼要評估?

微調完模型,不能只「看幾張圖覺得還行」——那是主觀的。要用**客觀數字**回答:
- 刀到底抓到幾成?漏了多少?
- 微調有沒有真的變好?好多少?
- 哪一類最弱、要再補資料?

**評估 = 把「好不好」變成可比較、可追蹤的數字。**

---

## 1. 前提:要有「標好答案的測試集」

評估一定要有 **ground-truth(正確答案)**:一批圖,每個物件都人工框好、標好類別。
就是我們切出來的 **test 集**。模型在這些圖上預測 → 跟答案比對。

> ⚠ **test 集不能拿去訓練**(否則是「考自己出的題」,分數虛高)。train / valid / test 要分開。

---

## 2. IoU — 判定「框對了沒」

**為什麼需要**:模型的框不會跟答案框「完全重合」,總是差一點。要有個標準判斷「算不算框對」。

**IoU(Intersection over Union,交集/聯集)**:
```
IoU = 兩框重疊面積 ÷ 兩框聯集面積      (0~1)
```
- IoU=1 完全重合;IoU=0 完全沒疊。
- **規定 IoU ≥ 門檻(常用 0.5)才算「框對」** ——這就是 AP@50 的「50」。

**範例**:答案的刀框和模型的刀框,重疊面積 60、聯集面積 100 → IoU=0.6 ≥ 0.5 → 算框對 ✅。

---

## 3. TP / FP / FN — 每個預測歸類

**為什麼**:要數「對幾個、錯幾個、漏幾個」,才能算後面的指標。

| 名稱 | 意思 | 白話 |
|---|---|---|
| **TP** 真陽性 | 預測框 IoU≥0.5 且類別對 | 抓對了 |
| **FP** 假陽性 | 預測了但沒對到任何答案 | 亂報 |
| **FN** 假陰性 | 答案有,但模型沒預測到 | 漏抓 |

**範例**(test 集共 10 把刀):模型報 8 個刀框 → 6 個框到真刀(TP=6)、2 個框空處(FP=2)、4 把刀沒報(FN=4)。

---

## 4. Precision 與 Recall — 兩個角度

**為什麼要兩個**:只看一個會被騙。
- 只看 Precision:模型只報「最有把握的 1 個」→ Precision=100%,但漏一堆(沒用)。
- 只看 Recall:模型「整張圖亂框一百個」→ Recall 很高,但全是垃圾(沒用)。
- **兩個一起看才完整。**

```
Precision(精準)= TP/(TP+FP)   「你報的裡面,對的比例」
Recall(召回)   = TP/(TP+FN)   「該抓的裡面,你抓到的比例」
```

**接續刀範例**:
```
Precision = 6/(6+2) = 0.75   報的刀 75% 是真的
Recall    = 6/(6+4) = 0.60   真的刀只抓到 60%,漏了 40%
```
→ 食安上 Recall=0.60 危險(漏 4 把刀 = 漏 4 個可能事件)。

---

## 5. AP — 為什麼不用手挑門檻

**問題**:模型每個預測有**信心分數**。門檻調高→報少但準;調低→報多但雜。**P/R 會隨門檻變**,那要看哪個門檻?

**解法**:把門檻**從高掃到低**,每個門檻算一組 (Precision, Recall),畫成 **PR 曲線**;**曲線下的面積 = AP(Average Precision)**。

```
AP = PR 曲線下面積(0~1)
```
**為什麼好**:AP 一個數字就綜合了「所有門檻下的表現」,不用主觀挑門檻,**可直接比較模型好壞**。

---

## 6. mAP@50 vs mAP@50:95 — 嚴格程度

| 指標 | 意思 | 為什麼 |
|---|---|---|
| **mAP@50** | IoU 門檻 0.5 下,各類別 AP 的平均 | 「大致框到就好」,寬鬆 |
| **mAP@50:95** | IoU 從 0.5 到 0.95(每 0.05 一格)各算再平均 | **要求框很準**,COCO 標準嚴格 |

- **m** = mean(所有類別平均)。
- 我們主要看 **mAP@50**(有沒有抓到);要求定位精準時看 @50:95。

---

## 7. 為什麼要「各類別分開看」

平均會**藏住問題**:person AP 0.95、knife AP 0.05 → 平均 0.5「看起來還行」,但**刀根本不能用**。

```
只看 mAP:0.5(還好?)
拆開看:person 0.95 ✅、knife 0.05 ❌ ← 真相
```

**所以一定要看各類別 AP,尤其小物件(knife、tongs)** —— 那才是食安成敗的關鍵。

---

## 8. 對食安系統:為什麼 Recall 優先

本案是**事後查詢**(不是即時警報),且**漏掉事件的代價 >> 誤報**:
- 誤報(FP):人再去看一眼,發現沒事 → 花點時間。
- 漏報(FN):**沒人知道發生過** → 食安破口。

```
寧可多報(Precision 低一點,人再濾)
不可漏抓(Recall 一定要高)
→ 關鍵物件(刀、生肉)看 Recall,操作門檻調成高 Recall
```

---

## 9. 怎麼算(工具自動算)

不用手算。用現成工具在 test 集跑:

```python
import supervision as sv
# predictions:模型預測;targets:答案(ground-truth)
m = sv.MeanAveragePrecision.from_detections(predictions, targets)
print(m.map50, m.map50_95)        # mAP@50、mAP@50:95
# 各類別 AP 可從 m 取;Precision/Recall 可用 sv.ConfusionMatrix 或自算
```
或用 **pycocotools 的 COCOeval**:吃 COCO 格式(我們的 test 就是),直接印各類別 AP。

---

## 10. 必做:微調前 vs 後對比

**為什麼**:證明「微調有效」的最直接證據,就是同一個 test 集上,微調前後的數字對比。

| 類別 | 微調前 AP@50 | 微調後 AP@50 | 提升 |
|---|---|---|---|
| knife | ~0.02 | ? | ? |
| cutting_board | ? | ? | ? |
| raw_meat | ? | ? | ? |
| person | ~0.9 | ~0.9 | ~ |

**knife 從「幾乎 0」往上動 = 微調有效**。person 本來就高,不是重點。

---

## 一句話總結

**M3 物件評估流程**:
```
標好 test 集 → 模型預測 → 用 IoU 判框對沒 → 數 TP/FP/FN
→ 算 Precision/Recall → 掃門檻得 AP → 各類別分開看(尤其刀)
→ 食安看 Recall → 微調前後對比
```
工具(supervision / pycocotools)自動算,你只要備好 test 集答案。
