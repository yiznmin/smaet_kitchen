## 4. 方法(`src/m6_assoc/`)

**單幀關聯**(`association.py`):

1. 人框:「人」且 conf > 0.3(固定)
2. 手框:「手」且 conf > thr_hand,IoA(手, 人框) ≥ 0.5(固定)→ 指派給 IoA 最大的人
3. 物件 o 與人 p 有關聯:
   - p 有手:o 與 p 任一手的框間距 ≤ d × p 的框高 → 證據 "hand"
   - p 沒偵測到手(退路):IoA(o, p 的上半身框) ≥ x_upper → 證據 "upper_body"

**時序平滑**(`smoothing.py`):遲滯狀態機,最近 n 步有 k_on 步成立才開、連續 k_off 步不成立才關;開關點回推到真正有證據的那一步。

**多視角融合**(只當參考):同一時間步至少 k 台成立 → 再平滑。

**兩條基準線**(同一快取、同一平滑網格、同一選擇規則):

- base_present:畫面裡有這類物件就算接觸
- base_person:物件與任一人框 IoA ≥ x_person 就算接觸(不用手)

## 5. 指標(`src/m6_assoc/metrics.py`)

時間軸 = 快取取樣點(0.1 秒一步)。所有指標都把 7 類的計數**加總(pooled)**後計算;各類別另列,樣本少(砧板 4 回合、鍋鏟 5 回合)不下結論。

| 指標 | 定義 | 角色 |
|---|---|---|
| **逐段 Recall** | GT 回合有 ≥ 50% 時間步被預測為正 → 抓到 | **主指標** |
| **逐段 Precision** | 預測區間有 ≥ 50% 落在 GT(往外擴 0.5 秒)內 → 正確 | **主指標** |
| 逐時間步 P / R / F1 | GT 聯集內 = 正例;距 GT 邊界 ≤ 0.5 秒的時間步不計分 | 輔助 |
| F1@τ(τ = 0.1 / 0.25 / 0.5) | MS-TCN / EPFL 基準定義:預測段與 GT 段一對一配對,tIoU ≥ τ 算 TP | 輔助,對外可比較 |

已用合成資料確認:把 GT 當預測 → 全部 1.0;整片全開 → 逐段 P = 0(定義不能被「一直報」騙過)。

**單視角**:每台各算一次,報 **9 台中位數**(主);逐台明細全列;另報「事後最好 3 台」平均,標示為事後挑選、只當參考。

### 9.4 檢討(看完結果後的診斷,非預先登記)

1. **主要錯誤是「認錯物件」,不是「沒偵測到接觸」**。以選定的 m6 設定在 Aoutput1、Aoutput2、output0 上拆誤報:
   各類誤報有 **68%~99%(多數約 90%)發生在人正在接觸「另一個」物件的時間**。
   檯面上刀、砧板、碗堆在手邊,「離手 d 以內就算」會把手附近**每一個**物件都算成接觸。
   - 原本懷疑的「EPFL 一段只標一個名詞,`Cut Tomatoes` 沒標刀和砧板」只解釋一小部分:刀的誤報 0% 落在 `Cut` 內(`Hold Knife` 已涵蓋),砧板約 20%~25%
   - 砧板最嚴重(逐步 P 0.03~0.10):砧板面積大、一直在手底下
2. **逐段指標有漏洞**:逐段 Precision 以「區間個數」計,碎成很多短區間就能拉高。
   base_present 融合的逐段 P 0.551、F1 0.708 是全表最高,但逐步 P 只有 0.193 —— 它幾乎一直報。
   §1 的合成檢查只擋住「一整段全開」,擋不住「碎片化」。**之後以逐步 F1 為主要判讀依據,逐段指標只當輔助**。
3. 鏡頭角色分工有效(H5、H6),之後的實驗都在「角色分工(自動定位)」這個設定上做。
4. 選定 m6 設定的關聯區間裡,93.0% 的時間步證據是「手」、7.0% 是上半身退路(`associations.jsonl` 統計)—— 主要問題不在沒偵測到手。
