## 1. 不可更動的規則

### 1.1 模型
- **RF-DETR**(`rfdetr` 套件,授權 Apache-2.0,可商用)。**不要換別的模型**。
- 變體:**nano 和 medium 各微調一次**,把兩者的 AP/Recall 交回來比較,由我方決定最終用哪個。

### 1.2 類別(11 類,名稱與順序絕對不能改)

| 順序 | 類別 | 說明 / 框什麼 |
|---|---|---|
| 1 | 人 | 整個人(含身體)。 |
| 2 | 刀具 | 菜刀、水果刀等手持刀。 |
| 3 | 砧板 | 切菜板。 |
| 4 | 食材 | 所有食物/食材**統一算這一類**(不分肉/菜/蛋)。 |
| 5 | 鍋鏟 | 鏟子、湯勺等翻炒/舀取器具。 |
| 6 | 鍋子 | 炒鍋、湯鍋。 |
| 7 | 手 | 露出的手/手掌(有戴手套時框「手套」不框「手」)。 |
| 8 | 容器 | 碗、盆、保鮮盒、料理盆等。 |
| 9 | 抹布 | 抹布、擦手巾。 |
| 10 | 夾子 | 料理夾。 |
| 11 | 手套 | 戴在手上的手套。 |

> **重點**:類別的**名稱(中文)與順序**不能改。
> **不用自己煩惱 id**:只要用我方提供的標註器(下方 2.2 的指令)產生標註,COCO 的 category id 會自動照這個順序排好(標註檔內是 1~11,模型訓練後預測出來是 0~10,兩者由我方腳本自動對應——你不用手動處理,**只要別改 `--classes` 的內容和順序即可**)。

### 1.3 不要標的東西(避免浪費工)
- **固定不動的區域**(灶台、洗手台、地板範圍)→ 我方用「區域框(zone)」另外處理,**不是物件**,不要框。
- **老鼠、水漬潑灑** → 由另一條動態偵測分支處理,**不在這 11 類**,不要框。
- **嘴巴/頭部姿態** → 屬姿態辨識,不在範圍,不要框。

## 2. 準備資料(你的主要工作)

流程:**影片 → 抽幀成圖 → 每張圖用 bbox 框出 11 類 → 切 train/valid/test → 打包 zip**

### 2.1 抽幀(把影片變成一張張圖)
最簡單用 ffmpeg,例如每 2 秒抽一張:
```bash
ffmpeg -i 你的影片.mp4 -vf "fps=1/2" frames/frame_%05d.jpg
```
建議:
- **量**:至少幾百張起跳,越多越好。
- **多樣性**:涵蓋不同時段、光線、鏡位、有人/沒人、不同料理動作——比「張數多但都很像」更重要。
- 優先挑**有動作、桌面上有物件**的畫面,空景少放。

### 2.2 標註(框 bbox)

**標註器要用你自己的圖片重新產生一份**(圖片是嵌在 HTML 裡的,不能直接沿用我方那份)。
只需要 Python + `opencv-python`、`numpy`,在專案目錄執行:

```bash
pip install opencv-python numpy
python scripts/make_bbox_labeler_html.py \
   --img_dir 你的frames資料夾 \
   --out results/m2/labeler_real.html \
   --classes 人,刀具,砧板,食材,鍋鏟,鍋子,手,容器,抹布,夾子,手套
```
> ⚠ `--classes` 的**內容與順序照抄上面這串**,一個字都不要改(這決定了類別對應)。

產生後**雙擊 `labeler_real.html`** 用瀏覽器打開(全程本機、不上傳):
- 拉滑鼠畫框框住物件 → 下拉選單或**數字鍵**選類別 → `←/→` 換圖 → `d` 刪最後一框。
- 標完按 **⬇ 匯出 coco.json**。
- 沒出現的物件就跳過,不用硬框。

**標註品質要求**:
- 框要**貼緊**物件邊緣(太鬆會拉低 AP)。
- **同一張圖裡所有出現的目標物件都要框**(漏框會被模型學成「這裡沒東西」)。
- 被部分遮住的物件,框**可見的部分**即可。

### 2.3 切分資料集
用 `scripts/split_coco.py`(把標好的 COCO 切成 train/valid/test):
```bash
python scripts/split_coco.py --labeled 你的標註.json --img_dir 圖片資料夾 --out_base dataset_out
```
產出 `dataset_out/{train,valid,test}/`,每個資料夾內含圖片 + `_annotations.coco.json`。把 `dataset_out` 壓成 **`dataset.zip`**。

## 3. 微調(Colab 免費 GPU 即可)—— 用一鍵筆記本,不用改任何程式

我方已把整個流程做成**一鍵筆記本 `notebooks/m3_finetune.ipynb`**,它會**自動**:
- 跑 **nano 和 medium 兩個變體**(不用手動改模型);
- 各自產出「**微調前(COCO 原始)**」vs「**微調後**」的偵測數據;
- 印出每個變體的 **per-class AP 表**;
- 最後印出總結表,並自動下載 `m3_compare_results.json` + 兩個權重。

### 操作(三步)
1. 到 https://colab.research.google.com → **檔案 → 上傳筆記本** → 選 `m3_finetune.ipynb`。
2. **執行階段 → 變更執行階段類型 → 硬體加速器:GPU(T4)**。
3. **執行階段 → 全部執行** → 跳出選檔時上傳你的 `dataset.zip`。

> ⏱ 兩個模型都要訓練,總共約 **60~90 分鐘**,請保持分頁開著、別關電腦。
> 💾 跑完瀏覽器會自動下載:`m3_compare_results.json`、`out_nano/checkpoint_best_regular.pth`、`out_medium/checkpoint_best_regular.pth`。
> ⚠ OOM(記憶體不足)時,把筆記本第 4 格的 `resolution` 從 704 降到 640。

### 關鍵設定(筆記本內已寫好,列出供你了解)
| 參數 | 值 | 說明 |
|---|---|---|
| epochs | 60 | 訓練輪數 |
| batch_size | nano 4 / medium 2 | medium 較吃記憶體 |
| resolution | 704 | 高解析度救小物件;必須是 32 的倍數 |
| lr | 1e-4 | 學習率 |

## 4. 怎麼判斷微調成功

| 看什麼 | 好的樣子 |
|---|---|
| val 的 **mAP@50** | 越高越好(bootstrap 90 張就到 ~0.85;真實資料多應更高更穩)。 |
| **各類別 Recall**(食安最重要) | **刀具、砧板、食材、手**的 Recall 越高越好——代表「不漏抓」,食安寧可多抓不可漏。 |
| test 圖預測 | 開始正確抓到刀具/砧板/食材等自訂類別(不是只有 person)。 |

**交回時附上這些數字**,我方會據此決定最終用 nano 還是 medium。

## 5. 常見雷(照做可避開)

| 症狀 | 原因 | 修法 |
|---|---|---|
| `No module named 'pytorch_lightning'` | 只裝了推理版 | 裝 `"rfdetr[train,loggers]"` |
| `resolution not divisible by 32` | 解析度不是 32 倍數 | 用 704 或 640 |
| 每張圖偵測結果一模一樣 | 呼叫了 `optimize_for_inference()` | 別呼叫,直接 predict |
| 類別顯示成英文 person/bowl | 用了 COCO 預設名 | 用 `det.class_id` + 自訂 NAMES |
| 免費 GPU 用到額度上限 | Colab 免費有上限 | 等幾小時~隔天冷卻,或改用 Kaggle Notebooks(獨立額度) |
| `files.upload()` 一直沒反應 | 在等你選檔 | 點「選擇檔案」選 dataset.zip |
