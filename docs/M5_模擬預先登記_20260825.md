## 2. 三個修法(設計已定,實作前登記)

### F1 未建模路徑(繞路)

不再硬拒沒有連結的鏡頭對,改成給它一個**寬且帶先驗懲罰**的轉場模型:

```
LLR_unknown = log p(Δt | 走了未建模路徑) − log λ_bg + log P(走未建模路徑)
```

- `p(Δt | 未建模)`:對數常態,中位數 = `median_multiplier × 該場域典型轉場時間`,
  `log_sigma` 大(路徑未知 → 時間變異大)
- `log P(走未建模路徑)`:負的先驗懲罰,確保「有連結的路徑」永遠優先於「沒連結的」

**預期副作用**:任何鏡頭對都變成候選 → 候選數上升 → 誤併率上升。這是要量的代價。

### F2 逗留尾部

系統目前的 `tau_loiter_s=20`。真實廚房的停留(洗手、處理食材)常在 30~120 秒,
20 秒太短 → 尾部太薄 → 長延遲的 LLR 掉到門檻以下。

修法:把系統的逗留尾部**刻意設得比預期更重**(保守方向),因為碎裂是主導失效模式。
具體值在 §3 掃描中決定,但**方向事先講死:只往加重尾部的方向調,不往減輕調**。

### F3 同鏡頭重關聯(M4 斷軌)

新增一條路徑:若某 chef 的出口在**同一台**鏡頭、且 Δt 很小,視為 M4 斷軌而非
真的離場再回來。

```
LLR_same_cam = log p(Δt | 軌跡中斷) − log λ_bg
p(Δt | 軌跡中斷) = Exp(1/tau_break),僅在 Δt ≤ max_gap_s 內有效
```

⚠ 目前只用時間,**不用位置**。`identity_st.py` 的 `bbox` 參數仍是死參數,
若日後接上,加入「斷軌前後 bbox 接近」會顯著收緊這條路徑、降低誤併。
本輪不做,但在此登記為已知的可強化點。

## 5. 已知會被質疑、事先說明的點

1. **世界參數仍是估計值**(`p_loiter=15%` 等)。所以本輪量到的是「相對改善量」,
   不是「絕對準確率」。改善的**方向與量級**可信,絕對值不可信。
2. **F2 是在調系統參數去貼近世界**,有「偷看答案」的嫌疑。緩解:世界的
   `tau_loiter_s=20` 固定不動,系統掃 20/45/90 —— **系統的最佳值若不是 20**
   (即不是世界的真值),才證明這不是偷看,而是「保守設定優於正確設定」的真實效果。
   這個檢查會在報告中明列。
3. **F1 幾乎必然抬高誤併率**。若最終要在碎裂與誤併之間取捨,取捨依據是
   §4 的成本比(誤併嚴重 5 倍),不是哪個數字比較好看。

## R4 逐項診斷

**F1 繞路 —— 幾乎無效。** 未建模路徑模型在 Δt=8s 給出 1.62 nats,剛好壓在門檻
1.61 上;但世界的繞路轉場是直達時間的 1~4 倍(中位數約 8~17s),多數落在
分布尾端。放寬先驗到 −1 只把碎裂帶到 18.5%,仍是 C 級,且誤併同步上升。

**F2 逗留 —— 登記的旋鈕方向錯誤。** 登記時假設「加大 τ = 尾部更重」,實際上
指數分布是正規化的:τ 變大會把質量攤到更遠處,**在中等延遲(Δt≈25s)反而
密度更低**。實測 τ=20 優於 45 與 90,與登記時的預期相反。
要修 F2 需要的是**改變尾部形狀**(指數 → 重尾如對數常態/冪律)或調
`p_loiter`/`λ_bg`,那些**不在本次登記網格內**,因此本輪不做,列為未解。

**F3 同鏡頭重關聯 —— 降碎裂但誤併翻倍,淨值為負。** 碎裂 −4.3pp、誤併 +5.4pp。
根因與登記時標註的可強化點完全一致:**只用時間無法分辨「同一台鏡頭裡的哪一位
廚師」**。同鏡頭同時有多人時,斷軌的片段會綁到錯的人。需要位置證據(bbox)才收得緊,
而 `identity_st.py` 的 `bbox` 參數目前仍是死參數。

## A5 過程中發現的一個陷阱(記錄下來免得重蹈)

把 F1/F3 的預設從「開」改成「關」之後,`compare_fixes` 的變體仍靠「預設開啟」

## A6 位置模型的一個缺陷(過程中發現並修掉)

初版 `PositionLR` 的 σ 隨 Δt 無上限成長,於是**長間隔時「同一人」的位置分布
比「均勻散布在畫面上」還稀疏**,給出莫名其妙的負證據(Δt=20s、跨半個畫面
得到 −2.96 nats,且隨 Δt 持續惡化)。

物理上這是錯的:人再怎麼走也走不出畫面,所以「同一人」的分布最多就是均勻。

修法:
- σ 上限設為畫面均勻分布的標準差 `span/√12`
- 加一個小的均勻混合成分(偵測跳框、被完全遮擋後從別處出現)

修完後長間隔的 LLR 飽和在 −0.79(20s 與 60s 相同),不再隨時間惡化。
S13 的「間隔久了自動失效」就是鎖這個行為。

## A7 第二次踩到同一個坑

A5 記錄了「變體不可依賴預設值」。把 F3 改成預設開啟後,我**又踩了一次**,
只是方向相反:「基準(三者皆關)」那一列用 `build()` 不帶參數,於是靜默變成
「含 F3」,與 `+F3` 那列數字完全相同。

已改成**每一列顯式指定所有開關**,一個都不靠預設。教訓比 A5 更強:
不是「改預設時要記得改變體」,而是**比較實驗的變體本來就不該讀預設值**。
