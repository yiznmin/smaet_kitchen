## 1. 為什麼:我們丟掉了 96% 的證據

2026-09-12 的修復網格,四個修法(F1/F2/F4/F5)**沒有一個讓系統更常綁對**。
F4 補上跨鏡頭位置證據後,重疊路徑正確率反而從 16.49% **掉到 6.07%**。

本輪的診斷指向一個與「證據不夠強」不同的方向:**證據用得不夠多次**。

`identity_st.py` 的 `on_new_track` 在 track **出現的那一瞬間**做一次綁定決策,
之後 `on_track_update` 只更新狀態,**不再重新評估身份**。

本機實測(`results/m5_full9/tracks.csv`,EPFL 九台全長):

```
93 條 track,存在的迴圈數:中位 31 / p90 4663 / 最長 4680
→ 中位有 31 次機會,我們只用了 1 次
```

**單幀證據很弱(外觀 0.062 nats、位置 1.12 nats),但一條 track 有幾十到幾千幀。**
弱證據 + 單次決策 = 擲硬幣;弱證據 + 多次投票 = 可靠。

實測完全吻合:重疊路徑正確率 16.49%,中位 7 人同時在場 → 1/7 = 14.3%。

### 依據:AI City Challenge Track 1 冠軍法

`Enhancing Multi-Camera People Tracking with Anchor-Guided Clustering and
Spatio-Temporal Consistency ID Re-Assignment`(CVPR 2023W,IDF1 **95.36**)
用的正是**滑動窗多數決** —— 逐幀用 Hungarian 指派,再用多數決定案。

⚠ **那個 95.36 不可直接對比**:他們有俯視圖、合成資料預訓練、五個 Re-ID 模型
串接、YOLOv7(GPL)。可移植的是**決策程序**,不是分數。

## 2. 設計(定死)

```
每收到 stride_loops 次 on_track_update → 用**完全相同**的評分邏輯重算一次候選
→ 投一票(過不了門檻就投「維持現狀」)
→ 滑動窗(window)保留最近幾票
→ 領先者比現任多 switch_margin 票 → 改判
```

### 四條先寫死的規則

| # | 規則 | 防的是什麼 |
|---|---|---|
| **R1** | 投票走 `_score_candidates`,與 `on_new_track` **同一個函式** | 兩條路若分歧,投票結果就不能和出生時的決策相比,累積投票失去意義 |
| **R2** | `stride_loops` **從資料量**,不得用猜的 | 連續幀高度相關。直接累加 31 幀 × 1.12 nats = 35 nats 是**假的自信** —— 與 `VelocityLR`(第七輪 OU 去相關)、`GroundPlaneLR`(第六輪 √2)同一類的坑。所以 **(a) 用多數決不用 LLR 相加、(b) 間隔取自實測** |
| **R3** | 重新投票時 **exclude_key 排除這條 track 自己** | 不排除的話,現任 chef 會因為「他正在這台鏡頭上」而自我佐證,投票永遠投給現任 |
| **R4** | 拿不到 embedding 就**不投票**,且計數器看得見 | 用預設值硬投等於投一張沒有根據的票。靜默失效是本專案最在意的那種錯 |

### `stride_loops` 的實測依據

`scripts/measure_evidence_decorrelation.py` 在 EPFL 九台上量:

```
腳點位移中位超過 σ 需要的 Δ迴圈:
  σ= 8.0px → 5    σ=16.9px → 12    σ=37.1px → 30    σ=74.7px → 80
建議取樣間隔 ≥ 8 個迴圈(1.33 秒)
```

⚠ 「位移 > σ」是**保守**判準:它只代表證據會變,**不代表兩次觀測獨立**。
真正的獨立需要位移遠大於人與人的典型間距。報告不得把它講成「獨立」。

### 誰會受惠 —— 時間加權後很清楚

| 可投票數 | track 數佔比 | **佔總追蹤時間** |
|---|---|---|
| 1 票 | 53.8% | **0.6%** |
| 2~7 | 26.9% | 1.8% |
| **≥8 票** | **19.4%** | **97.6%** |

**能投 ≥8 票的只佔 19.4% 條數,卻佔 97.6% 的追蹤時間** —— 而那些正是主導 IDF1 的。

## 4. 判準(先寫死,採用 9/12 修正後的三層)

### 4.1 主判準:**IDF1 必須上升**

```
基線 IDF1 = 0.1214
IDF1 > 0.1214  → 可以進一步考慮
IDF1 ≤ 0.1214  → **修法無效**,不論其他數字多好看
```

### 4.2 硬性約束:**正確率不得低於基線**

```
基線正確率 = 9.83%
```

### 4.3 `cost` 降級為排序工具(不再是門檻)

### 4.4 硬性驗收(不通過就是實作錯,不是效果不好)

| # | 條件 |
|---|---|
| V1 | `base` 與 2026-09-12 的 `base` **逐位相同** |
| V2 | `p1` 的 `revotes` **> 0** —— 否則投票根本沒發生 |
| V3 | `p1` 的 `revote_no_emb` **= 0** —— 有的話表示 runner 沒把 embedding 接上,整輪無效 |
| V4 | 每格的重疊路徑決策數仍是 922、轉場 814 —— 沒有決策憑空消失 |
| V5 | `src/m5_sim/world.py` 未被動到 |

### 4.5 ⚠ 本輪特有的失敗條件

若 `p1` 的 **ID switch 數比基線高出超過 50%**,判定為
**「投票在製造新的身份跳換」**。

處置先寫死:**提高 `switch_margin`**(讓改判更保守),
⚠ **不是**降低 `min_votes` 或縮短 `window` —— 那會讓投票更不穩定。
若 `switch_margin` 提到 5 仍無效,結論是「這份資料上的證據不足以支撐改判」,
應**關閉 P1** 而不是繼續調。

## 5. 事先寫下的預測(可被否證)

| # | 預測 | 依據 |
|---|---|---|
| **1** | `p1f4` 的重疊路徑正確率 **> 30%**(基線 16.49%) | 投票把弱證據累積起來;訂 30% 而非 50% 是因為單票偏好可能很小 |
| **2** | `p1`(無 F4)的改善**小於** `p1f4` | 沒有 F4 時每票只靠外觀 0.062 nats,投再多次也收斂得慢 |
| **3** | 短 track(< 3 票)的行為與基線**完全相同** | `min_votes = 3` 的設計保證 |
| **4** | `p1f4` 的 **IDF1 > 0.1214**(本輪必須達成的目標) | 主判準 |
| **5** | `revote_switch` 佔 `revotes` 的比例 **< 20%** | 多數票應該同意現任;比例過高表示投票不穩定 |

⚠ 預測 1 與 4 若**同時不成立**,而 V2/V3 都通過(投票確實發生了),
則結論是「**累積投票在這份資料上無效**」,而不是實作問題。
那會是一個重要的否定結果:它表示證據弱到連投票都救不了。

## 6. 已知限制(報告要照抄,放在結論之前)

1. **這不是冠軍法。** 冠軍法還有 Hungarian 全域指派(P2)與 anchor
   (同一人多個特徵向量)。本輪只做投票,是三者裡最便宜的一項。
2. **`stride_loops = 8` 量自 EPFL 不是 CHIRLA。** EPFL 全片單人、幾乎無遮擋,
   CHIRLA 有 6~7 人同時在場,track 會更短更碎。**遠端應先在 CHIRLA 的
   tracks.csv 上重跑 `measure_evidence_decorrelation.py`**,若建議值不同,
   照 CHIRLA 的值 —— ⚠ 但那要在**看到評估結果之前**決定。
3. **投票開啟後每幀每條 track 都要抽 crop 跑 embedder**,成本會上升。
   關閉時不付這個成本(runner 只有 revote 開啟時才抽 crop)。
4. **CHIRLA 是辦公室不是廚房。** 絕對值不可當廚房預測值。
5. **`window`/`min_votes`/`switch_margin` 是工程判斷不是實驗結果。**
   換值結果會變;§4.5 已先寫死唯一允許的調整方向。
