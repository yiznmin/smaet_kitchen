## 1. 為什麼:我們丟掉了 96% 的證據

2026-09-12 的修復網格,四個修法(F1/F2/F4/F5)**沒有一個讓系統更常綁對**。
F4 補上跨鏡頭位置證據後,重疊路徑正確率反而從 16.49% **掉到 6.07%**。

本輪的診斷指向一個與「證據不夠強」不同的方向:**證據用得不夠多次**。

`identity_st.py` 的 `on_new_track` 在 track **出現的那一瞬間**做一次綁定決策,
之後 `on_track_update` 只更新狀態,**不再重新評估身份**。

本機實測(`results/m5_full9/tracks.csv`,EPFL 九台全長):

```
93 條 track,存在的迴圈數:中位 31 / p90 4663 / 最長 4680
→ 中位有 31 次機會,我們只用了 1 次
```

**單幀證據很弱(外觀 0.062 nats、位置 1.12 nats),但一條 track 有幾十到幾千幀。**
弱證據 + 單次決策 = 擲硬幣;弱證據 + 多次投票 = 可靠。

實測完全吻合:重疊路徑正確率 16.49%,中位 7 人同時在場 → 1/7 = 14.3%。

### 依據:AI City Challenge Track 1 冠軍法

`Enhancing Multi-Camera People Tracking with Anchor-Guided Clustering and
Spatio-Temporal Consistency ID Re-Assignment`(CVPR 2023W,IDF1 **95.36**)
用的正是**滑動窗多數決** —— 逐幀用 Hungarian 指派,再用多數決定案。

⚠ **那個 95.36 不可直接對比**:他們有俯視圖、合成資料預訓練、五個 Re-ID 模型
串接、YOLOv7(GPL)。可移植的是**決策程序**,不是分數。

## 2. 設計(定死)

```
每收到 stride_loops 次 on_track_update → 用**完全相同**的評分邏輯重算一次候選
→ 投一票(過不了門檻就投「維持現狀」)
→ 滑動窗(window)保留最近幾票
→ 領先者比現任多 switch_margin 票 → 改判
```

### 四條先寫死的規則

| # | 規則 | 防的是什麼 |
|---|---|---|
| **R1** | 投票走 `_score_candidates`,與 `on_new_track` **同一個函式** | 兩條路若分歧,投票結果就不能和出生時的決策相比,累積投票失去意義 |
| **R2** | `stride_loops` **從資料量**,不得用猜的 | 連續幀高度相關。直接累加 31 幀 × 1.12 nats = 35 nats 是**假的自信** —— 與 `VelocityLR`(第七輪 OU 去相關)、`GroundPlaneLR`(第六輪 √2)同一類的坑。所以 **(a) 用多數決不用 LLR 相加、(b) 間隔取自實測** |
| **R3** | 重新投票時 **exclude_key 排除這條 track 自己** | 不排除的話,現任 chef 會因為「他正在這台鏡頭上」而自我佐證,投票永遠投給現任 |
| **R4** | 拿不到 embedding 就**不投票**,且計數器看得見 | 用預設值硬投等於投一張沒有根據的票。靜默失效是本專案最在意的那種錯 |

### `stride_loops` 的實測依據

`scripts/measure_evidence_decorrelation.py` 在 EPFL 九台上量:

```
腳點位移中位超過 σ 需要的 Δ迴圈:
  σ= 8.0px → 5    σ=16.9px → 12    σ=37.1px → 30    σ=74.7px → 80
建議取樣間隔 ≥ 8 個迴圈(1.33 秒)
```

⚠ 「位移 > σ」是**保守**判準:它只代表證據會變,**不代表兩次觀測獨立**。
真正的獨立需要位移遠大於人與人的典型間距。報告不得把它講成「獨立」。

### 誰會受惠 —— 時間加權後很清楚

| 可投票數 | track 數佔比 | **佔總追蹤時間** |
|---|---|---|
| 1 票 | 53.8% | **0.6%** |
| 2~7 | 26.9% | 1.8% |
| **≥8 票** | **19.4%** | **97.6%** |

**能投 ≥8 票的只佔 19.4% 條數,卻佔 97.6% 的追蹤時間** —— 而那些正是主導 IDF1 的。

## 2b. P2 Hungarian 全域指派(同日追加,仍在跑任何一格之前)

⚠ **本節與 §1–§7 同屬「跑之前定稿」的範圍。** 追加時尚未執行任何一格。

`revote.assignment` 從 `"greedy"` 換成 `"hungarian"`:同一台鏡頭、同一取樣輪的
所有 track 與候選做**全域一對一**最佳指派,而不是每條各自搶最高分。

專案內的 MTMCT PDF 與 AI City 冠軍法都用這個。**F2(同鏡頭互斥)是它的粗糙版**
—— F2 只能說「這個候選不准選」,Hungarian 會**重新安排整組配對**。

實作要點(先寫死):

| # | 規則 | 理由 |
|---|---|---|
| A1 | 它**只作用在投票路徑**上 | `on_new_track` 是逐條事件進來的,同一幀同時出現多條新 track 很罕見,在那裡做批次指派收益極小而複雜度高 |
| A2 | 不可行的配對給**大成本而不是 inf** | `linear_sum_assignment` 在無完美匹配時遇到 inf 會直接丟例外 |
| A3 | 沒被指派到 → 投「維持現狀」 | 與 greedy 的語意一致,不是硬塞一個錯的 |
| A4 | runner 沒呼叫 `resolve_frame` → 票卡在緩衝,`revote_pending` 讓它**看得見** | 靜默失效是本專案最該防的 |

### ⚠ P2 的一個真實限制(驗證過程中發現,照實記錄)

**若撞車的兩條 track 都只有同一個可行候選,Hungarian 也救不了。**

驗證時先做的情境是 chefA@300 / chefB@900、cam2 兩條 track 都在 300 附近 ——
B 距離太遠而不可行,於是 Hungarian 只能指派一條給 A,另一條「沒被指派」→
依 A3 投「維持現狀」→ **撞車被保留**。

改成 chefB@345(對兩條都可行)之後,Hungarian 才把它們分開
(`(20→A,21→B)=7.22` 優於 `(20→B,21→A)=6.10`)。

> **所以 P2 解決的是「有替代方案時選錯」,不是「沒有替代方案」。**
> 後者是 F2 的職責,或應該讓其中一條碎裂。**報告不得把 P2 講成能解所有撞車。**

## 6. 已知限制(報告要照抄,放在結論之前)

1. **這不是冠軍法。** 冠軍法還有 Hungarian 全域指派(P2)與 anchor
   (同一人多個特徵向量)。本輪只做投票,是三者裡最便宜的一項。
2. **`stride_loops = 8` 量自 EPFL 不是 CHIRLA。** EPFL 全片單人、幾乎無遮擋,
   CHIRLA 有 6~7 人同時在場,track 會更短更碎。**遠端應先在 CHIRLA 的
   tracks.csv 上重跑 `measure_evidence_decorrelation.py`**,若建議值不同,
   照 CHIRLA 的值 —— ⚠ 但那要在**看到評估結果之前**決定。
3. **投票開啟後每幀每條 track 都要抽 crop 跑 embedder**,成本會上升。
   關閉時不付這個成本(runner 只有 revote 開啟時才抽 crop)。
4. **CHIRLA 是辦公室不是廚房。** 絕對值不可當廚房預測值。
5. **`window`/`min_votes`/`switch_margin` 是工程判斷不是實驗結果。**
   換值結果會變;§4.5 已先寫死唯一允許的調整方向。

| `p1f4` | 52,259 | 573 | 1.10% | 0 | 0 | 0 | 1,779 |
| `p1p2f4` | 52,259 | 879 | 1.68% | 0 | 0 | 52,259 | 1,694 |

三格的 `revotes` 完全相同(52,259)—— 投票次數只由 track 壽命與取樣間隔決定,
與用哪些證據無關,這是一致性的旁證。

## 8.7 §5 七個預測的逐條核對

| # | 預測 | 實測 | 判定 |
|---|---|---|---|
| 1 | `p1f4` 重疊路徑正確率 > 30% | **5.42%**(基線 16.49%) | **不成立**,且方向相反 |
| 2 | `p1` 的改善小於 `p1f4` | `p1` −0.0087 / `p1f4` −0.0750 | **不成立**,方向相反 |
| 3 | 短 track(< 3 票)行為與基線完全相同 | 725 條 track 綁定改變,其中 **190 條可投票數 < 3** | **不成立** |
| 4 | `p1f4` 的 IDF1 > 0.1214 | 0.0464 | **不成立** |
| 5 | `revote_switch` 佔 `revotes` < 20% | 0.81% ~ 1.68% | 成立 |
| 6 | `p1p2f4` 的 `same_cam_conflicts` < `p1f4` | 1,694 < 1,779 | 成立 |
| 7 | P2 單獨增益小於 P1 | P2 +0.0024 / P1 −0.0087 | 字面上不成立;兩者都在遠低於基線的水準上比較,**這條本輪沒有鑑別力** |

### 預測 3 為什麼不成立 —— 預先登記的推理錯了

§5 寫「`min_votes = 3` 的設計保證」。`min_votes` 確實保證一條票數不足的 track
**不會被投票改判**(`_maybe_switch` 在 `len(votes) < min_votes` 時直接 return),
但它**保證不了那條 track 出生時的決策不受影響**:別條 track 被改判之後,
chef 登記簿與排除集都變了,後來出生的短 track 看到的候選集因此不同。

190 條裡沒有一條可能是直接改判(被 `min_votes` 擋住),所以**全部來自級聯**。
這是預先登記的推理漏了一層,不是實作錯誤。

## 8.8 探索格 `p1dino`(⚠ 不在 §3 的網格內)

**這一格不在預先登記的網格裡,只能當探索性結果,不得當主結論。**

加它的理由:`--embedder none` 回傳的是 64 維**全零向量**,`cosine` 對每個候選
都是 0 —— 本輪網格裡外觀證據其實是**零**,不是 §5 預測 2 依據的 0.062 nats。
少了這一格就分不開「投票沒用」與「根本沒有證據可投」。
它唯一正確的對照是 9/4 的 `coco_dino`(同為 `embedder=dinov2`)。

| 格 | IDF1 | 正確率 | 誤併 | 碎裂 | ID switch | 重疊正確 | `revote_switch` |
|---|---|---|---|---|---|---|---|
| `coco_dino`(9/4) | 0.1254 | 8.41% | 64.16% | 27.43% | 1,204 | 15.08% | — |
| `p1dino` | **0.1222** | 8.94% | 63.63% | 27.43% | 1,126 | **15.08%** | 79 / 52,259 = **0.15%** |

**接上真的外觀證據之後,投票改判得更少(0.15%,比零向量時的 0.81% 還低),
IDF1 沒有上升,重疊與轉場路徑的正確率一位數都沒變。**

→ 這不是「沒有證據可投」的問題。DINOv2 的外觀證據存在,而多數決仍然一面倒地
同意現任。**證據弱到連投票都救不了** —— §5 那句話成立。

## 8.9 §1–§7 中被實測推翻的兩處(照實記錄,不回頭改)

1. **§5 預測 2 的依據寫錯了。** 它說「沒有 F4 時每票只靠外觀 0.062 nats」,
   但本輪協定固定 `embedder=none`,那是全零向量,外觀證據是 **0** 不是 0.062 nats。
   `p1` 那一格每一票用的證據與出生時那票完全相同,所以它幾乎注定是 no-op ——
   實測 0.81% 改判率正是如此。這是 §8.8 加探索格的理由。
2. **§5 預測 3 的推理漏了級聯**(見 §8.7)。

## 8.10 §6 限制 3 的成本疑慮實測不成立

| `base` | 0.98 小時 |
| `p1` / `p1f4` / `p1p2f4` | 0.99 小時 |
| `p1dino` | 1.06 小時 |

`embedder=none` 時抽 crop 幾乎不花錢(+1%);DINOv2 也只多 8%。

## 8.11 這一輪不能回答什麼

1. **不能說「累積投票這個方法沒用」**,只能說**在 CHIRLA、在這套證據下沒用**。
   冠軍法還有 anchor(同一人多個特徵向量)與俯視圖,本輪兩者都沒有。
2. **`stride_loops = 3` 是七個序列的中位數,對其中三個序列而言太密**,
   那三個序列投的是高度相關的票。換一個彙總規則結果可能不同,但那要**另外預先登記**。
3. **`window` / `min_votes` / `switch_margin` 沒有掃過。** 它們是工程判斷,
   §6 限制 5 已寫死;本輪不因為結果不好就回頭掃它們。
4. **`p1dino` 不在預先登記的網格內**,是看到「外觀證據為零」之後才加的探索格。
5. **誤偵綁定率 32.55% 本輪完全沒動**,四格逐位相同。9/12 的分析指出
   它才是重疊路徑的主要病灶,而 P1 不碰它。
6. **CHIRLA 是辦公室不是廚房**,絕對值不可當廚房預測值。
