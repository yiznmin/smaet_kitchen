## 1. 這是什麼

一份從 **Roboflow Universe 公開資料集庫**取得的**廚房場景物件偵測資料集**。
**不是我們自行拍攝或標註的**,而是外部公開資料,我們拿來作為 M3 物件偵測(RF-DETR)微調的**可商用補充素材**。

| 項目 | 內容 |
|---|---|
| 資料集名稱 | `kitchen-object-detection` — v1 `kitchen-final-dataset` |
| 來源 | Roboflow Universe(公開資料集) |
| 來源連結 | `https://public.roboflow.ai/object-detection/undefined` |
| 匯出日期 | 2022-05-02 19:32 GMT |
| 標註格式 | **COCO JSON**(`_annotations.coco.json`,每個 split 一份) |
| 影像格式 | JPEG(`.jpg`) |
| 影像尺寸 | **全部統一 416 × 416**(強制拉伸 resize,非等比) |
| 前處理 | 1. EXIF 方向自動校正並移除方向資訊<br>2. Resize 到 416×416(Stretch 拉伸) |

| 授權 | **CC BY 4.0** — 可自由使用、修改、**可商業使用**,唯需標示原始來源 |

> ⚠ **授權是這份資料最重要的價值**:我們主線驗證用的 EPFL 資料集是 **CC BY-NC(禁止商用)**,不能進出貨模型;這份 CC BY 4.0 是少數「可以進商用模型」的素材。

## 4. 資料內容特性(誠實評估)

從檔名前綴可以看出資料的蒐集方式 —— 檔名就是「類別關鍵字 + 流水號」:

`knife24.jpg`、`microwave33.jpg`、`wineglass21.jpg`、`kitchenstonecounter18.jpg`、
`uskitchenforkimages4.jpg`、`usspoonimages5.jpg`、`refrigeratorimages4.jpg` …

含 `us` 前綴的一批(約 30 餘張)推測是以 "US kitchen ..." 之類的英文關鍵字搜尋而來。

### ✅ 優點
1. **授權乾淨可商用**(CC BY 4.0),是我們手上少數能進出貨模型的素材。
2. 標註格式標準(COCO),尺寸統一,可直接餵進訓練流程。
3. 刀具、碗、杯、盤、瓶等**餐廚小物**有一定數量,類別定義明確。

### ⚠ 限制(對外說明務必一併提出)
1. **規模極小**:330 張 / 531 框,以現代偵測模型標準屬於「玩具級」資料量。
2. **不是真實作業場景**:75% 的圖只有單一物件,且大型家電佔滿畫面 → 這是**網路擺拍照/商品照**,沒有人、沒有烹飪動作、沒有遮擋、沒有多物件互動。與我們的實際應用情境(廚師在廚房作業)差距很大。
3. **無驗證集,test 過小**:test 僅 32 張 44 框,其中 `countertopwood` 在 test 中是 **0 框**,無法評估。
4. **416×416 強制拉伸**:影像已被非等比壓縮變形,原始長寬比資訊已遺失,無法還原。
5. **類別與我們的需求重疊有限**:我們的 11 類是「人、刀具、砧板、食材、鍋鏟、鍋子、手、容器、抹布、夾子、手套」。這份資料集**完全沒有**人、手、手套、砧板、鍋子、鍋鏟、抹布、夾子、食材 —— 而這些正是我們最缺、最弱的類別。
6. **標註品質已抽查,確認有漏標與錯標**(2026-08-20 補查):類名有拼字錯誤(`bottel`)、父類佔位符未清除已顯示製作隨性;實際開圖抽查後問題更明確 —— 見下方獨立小節。

### 標註品質抽查(2026-08-20)

重映射後的 100 張 train 影像中,**79 張(79%)只有 1 個標註框**。抽查 3 張,3 張全部有缺陷:

| 影像 | 框數 | 問題 |
|---|---:|---|
| `knife32.jpg` | 1 | 畫面有 **4 把刀 + 1 塊砧板**,卻只有一個 `(77,56,261,329)` 的大框、**佔全圖 49.6%**,把 4 把刀和砧板整個包成單一「刀具」實例 → **錯標**,同時教壞刀具定位與砧板 |
| `kitchenwoodcounter27.jpg` | 1 | 唯一的框在畫面最右緣 `(391,194,24,78)`(佔 1.1%,標的是窗邊瓶子);**畫面正中央的砧板、紅蘿蔔(食材)、水果碗(容器)全部沒標** |
| `kitchenstonecounter26.jpg` | 1 | 只標了青蘋果碗(1.6%),玻璃花瓶未標 |

漏標最集中的是「場景照」——檔名前綴 `kitchenwoodcounter`(6 張)、`kitchenstonecounter`(3 張)、`ussink`(1 張),整個廚房場景只標一個角落物件。

> ⚠ 這對 DETR 系模型有理論風險:Hungarian matching 會把未匹配到 GT 的 query 推向 no-object,等於教模型「畫面中央那塊砧板是背景」。
> **不過實測(Arm C)顯示,在目前的混入比例下這個傷害沒有出現** —— 見下方實驗結論。

## 5. 我們實際如何使用它

### 類別重映射(14 類 → 我們的 11 類)

腳本:`scripts/remap_roboflow.py`

| 原始類別 | 對映到我們的類別 |
|---|---|
| `knife` | **刀具** |
| `bowl` / `cup` / `plate` / `wineglass` / `bottel`(`bottle`) | **容器** |
| `blender` / `countertopstone` / `countertopwood` / `fork` / `spoon` / `microwave` / `refrigerator` / `sink` | **全部丟棄**(我們的類別定義中沒有) |

處理規則:
- 只保留「至少含一個有效框」的圖片,其餘整張捨棄。
- 輸出的 COCO `categories` 保留完整 11 類(未出現的類為 0 框),避免後續訓練載入時偵測頭被重置。
- 重新以 `scripts/split_coco.py` 切成 train/valid/test。

### 重映射後的實際可用量

輸出位置:`data/m3_finetune_rf/`

| Split | 影像數 | 標註框數 | 容器 | 刀具 |
|---|---:|---:|---:|---:|
| train | 100 | 160 | 137 | 23 |
| valid | 25 | 41 | 38 | 3 |
| test | 25 | 43 | 29 | 14 |
| **合計** | **150** | **244** | **204** | **40** |

> **330 張原始影像,對我們真正有用的只剩 150 張 / 244 框 / 2 個類別。**

### 實驗結論

我們一共試過**三種接法**,結論一致:

| Arm | 接法 | test F1 | 文件 |
|---|---|---|---|
| A | 完全不用 Roboflow(EPFL-only) | 0.807 | `docs/M3_實驗_分階段vsEPFL_20260810.md` |
| B | 先 Roboflow 40ep → 再 EPFL 60ep(分階段) | 0.835 | 同上 |
| C | EPFL + Roboflow 合併,一次訓(混合) | 0.814 | `docs/M3_實驗_ArmC混合訓練_20260820.md` |

- **三臂全距只有 0.028 F1**,test 僅 90 圖,±2~3 分本就在雜訊範圍 → **全部打平**。
- Arm C 還多吃了 28% 的 step 數(460 張 vs 360 張跑同樣 60 epoch),拿了這個便宜仍沒贏 → **更說明這份資料的影響 ≈ 0**。
- **結論:混入這份資料對模型幫助有限,三種接法都一樣,不需再糾結。**
- 原因很清楚:它只補了刀具/容器兩類,而我們的弱項是鍋子、砧板、鍋鏟、抹布;且它是靜態擺拍照,與廚房作業場景的分布不一致。

兩點值得記下的細節:

1. **上面抽查到的漏標,實測沒有造成傷害**。Arm C 的砧板/食材/手 val AP 反而比 Arm B 各高 0.017~0.027。原因是**訊號量太小**:Roboflow 佔 21.7% 的影像,卻只佔 **4.5% 的標註框**,嚴重漏標的場景照更只有 10 張(全 train 的 2%)。若混入比例拉高到 30~50%,結論可能不同。
2. **唯一的負面訊號在「容器」**。容器是這份資料貢獻最多的類(137/160 框 = 86%),理論上最該受益,test F1 卻是三臂最差(A 0.856 → C 0.838),且掉在 precision(0.841 → 0.811,誤報變多)—— 像是學了商品照的容器外觀後,在真實廚房場景亂開火。但 val 沒複製這個訊號,屬單一數據點。

### 對照組:真正有效的做法

同期我們自行標註的 **540 張真實多視角廚房影像(5016 框)**,讓 val mAP@50 從 **0.85 → 0.95**,鍋子/砧板的 AP 從 0.09~0.22 衝到 0.73~0.77。

> **這說明:提升模型表現的關鍵是「標註貼近實際場景的資料」,而不是「混入更多不相關的公開資料」。**

## 6. 目前定位與建議

| 面向 | 結論 |
|---|---|
| **保留與否** | 保留。它是目前手上少數可商用授權的廚房影像素材。 |
| **訓練上的期待** | **不應期待它提升分數,三種接法(不用/分階段/混訓)實測全部打平。** 唯一有標的兩類中,容器在混訓時 precision 反而掉了 0.03。在完全沒有可商用資料時可當起始素材,否則不必納入。 |
| **出貨模型** | 可以合法納入(需標示 CC BY 4.0 來源),但單靠它遠遠不足;**且實測沒有增益,納入只是多一份標註品質不可控的相依 → 建議不納入**。 |
| **下一步** | 主力仍是**真實廚房影片的自行擷取與標註**,尤其針對鍋子、砧板、鍋鏟、抹布、手套等這份資料集完全沒有涵蓋的類別。 |
