## 2. 影片規格與視角

同一 session = **同一時間點、多台固定相機同步錄製**(重疊多視角)。

| 項目 | 值 |
|---|---|
| **視角數** | **9 支**(`Aoutput0~3`、`Boutput0~3`、`output0`) |
| **解析度** | **1280 × 720**(9 支全部相同) |
| **幀率** | **30 fps** |
| **每支幀數** | **23,400 幀** |
| **每支長度** | **780 秒(13 分鐘)** |
| **場景人數** | 單人烹飪 |
| **合計素材** | 9 × 13 分 = **117 分鐘**、約 21 萬幀 |

> 註:因為是**同步多視角**,9 支拍的是同一段烹飪過程的不同角度,不是 9 段不同內容。

## 3. 抽幀(畫面數)

| 項目 | 值 |
|---|---|
| **抽幀策略** | 每視角挑 **有動作(M2 觸發)** 的幀,並在全片**均勻分散**(避免全是相似畫面) |
| **每視角抽** | **10 張** |
| **總畫面數** | **9 視角 × 10 張 = 90 張** |
| **影像解析度** | **1280 × 720**(原始解析度,未縮放) |
| **腳本** | `scripts/extract_multiview_frames.py` |

### 切分方式
- 腳本 `scripts/split_coco.py`,**均勻切**:每 6 張中 1 張進 valid、1 張進 test、其餘進 train。
- 比例 **train : valid : test = 60 : 15 : 15 張(4 : 1 : 1)**。
- 均勻切確保三個 split **涵蓋所有 9 個視角**,不會某視角全落在同一 split。

## 6. 資料缺口(影響結果的已知限制)

| 缺口 | 說明 | 影響 |
|---|---|---|
| **夾子 0 框** | 類別有定義但畫面沒出現 | 該類完全沒學到,實務上要補 |
| **鍋子僅 28 框** | 最少的有效類別(test 只有 5 個) | 實測最弱(Recall 0.4–0.6) |
| **砧板僅 36 框** | 第二少 | Precision 僅 0.571(誤判多) |
| **單一 session** | 同一天、同一廚房、同一位烹飪者 | 場景多樣性極低,泛化能力未驗證 |
| **總量僅 90 張** | 各類 test 只有 5–23 個物件 | **單一物件對錯就會讓指標跳** → 變體比較分不出高下 |
| **授權 CC BY-NC** | 禁商用 | 模型只能丟棄,無法出貨 |

> ➜ 真實資料階段的具體行動:**至少幾百張**、涵蓋不同時段/光線/鏡位/烹飪動作,
> 並**特別補足鍋子、砧板、夾子**的樣本量。
