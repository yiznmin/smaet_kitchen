## 4. 實驗與結果

### 4.1 資料量效應(最重要的發現)
| | bootstrap(90 張) | round2(540 張) |
|---|---|---|
| val mAP@50 | 0.85 | **0.95** |
| 鍋子 AP | 0.09 | **0.76** |
| 砧板 AP | 0.22 | **0.73** |

→ **「把資料標多、標好」是關鍵躍進**,遠大於任何模型 trick。

### 4.2 變體:nano vs medium
bootstrap 上兩者 test F1 ~0.82、**幾乎打平** → 先用 **nano**(更輕、對部署主機友善),定案待真實資料。

### 4.3 受控實驗:分階段(Roboflow 預訓 → EPFL) vs 只用 EPFL

**方法**(唯一變因 = 有沒有 Roboflow 前置):

| | Arm A(基準:EPFL-only) | Arm B(分階段) |
|---|---|---|
| Stage 1 | 無 | COCO→Roboflow(**remap 成 11 類**,只有刀具/容器有框)40 epoch |
| Stage 2 | COCO→EPFL 540 | stage1 權重→EPFL 540 |
| Stage 2 設定 | epochs=60、res=704、batch=4 | **與 A 完全相同** |

> 關鍵設計:stage1 也用 11 類 → 偵測頭不重置,讓 Roboflow 學到的刀具/容器**延續**到 stage2(否則換類別頭會重置、前段全丟)。

**結果**(同一 EPFL test 集):

| | val mAP@50:95 | val mAP@50 | **test P / R / F1** |
|---|---|---|---|
| Arm A(EPFL-only) | **0.7356** | 0.9518 | 0.795 / 0.819 / 0.807 |
| Arm B(分階段) | 0.7327 | 0.9528 | 0.857 / 0.815 / **0.835** |

重點類別(Roboflow 唯一能影響):

| 類別 | Arm A(P/R/F1) | Arm B(P/R/F1) |
|---|---|---|
| 刀具 | 0.773 / 0.785 / 0.779 | 0.836 / 0.785 / **0.810** |
| 容器 | 0.841 / 0.872 / 0.856 | 0.892 / 0.854 / **0.872** |

**結論:基本打平。** val 上兩臂幾乎一樣(A 甚至微高);test 上 B 略勝(靠 precision,誤報少一點),但差距(~2~3 F1 分)在 90 圖 test 的**雜訊範圍內**,且 val 沒複製這個優勢。→ **「先 Roboflow 預訓」最多帶來邊際好處,無法證明明顯有用**;原本預期(頭重置 + COCO 已涵蓋刀/容器 → 幫助有限)大致成立。

### 4.4 每類信心門檻(工具驗證通過)
`sweep_thresholds` 在 val 上掃出每類門檻,行為符合設計:

| 策略 | 類別(門檻) |
|---|---|
| 食安類:壓低門檻換 recall | 手/刀具 **0.15**、人/砧板 0.20、食材 0.35 |
| 一般類:最大 F1 | 鍋鏟 0.35、容器/鍋子/抹布 0.40 |
| 無樣本 | 夾子/手套 → 預設 0.30 |

→ `configs/m3_thresholds.json`(EPFL 示範;真實模型要重掃)。

## 5. 關鍵結論(一句一條)

1. **微調流程與工具鏈全部打通、可複現。**
2. **資料量是主因**:90→540 讓 val mAP@50 0.85→0.95,鍋子/砧板從崩盤救回。
3. **變體**:nano/medium 打平 → 先用 nano。
4. **分階段預訓**:與純 EPFL 基本打平 → **不值得為它多花力氣**,兩者皆可。
5. **每類門檻工具**:驗證可用,食安類自動壓低門檻換 recall。
6. ⚠ **所有 EPFL 模型都是丟棄驗證版**;可出貨模型必須用**真實廚房影片**走同一套流程。
